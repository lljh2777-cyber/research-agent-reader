# Direct API 阅读助手

阅读助手使用当前论文、所选节点和相应支线背景组织任务。旧支线保留创建时主线背景；不会默认装入整棵会话树或无关兄弟支线。

能力注册表 `src/assistant/capabilities.ts` 同时提供模型工具说明与结构校验定义，导读规则来自构建时嵌入的 `skills/reading-assistant/SKILL.md`。新增能力需要同时接通业务服务和行为测试。

首阶段实现进度分页、节点阅读、正式知识检索、历史学习关联、原文文字读取、整理记录查询和后续操作卡。正式知识检索沿用已有关键词、BGE embedding/rerank 与降级规则；学习记录不作为论文事实依据。引用必须来自本轮实际读取且指纹匹配的片段。助手当前只读取文字与图注，图像核对由原文窗口及现有深读流程完成。

每次请求最多八轮模型调用、累计约 42,000 文字输入 token、38,000 字符工具结果，240 秒超时；同一工具请求在本轮复用，但读取依据时重新核对来源。估算预算用于限制上下文，并非费用账单。记录单独保存服务商返回的实际用量；缺失用量不记为零。无效格式直接停止，可由用户重试。

助手记录原子串行保存到插件目录 `reading-assistant-runs/`，包括问题、工具轨迹、读取片段、操作卡和调用用量；保留全部历史，不自动删除。应用重启将未完成调用标为中断。原文或正式笔记变化时拒绝旧引用。工具仅准备操作，不直接写入正式笔记、导出文件、修改理解状态或核验标记。

基础回归：`node tests/test_reading_assistant.js`，全部使用内存数据，无文件清理和线上调用。另需执行类型检查、构建以及阅读、知识库、整理回归。

在交互深读顶部点击星光图标“阅读助手”。先选择已完成的正式节点，再输入请求；Ctrl/⌘ + Enter 发送。窗口可调整大小，正文区随窗口扩展。助手是单次任务入口，每个请求独立处理，历史可随时查看。输入草稿按会话和节点保存。切换阅读模式或关闭窗口不会停止已开始的任务；停止按钮单独取消。选择 Codex CLI 作为阅读模型时，助手仍可独立选用已验证的 Direct API。

完成后，操作卡可打开预选范围的导出预览，或预选节点和目标笔记的整理界面；整理界面先读取依据和预算，再由已有按钮生成建议。卡片尚未写入任何笔记。“继续主线”点击后沿用会话的阅读模型；失败在主线节点中重试，同一卡片不会重复推进。内容变化后的旧卡需要重新准备，已经打开的导出和整理预览可以重新打开。

助手的模型调用和实际读取轨迹单独保存；后续主线与整理模型调用仍在原有阅读、整理记录中显示，避免把准备操作计作实际完成。不会自动更改“已理解”或“已核对”标记。

## 结构化输出

“模型格式与调用边界”中可执行一次短 Schema 探测。插件用仅存在于 Schema 的随机值验证返回格式，并记录探测结果和接口用量。通过后，该接口的助手、讲解、证据选择、记忆压缩与整理请求会附带 Schema。修改接口类型、地址、模型或凭据名称后旧探测失效。未验证或未通过时保留原有提示词与本地校验，不额外补发模型请求。

当前接入 OpenAI Responses 的 `text.format` 和 OpenAI 兼容 Chat Completions 的 `response_format`；其他协议继续使用本地校验。原生格式不能保证引用真实、科学结论正确或所有复杂 Schema 均被服务支持，所以本地校验始终保留。接口协议依据：[OpenAI 官方文档](https://developers.openai.com/api/docs/guides/structured-outputs)、[阿里云官方文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。

自动化检查：`pnpm test:assistant` 覆盖上下文、权限、实际读取、存储恢复、操作交接，以及 Schema 探测、配置失效、两种原生协议和未验证时的降级。全部使用内存或 mock，不包含文件清理。正式知识写入继续使用既有差异预览与修订服务。
