# 文献入库续办状态修复（0.43.1）

## 问题与原因

首次入库由控制台启动，会主动刷新任务列表；“继续完成入库”由结果窗口启动，原先没有通知控制台任务已改变。因此续办在后台运行时，列表仍可能只显示上一条失败记录，入口按钮也保留旧的点击行为，弹出“文献入库正在运行”，却没有显示可停止的新任务。

本次现场记录中，原任务于 15:47 开始、15:49 失败；续办于 15:49 开始、15:53 失败。检查时没有仍在运行的入库任务。问题是任务状态与界面不同步，不能据此把运行中的续办强行标记为结束。

## 修改

- 任务创建成功和终态保存结束后统一通知已打开的控制台；视图关闭时解除订阅。复用已有数据缓存，不轮询、不调用模型。
- 文献入库按钮点击时读取当前运行任务，避免使用渲染时捕获的旧任务。运行中的续办可以从同一入口停止，结束后恢复新建入库。
- 在任务保存队列内部检查入库并发，防止两个打开的窗口各自创建运行任务。首次入库与续办都显示启动失败，不留下悬挂任务。
- 首次入库和续办共用终态转换，保留结构化错误、冲突、网络错误及取消信息。续办抛出异常时同样打开失败结果窗口。
- 仅失败或中断任务提供“继续完成入库”；上一条失败记录保留，续办仍是独立任务。

## 验证

- 类型检查、生产构建、5 组入库回归、2 组控制台回归、28 项发布审计、差异检查通过。
- 新增纯内存回归覆盖：状态通知、并发启动、失败后重试、取消、旧任务完成不干扰新任务、开始保存失败、完成日志和设置保存失败、视图关闭后解除订阅。
- 测试库原生界面完成 14 项检查，包括无需 Vault 文件事件即可更新运行任务及停止按钮、重复点击只启动一次、失败后入口恢复、旧按钮操作当前任务、超时结果显示、再次新建入库。
- 原生验收使用延迟模拟后端和内存任务存储，未调用真实模型、读取 PDF 或运行 MinerU；用户设置及任务历史一致。
- 未运行含批量文件回收路径的全量旧测试及任务输出持久化整套测试；本次用内存存储失败测试覆盖涉及的任务状态路径。未验证真实模型的入库成功率。

此次修改不改变论文身份核验、重复候选校验、原文复用和写入条件。若任务报告重复判定与检索回执冲突，仍保留失败结果与校验依据，不绕过入库校验。

验收脚本：`tests/test_ingest_task_lifecycle.js`、`tests/obsidian-ingest-continuation.cjs`。
