# 本机 CLI 批注的证据范围

更新：2026-10-18，版本 `0.89.1`。适用于 CodeBuddy、Qoder CLI CN，以及 OpenCode 官方配置的非联网文字批注。其他 API、既有联网路径及旧批注沿用原有规则。

## 本轮问题

此前[刷新后真实 AI 验收](cli-model-refresh-ai-validation.md)中，CodeBuddy 带入前文的药物发现／合成化学空间比较；Qoder 在没有图像输入时描述图 1a 的概念或流程，并给出“无歧义或错误”的译文评价；mimo 用前一句补出“该分类器”的随机森林身份和训练对象。这些内容即使出现在附近段落，也不属于所绑定引句的直接释义。

历史回答、失败和来源凭据保留，不通过改写旧记录使其符合新规则。

## 输入与输出

- 英文或普通 Markdown：从实际可见文字中取选区所在句。选区无法唯一定位时仅提供所选文字，不退回整段。
- 中文双语：第一次调用仅从实际读取的英文段落中返回最少候选句编号与有限状态；最多两句，不能为消解代词而加选前文。找不到对应、范围过宽或返回无效编号时停止，提示在英文侧重新划选。
- 第二次为新的独立调用，只收到中文选句和已选英文句，不带第一次会话、整段、章节、路径或邻句。保留“该分类器”“这两类分子”等指代，不从记忆补身份。两步均明确传入相同模型参数。
- 释义只返回原文引句与短释义；引句须存在于实际提供的文字中。图号和链接只作引用；未提供图像时不推断流程、曲线或验证结果。引句本身明确描述图示时，可转述作者文字，仍不代表查看或核验图像。
- 中文“译文对照”由插件渲染有限提示：候选句定位不代表译文准确或无歧义，译文及对应关系仍待人工核对。模型只能提示可能存在差异，不能自由撰写翻译审阅结论。

候选句选择也是模型输出，不是逐词对齐或语义对应的证明。机器仍可能选错句子，读者应核对最后显示的英文引句。新增拦截针对本轮已复现的背景、方法身份、翻译评价与图示推断，保留原有程度／调整／目的检查；这不是通用语义验证器。

## 调用、回执与失败

中文双语现在有两次有意安排的 CLI 调用，可能增加时间和用量；这不是失败重试。两步共享设置中的总超时预算和取消状态。定位后重新核对来源版本；取消、超时、来源变化或不确定定位均不进入释义步骤。失败不自动换模型或扩大上下文。

保存记录的主 `aiCli` 回执属于最终释义；可选的 `aiCli.evidenceSelection` 保存候选句定位的请求模型、实际模型、用量及费用。两份回执分别保留，不把最终释义用量当作整条流程总量；未报告的字段仍为未知。旧版单次回执可正常读回。

准确请求参数保持为 `--model step-5-preview`、`--model Qwen3.8-Flash` 与 `--model opencode/mimo-v2.6-flash-free`。模型刷新和 Qoder 额度接口不发送论文内容，不改变本轮两步调用的证据规则。

## 验收记录

工程定向检查包括句子窗口、候选编号及数量、输入隔离、上下文扩展／图示推断拒绝、作者明确描述的正例、共享超时、取消、来源变化、嵌套回执与旧记录兼容。此前三个后端原始输出在新校验中的离线回放均被拒绝；另行剥离旧版翻译评价字段后，扩展释义本身仍被拒绝。

Windows / Obsidian 测试库的三份真实含链接选区，均从实际刷新目录选模，经原生 AI 解释入口生成，由实际“保留”按钮保存，再由生产服务读回并定位原文。共三次解释流程、五次 CLI 生成调用，无失败重试或模型切换：

| 后端与模型 | 选区及调用 | 本轮限定核对 |
|---|---|---|
| CodeBuddy `step-5-preview` | 英文 DeepMet 介绍句；一次释义 | 保留已知代谢物训练与预判含义，只说作者引用图 1a；没有加入药物发现背景或图示概览 |
| Qoder `Qwen3.8-Flash` | 对应中文介绍句；候选定位＋释义 | 只选目标英文句；没有图示推断或自由翻译评价，两步回执保存一致 |
| OpenCode `opencode/mimo-v2.6-flash-free` | 中文分类器表现句；候选定位＋释义 | 保留“该分类器”“这两类分子”和仅略优于随机猜测的范围；没有补随机森林身份、训练对象或图中曲线 |

最终实际请求仅含选句与最小英文依据；所有已保存回答再次通过最终生产校验器。CodeBuddy 的回答生成后补了一处图示否定语句检查，最后离线回放其原始输出通过，没有为此重复请求模型。OpenCode 两个独立本机会话的只读导出均报告所选 mimo 模型并正常完成；界面和批注回执仍忠实显示文字事件未报告实际模型，不以事后导出改写记录。

CLI 报告的两步用量分别保存。CodeBuddy 单次报告输入 4,053、输出 1,671；Qoder 两步均报告 0，不把这个报告解释为可验证的真实 Token 消耗；mimo 定位报告输入 2,605、输出 14，释义输入 3,243、输出 96，两步各有缓存读取 4,096。各次报告费用为 0，不据此推算永久免费、额度消耗或可调用次数。

最后以正常退出确认全部宿主进程消失后重新启动，宿主与渲染进程均替换。43 份新旧记录及回执完整一致，三份新来源可重新定位，原文和配对记录哈希不变；模型选择、交换布局、比例及阅读位置恢复。Qoder 真实额度显示、明确注入“不支持额度接口”后的未知回退与恢复通过；新宿主查询缓存为空、额度先显示未知，手动刷新后重新取得真实额度。已恢复测试前插件偏好和工作区，保留新批注及原始输出。

首次重启因开发重载仅运行时启用插件、未保存宿主自动启用状态，导致插件未加载；这是验收准备问题，保留日志后用宿主原生启用命令修正，再完整正常重启并通过上述检查，未追加模型请求。没有强制终止宿主、删除历史或改写来源。

本机类型检查、生产构建、证据窗口／双语两步／含链接批注／三个 CLI／来源完整性／模型刷新／设置及公开发布边界的定向回归通过。完整旧测试集中存在递归清理，本机未运行该清理路径；完整矩阵由三平台 CI 执行。宿主重启是恢复与定位验证，不代替独立科学审阅。

首次发布检查发现旧调整信息回归的模拟回答仍引用整段，先于预期的调整判断触发了句子窗口引句校验；将夹具改为实际提供的首句，并保留“未报告不等于未调整”及单次拒绝断言。该次流程未生成安装文件或公开 Release，保留失败记录；修正后重新运行完整发布检查。
