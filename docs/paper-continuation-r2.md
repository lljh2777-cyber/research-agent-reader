# R2 第五批：从文献详情补充原文与继续处理

2026-09-12，开发版 `0.65.0`，已部署 `E:\paper-test`。公开 beta 保持 `0.31.0`，R2 尚未收尾。

## 使用流程

在文献库选择已保存完整书目信息的文献，详情的“补充原文与继续处理”提供两个入口：

- **查找全文 / 继续获取**：锁定已有文献，按实际需要选择 PDF 或 JATS、版本范围与图片策略，再明确启动新查找。下方“此文献的获取记录”按精确标识筛选；重试、选择候选、查看已下载原文、保存和关联入库任务继续使用原流程。
- **添加本地 PDF / 恢复登记**：沿用保存的书目信息，选择文件、声明版本并核对页面。下方展开此文献的本地记录，可继续核对与登记或重新选择相同内容的文件。

详情本身只读；进入后续窗口不自动启动新查询、下载或保存。全文服务初始化沿用既有中断恢复行为，可能把本设备尚在运行的旧任务记为中断，但不会自动重试。用户继续旧记录时保留该记录当时的元数据和版本选择，不用当前书目快照替换它。

尚无完整书目信息的旧记录说明如何从顶部“添加文献”重新查询并继续。旧人工记录没有 `bibliography` 时不会被本批自动回填；统一添加仍可使用新查询预览继续操作。身份冲突、书目损坏、并发决定或阻断性的目录读取问题会阻止详情衔接。无法核验归属的本地记录保留警告，不提供恢复按钮。

## 实现边界

`paper-continuation.ts` 比较详情展示的书目信息和新读取的目录。`MetadataIntakeService.savedContext()` 再次读取持久记录并核对来源目录的 paperId，仅返回独立副本，不写记录或调用标识解析器。插件检查取消状态后打开原有窗口；详情中的切换、编辑和下一步按钮互斥。成功重新定位文献会清除旧操作错误提示。

全文窗口按 `identityRelation` 的精确共同标识筛选历史，标识冲突或无共同标识的记录不展示。没有身份结果的旧请求仅凭其请求标识筛选，不借用标题。原独立全文入口继续展示全部记录。所有设备归属和既有动作守卫继续生效。

本地历史在只读解析后按身份筛选，恢复时检查旧快照与当前文献的标识关系，并在实际 PDF 核对后确认 paperId 一致。错误归属在持久写入前停止；完成记录与旧源文件仍使用原恢复器校验。不新增持久字段或迁移历史数据。
