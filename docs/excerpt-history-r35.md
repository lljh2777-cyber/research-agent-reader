# R3.5：摘录整理历史、人工完成与待处理联动

2026-09-12，开发版本 `0.73.0`。在 R3.4 的受控补充基础上，接通摘录详情中的历史和人工整理状态；不调用模型，不新增数据根。R3 尚未整体收尾。

## 使用方式

从“文献库 → 摘录”或“打开摘录（原句与个人备注）”命令进入，按原句、来源或备注搜索，并筛选全部、待整理或整理完成。选择摘录后可查看原句、保存时上下文、个人备注、当前来源核对结果与整理历史。

历史按摘录路径和 ID 准确关联，展示整理批次、补充修订、撤销修订及其目标路径。展开修订可查看当时目标笔记的修改前后全文，正文以纯文字呈现，不执行 HTML 或链接。只有展开修改快照时才构建对应长文本；每次显示 25 条，可继续加载已读历史。

“打开当前目标笔记”重新读取已保存历史，并核对修订凭据和准确路径。记录变化、无法读取或目标缺失会停止，不选择同名替代。打开的是目标当前内容，历史快照不证明当前笔记仍保留那次补充。此处只读；恢复写入和撤销仍从知识整理入口操作。

“标记整理完成”表示你认为这条摘录当前已处理，可以没有正式笔记补充，也可以曾补充到多个目标。“重新待整理”恢复工作状态。状态不自动采纳建议、不完成修订，也不改变证据深度；完成后刷新待处理中心，只在来源明确一致时移出摘录。原文变化、缺失或无法核对的已完成摘录仍列入复查，独立恢复事项继续保留。

## 数据与实现边界

- `excerpt-library.ts` 复用既有 `archiveStatus` 的 `none/completed`，更新既有时间与生成状态行。这里只处理独立 R3 摘录；存在归档任务 ID、目标、错误或处理中状态时，继续交给原归档功能。没有增加完成事件日志，也不把原来的 `pending` 归档状态解释为手动待整理。
- 状态与备注使用同一 `Vault.process` 写入边界，比较完整文件摘要和对象路径；外部附录变化、文件移动或替换会停止。保存保留原句、上下文、来源位置、AI 文本、个人备注、未知元数据和额外正文。写入响应丢失时只接受当前对象中完全相同的预期结果。
- `excerpt-history.ts` 通过 `FileSourceStorage` 只读取 `knowledge-reviews/reviews` 与 `revisions`。准确关联后复用 `validatedReview` 和从写入器提取的 `validateCurationRevision`，核对固定正文、文件摘要、日志及撤销关系。先校验原修订，再校验撤销；损坏原修订不能认证撤销记录。读取不实例化 `CurationService`、工作区或恢复服务。
- 单次历史扫描最多 256 个 JSON、64 MiB 总量、8 MiB 单文件。重复标识、局部错误、临时记录和达到上限明确显示；读取不完整时不能断言不存在未显示的补充或撤销。目标打开前再次核对历史内容，关闭或切换摘录使迟到结果失效。
- 整份摘录摘要继续作为整理输入凭据。备注、人工状态、更新时间或其他内容变化后，旧的待应用预览必须重新准备；已应用记录保留，现有知识整理的来源检查也可能将其列为需复查。本批未引入忽略状态变更的“宽松”来源校验。
- 状态变更不会主动刷新已经打开的其他窗口；待处理中心仍需手动刷新。未保存草稿仍只保存在当前窗口内，插件卸载或宿主退出不提供草稿持久恢复。
