# R3.7：人工修订稿与学习摘录待处理

更新日期：2026-09-12。开发版本：`0.75.0`。本增量在学习回答摘录中接入人工修订稿、手动整理状态和待处理中心。原始 AI 回答、人工修订与个人备注分别保留；全过程不调用模型。

## 用户流程

1. 打开“学习回答摘录”，选择已有记录。在“人工修订稿（基于 AI 回答）”中输入自己的改写，或明确点击“以 AI 片段起草”。修订框已有内容时，起草按钮不会覆盖。
2. 点击“预览人工修订”，核对候选内容，再点击“确认保存人工修订”。更换候选内容使旧预览失效；空白候选会明确预览为清空已保存修订稿。
3. 个人备注仍独立保存。保存一个编辑框不会丢失另一个编辑框中的未保存草稿；重新读取保留两个草稿，并要求重新准备人工修订预览。
4. 可手动“标记整理完成”或“重新待整理”，列表支持对应筛选。修订稿或备注实际变化后重新待整理；保存相同内容和重复完成不改变原状态。
5. 待处理中心新增“学习摘录”阶段。当前回答版本一致且用户未标记完成时显示待整理项；点击“查看学习摘录”回到准确文件。

完成仅表示用户的整理进度，不代表内容已经写入正式笔记、回答正确或科学／教学审阅完成。回答版本变化、缺失或无法核对时，已完成的摘录仍进入“审阅与复查”。

## 记录与写入约定

仍使用 `wiki/qa/answer-excerpts/`。旧 v1 摘录可直接浏览，浏览、预览和无变化操作不迁移内容。首次保存人工修订或修改完成状态时，此单份记录升级为 v2；不会批量转换旧记录。v2 增加独立的 `humanRevision` 和 `organization`，原回答快照、选区、固定文件名及个人备注继续保留。升级后的记录需要 `0.75.0` 或支持 v2 的后续版本读取，旧插件不会自动降级它。

人工修订保存当前文本与时间，最多 20,000 字符；个人备注仍最多 10,000 字符。清空修订稿后，AI 原回答保留。修订稿以纯文本围栏显示，不能执行其中的 HTML、脚本或链接。本版保留的是原始 AI 回答和当前人工修订稿，**尚未提供每一版人工改写的历史或撤销**，也没有套用正式笔记的修订日志。

三个内容角色都不升级为论文证据。原回答、修订稿和备注所在文件继续排除通用词法检索、学习索引与正式知识检索；仅学习摘录列表自身可搜索修订稿。原文摘录的补充和正式笔记修订仍使用既有流程，新人工修订稿尚未接入该写入适配器。

预览检查整份摘录是否变化；确认保存通过 `Vault.process` 再次比较全文摘要和文件身份。并发备注、修订、状态或手工修改都能使旧操作失效。写入前失败保留草稿；若写入已提交但响应丢失，只接受与预期完全一致的文件。新增字段、时间、文本长度和正文凭据在写入前校验，避免生成无法重读的记录。

任一编辑框有草稿时，切换记录、返回回答和状态修改被禁用，普通关闭被阻止；可分别保存或放弃。插件卸载仍会关闭窗口，未保存草稿不跨卸载持久化。卸载或取消后迟到的读取不会重新展示预览或触发保存。直接手工编辑生成 Markdown 的限制沿用 R3.6：发生格式或凭据冲突时保留文件并提示检查，不自动合并或修复。

## 待处理读取

新增只读适配器 `readAnswerExcerptPending()`，复用现有学习摘录列表与保存回答读取器；不初始化任务恢复、生成服务、原文转换或学习会话运行环境。相同回答版本在单次扫描中复用核对结果；单次最多核对 100 个不同回答版本，余下项明确保留为无法核对，并报告读取上限。文件列表本身沿用 R3.6 的数量和大小限制。

待处理项包含固定摘录路径、整份文件摘要和回答核对结果。打开前重新扫描并核对它们，防止从旧结果打开已完成、已变化或不可读对象；同名回答不会替代准确记录。学习摘录读取失败只影响此部分，其他阶段的事项继续显示并保留错误提示。

这里核对的是已保存回答的版本，不是原始 PDF、代码或科学主张。完整待处理刷新仍会读取其他阶段，速度受现有库规模和文件访问影响；本轮没有替换全库扫描机制。
