# R4.2 首批交付：生产校验与保留副本读回

2026-10-05，开发版本 `0.83.0`。本步骤将 R4.1 的首批候选接入实际生产校验器，检查历史与记录间依赖，复制到新建的私有隔离目录，并在全新 Node 进程中读取副本。R4.2 的全部依赖闭包仍未完成，正式迁移、存储路由切换和回退尚未实现。

## 实现

`src/storage/validation.ts` 接收内存中的不可变文件字节，使用写入方法会抛错的存储适配器。各类数据复用现有生产逻辑：

| 记录 | 校验与关系 |
| --- | --- |
| 阅读／代码会话 | `validateReadingSession`；校验文件 ID、节点链、代码／结构化来源快照，收集节点的来源路径 |
| 文献人工历史 | `readPaperRecord`；内容摘要、提交标记、前置版本和唯一有效当前版本，保留主要笔记引用 |
| 助手记录 | `validateAssistantRun`；会话、节点、动作节点及已有整理执行记录必须可找到 |
| 整理建议与修订 | `validatedReview`、`validateCurationRevision`；核对建议、写入前后内容、日志、撤销依赖，未完成状态单独报告 |
| 草稿历史 | `KnowledgeDraftStore.read`；校验提交、版本链和固定材料，并核对材料中的学习回答引用 |
| 建页计划 | `validatePagePlan`；校验页面、索引／日志、完成标记及对应的准确草稿版本 |
| 主题路线与讲解 | `TopicSessionStore.read`、`TopicStudyStore.read`；检查事件历史，以及讲解所用路线版本确实存在 |
| Vault 中的学习回答摘录 | `readAnswerExcerpt`；检查正文与凭据、人工修订历史，以及指向的会话／路线和节点 |

不调用会在启动时改写中断状态的 `ReadingRepository.load()` 或 `CurationService.ready()`。部分旧记录会被生产校验器规范化为内存对象，报告以 `normalizedInMemory` 标注；副本保存原始字节，不自动升级原记录。

`scripts/load-storage-validator.cjs` 使用仓库已有的 esbuild 在内存中加载校验入口。Obsidian 接口桥仅让类型声明可以加载，实际原生 API 调用一律抛错；未用简化 YAML 解析器代替宿主行为，也未安装依赖。

## 保留副本工具

```powershell
pnpm storage:rehearse --vault E:\paper-test --plugin-dir .obsidian/plugins/research-agent-reader --output-dir E:\research-reader\r4-validation-new-copy
```

父目录须已存在，输出目录必须是 Vault 和源码仓库之外的**新目录**。不覆盖旧演练目录，不删除任何源文件或副本，不安装或重载插件。结构盘点已有问题时，仅保存报告并停止复制。

通过结构盘点后，工具在读取上限内捕获候选字节和 `wiki/qa/answer-excerpts/` 下的学习摘录，执行生产校验，再逐文件创建隔离副本并逐字节比较。复制窗口结束时重新检查候选文件集合、摘录集合和已读文件属性，变化会阻止完成结果。没有冻结宿主写入，因此这不是正式切换需要的全库事务快照。

副本目录含：

- `records/`：首批插件持久记录；不复制 `data.json`、获取事务、运行产物、缓存或安装代码。
- `vault-context/`：用于反向引用校验的学习摘录快照；其原件仍由 Vault 服务拥有。
- `manifest.json`：完成捕获后的精确文件清单、大小和内容指纹。
- `inventory.json`、`source-audit.json`、`unmoved-dependencies.json`：盘点、生产校验和留在原位的来源／目标存在性观察。
- `restored-audit.json`、`result.json`：独立进程读回结果及与原捕获结果的比较。

原始记录和学习摘录可能含私人内容，副本仅在本机保留，不应提交公共仓库。检查报告不输出正文、问答、提示词或异常原文。指纹只用于这批副本的完整性校验，没有全库哈希扫描。

可单独执行只读复验：

```powershell
node scripts/storage-rehearsal.cjs --verify E:\research-reader\r4-validation-20261005
```

复验进程只获得副本位置，不读取原 Vault。它拒绝清单越界、重复路径、文件损坏和未列入清单的额外文件，再运行同一生产校验器。`--verify` 不写文件；内容完整性与生产校验问题分别出现在输出中。复制中断会留下已有文件，不产生成功结果；当前不支持续写部分目录，应保留现场后使用新的目录重新演练。

演练命令退出码：`0` 为覆盖范围内无问题，`2` 为报告中有结构、记录或依赖问题，`1` 为参数／文件操作等错误。报告始终为 `migrationExecutable: false`。记录语义有问题时仍可保留原字节副本供检查；复制成功不等于记录有效。

## 本轮实测

源为 `E:/paper-test`，已安装插件仍为 `0.81.1`。私有副本保存在 `E:/research-reader/r4-validation-20261005/`。

| 项目 | 结果 |
| --- | --- |
| 捕获文件 | 76 个候选文件、2 份学习摘录，共 3,786,368 字节 |
| 生产校验 | 62 个逻辑对象通过，格式／历史错误 0；收集 108 条去重关系 |
| 对象构成 | 22 个阅读会话、11 个助手、11 个整理建议、6 个修订、5 份草稿历史、2 份建页计划、3 份文献历史、2 份学习摘录 |
| 旧格式兼容 | 19 个对象在内存中规范化；源和副本的原始字节保持 |
| 独立进程读取 | 副本逐文件校验通过，读回的生产校验报告与捕获时完全一致 |
| 留在原位的文件关系 | 60 条文件存在，2 条缺失；未验证这些文件的科学内容或完整原文包 |
| 数据操作 | 源文件集合与属性检查通过；无源写入、删除或路由切换 |

两条缺失关系都来自旧演示会话，指向 `demo-evidence.md`。本轮保留真实缺口，没有补造该文件，也没有因会话属于演示而掩盖缺失引用。因此实测演练命令返回问题状态，不能报告为全部迁移条件通过。

当前测试库未保存主题学习目录；其格式、事件链和路线依赖由使用生产服务生成的隔离夹具覆盖，不能据此声称已有真实主题记录迁移完成。

## 尚未闭合的依赖与下一步

当前校验边界为候选记录及学习摘录。节点关系检查证明所指节点存在，不要求当前答案与历史快照相同，也不替代原有的继续执行前来源核验。助手或整理日志读回成功不代表未完成任务可以立即执行。

原文包及包内资源、外部代码目录、其他 Vault 反向链接、`data.json` 问答／任务记录、暂留的获取和入库事务，以及设备所有权仍需专项闭包。留在原位的文件只做当时存在性检查，没有包含在这份候选副本中；离线复验不重新访问它们。不能将候选副本当作完整 Vault 备份。

下一步继续 R4.2：明确旧演示缺失引用的处置策略，补齐暂留记录与候选记录的双向依赖，产出可逐项审阅的迁移分组和阻断项；之后才进入可恢复复制日志、单写入端切换与回退演练。正式 Vault 切换仍需具体方案审阅与用户批准，本轮不请求或执行切换。
