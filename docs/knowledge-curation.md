# 学习内容整理与正式知识修订

开发目标为 0.33：从选定学习节点开始，查找相关学习记录与正式笔记，核对实际证据，生成可审阅的段落修改。每次以一篇已有笔记为目标，默认最多五条建议；确认预览后应用并保留修订。现有导出流程继续独立可用。

## 阶段与约束

1. 固定生产检索复验与整理反例。
2. 独立学习索引，排除演示和测试，避免把 QA 当成论文证据。
3. 小批量建议、只读证据、缓存与用量记录。
4. 逐条预览、目标文件和来源复查、修改前快照及恢复日志。
5. 待审阅、需复查、修订与索引维护面板。
6. 两来源、两生成后端、异常恢复与真实 Obsidian 验收。

正式目标限于现有 `wiki/sources/`、`concepts/`、`methods/`、`synthesis/` 的正文，保留 YAML、标题、深度和现有手工编辑。原始 PDF 和 MinerU 包只读。模型只返回目标段落编号、候选正文及证据引用，文件路径和写入操作由插件控制。页面整合、新建正式页面、批量重写与自动升级 x-ray 不属于本版。

指纹比较、差异、历史浏览和预览在本地完成。生成请求使用选中节点、相关证据与目标段落；缓存依赖内容、来源、目标、后端及规则版本。页面切换和勾选不调用模型。缺少 API 用量时显示估算，推理和图像开销不能伪装为精确计费。

## 独立学习索引

`LearningLibrary` 将正式阅读节点与 `wiki/qa/` 作为学习记录读取，演示和测试会话及其可识别导出被排除。旧 QA 只参与相似性发现，来源未核验时明确标记。向量存放在插件目录 `learning-index/bge-v1.bin`，复用增量构建、停止、恢复和模型错误回退能力。

跨会话查询排除当前会话的节点。完全相同的正文标为「文字相同」，其余命中标为「主题相关」；两者都不能证明事实一致或独立证据。正式知识问答不会读取该索引。`node tests/test_learning_library.js` 使用内存验证范围、旧 QA、跨会话匹配和变化后的结果。

## 小批量生成与缓存

整理规则由仓库 `skills/knowledge-curation/SKILL.md` 嵌入构建，Direct API 与 Codex CLI 共用。默认一批一个节点，支线可选择一至三个已完成回答；最多五条建议。文字输入估算超过 18,000 token 时要求缩小范围，实际图像及推理开销另行计量。

建议必须定位到原目标段落并引用本轮证据原句。元数据、标题、代码围栏和不受支持的笔记目录不能作为修改位置。图表声明缺少本轮图像、数字或单位未出现在引用中、引用来自设想或边界说明时会阻止直接应用。这些校验只是必要条件，不能代替读者的科学判断。

完整建议、证据、缓存键和用量保存在插件目录 `knowledge-reviews/reviews/`。缓存键包含规则、学习内容、目标全文、证据和后端；恢复缓存、勾选与预览不再次调用模型。API 已返回结果但磁盘保存失败时，本次插件运行内重试会复用内存结果。重启后的未完成任务标为中断，待用户主动重试。

## 段落修订与恢复

逐条选择可应用的建议后，预览目标正文、索引和日志的全部变化。应用时再次核对学习内容、原文与已读取的知识库证据。目标、索引或日志在预览后发生变化时停止写入。保留 YAML、标题和原有链接；包含链接的原段落不允许整段替换。

修改前先把各文件的前后全文和指纹写入 `knowledge-reviews/revisions/`。多文件更新中断时保留恢复记录，只跳过指纹完全一致的已写入文件。撤销也先预览并生成独立修订；若目标已有后续编辑则拒绝覆盖。既有索引入口保留，缺失的索引文件不会被自动创建；日志记录这一处理。

`node tests/test_curation_writer.js` 使用内存验证预览、逐条采用、重复点击、并发手工编辑、存储失败、部分写入恢复、日志和路径篡改、撤销与索引边界，不操作真实研究笔记。

## 评估

`scripts/production-retrieval-check.cjs` 在 Obsidian 内显式运行，使用原有冻结私有语料与问题，并调用生产检索服务。私有结果必须保存在仓库和 Vault 之外。语料变化时停止同条件比较。它不生成答案或改写笔记。

`tests/fixtures/curation-counterexamples.json` 是合成的整理反例，涵盖同义、条件、数值、单位、对象、同源、缺失证据与指令伪装，标签用于检查整理建议，不代表真实科学发现。高相似度不能使建议自动获得写入权限。

每阶段运行类型检查、生产构建和安全定向回归，通过后提交推送。禁止执行包含批量或递归删除清理的测试；实际界面验收与模型评估单独记录。
