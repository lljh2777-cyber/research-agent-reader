## 阶段与约束

1. 固定生产检索复验与整理反例。
2. 独立学习索引，排除演示和测试，避免把 QA 当成论文证据。
3. 小批量建议、只读证据、缓存与用量记录。
4. 逐条预览、目标文件和来源复查、修改前快照及恢复日志。
5. 待审阅、需复查、修订与索引维护面板。
6. 两来源、两生成后端、异常恢复与真实 Obsidian 验收。

正式目标限于现有 `wiki/sources/`、`concepts/`、`methods/`、`synthesis/` 的正文，保留 YAML、标题、深度和现有手工编辑。原始 PDF 和 MinerU 包只读。模型只返回目标段落编号、候选正文及证据引用，文件路径和写入操作由插件控制。页面整合、新建正式页面、批量重写与自动升级 x-ray 不属于本版。

指纹比较、差异、历史浏览和预览在本地完成。生成请求使用选中节点、相关证据与目标段落；缓存依赖内容、来源、目标、后端及规则版本。页面切换和勾选不调用模型。缺少 API 用量时显示估算，推理和图像开销不能伪装为精确计费。

## 独立学习索引

`LearningLibrary` 将正式阅读节点与 `wiki/qa/` 作为学习记录读取，演示和测试会话及其可识别导出被排除。旧 QA 只参与相似性发现，来源未核验时明确标记。向量存放在插件目录 `learning-index/bge-v1.bin`，复用增量构建、停止、恢复和模型错误回退能力。

跨会话查询排除当前会话的节点。完全相同的正文标为「文字相同」，其余命中标为「主题相关」；两者都不能证明事实一致或独立证据。正式知识问答不会读取该索引。`node tests/test_learning_library.js` 使用内存验证范围、旧 QA、跨会话匹配和变化后的结果。

## 小批量生成与缓存

目标选段现在复用当前检索设置，可使用 BGE 混合检索和重排；检索只限用户选定的目标文件，核对文件指纹和字符位置，再与关键词候选合并，最多选八段。界面显示实际模式和回退原因。此步骤可能调用 embedding/rerank，不调用回答模型，也不保证覆盖全文所有重复。

新建议优先引用插件生成的原句编号，由插件还原精确文字和位置，旧逐字引用继续兼容。声称冲突时必须同时提供目标原句与另一方依据，否则按证据不足展示，并保留模型原分类。已验证的引用仍须人工判断是否支持结论；这些检查不是自动事实审查。

整理规则由仓库 `skills/knowledge-curation/SKILL.md` 嵌入构建，Direct API 与 Codex CLI 共用。默认一批一个节点，支线可选择一至三个已完成回答；最多五条建议。文字输入估算超过 18,000 token 时要求缩小范围，实际图像及推理开销另行计量。

建议必须定位到原目标段落并引用本轮证据原句。元数据、标题、代码围栏和不受支持的笔记目录不能作为修改位置。图表声明缺少本轮图像、数字或单位未出现在引用中、引用来自设想或边界说明时会阻止直接应用。这些校验只是必要条件，不能代替读者的科学判断。

完整建议、证据、缓存键和用量保存在插件目录 `knowledge-reviews/reviews/`。缓存键包含规则、学习内容、目标全文、证据和后端；恢复缓存、勾选与预览不再次调用模型。API 已返回结果但磁盘保存失败时，本次插件运行内重试会复用内存结果。重启后的未完成任务标为中断，待用户主动重试。

## 段落修订与恢复

逐条选择可应用的建议后，预览目标正文、索引和日志的全部变化。应用时再次核对学习内容、原文与已读取的知识库证据。目标、索引或日志在预览后发生变化时停止写入。保留 YAML、标题和原有链接；包含链接的原段落不允许整段替换。

修改前先把各文件的前后全文和指纹写入 `knowledge-reviews/revisions/`。多文件更新中断时保留恢复记录，只跳过指纹完全一致的已写入文件。撤销也先预览并生成独立修订；若目标已有后续编辑则拒绝覆盖。既有索引入口保留，缺失的索引文件不会被自动创建；日志记录这一处理。

`node tests/test_curation_writer.js` 使用内存验证预览、逐条采用、重复点击、并发手工编辑、存储失败、部分写入恢复、日志和路径篡改、撤销与索引边界，不操作真实研究笔记。

## 界面入口与日常维护

阅读界面工具栏「整理进知识库」或导出窗口「整理到已有笔记」打开整理工作台。选择一至三个同支线已完成节点，再选择已有笔记，先读取依据与文字输入估算，然后主动生成。默认不勾选建议；可核对引用、编辑候选正文、忽略，最后预览选中修改。关闭窗口保留生成，使用独立停止按钮取消。

命令面板「打开知识库维护」、阅读更多菜单和检索设置页均可打开维护面板。面板包括待审阅、需复查、修订记录与索引。正式知识和学习记录使用独立索引；更新索引只处理变化内容。Vault 文件事件提示「文件有变化，待检查」；手动检查逐项验证指纹，并将失效建议和已应用修订标记为需复查。外部 PDF 的变化在手动检查和应用前强制验证。

检查、浏览、差异与编辑校验不会调用回答模型。关联检索可能调用 BGE；只有点击生成才调用所选阅读后端。重新打开保存结果不再调用模型。用量区分接口报告与估算。

同批结果可重复使用；若需要模型重新判断，使用「重新生成（新请求）」，这会再次消耗模型用量，并保留前一批建议和决定。原文或目标已变化时，先重新读取依据。无法定位的引用持续阻止应用，重新加载不会解除这一限制。

## 验证记录

2026-09-07 生产检索复验：冻结的 40 题中，32 道可回答题 Hit@5 为 31/32，留出集为 23/24；未出现回退，语料指纹未变化。这是检索命中率，不是回答正确率。

14 条合成整理反例分别运行 Direct API（qwen3.7-flash）和 Codex CLI（gpt-5.6-terra）。两者严格满足「标签一致且候选正文不改写」均为 8/14，单看标签均为 11/14；13 条不应直接采用的候选均未获得应用权限，可补充案例可进入人工预览。差异包括把未验证归为冲突、把限定补充归为条件，以及在证据不足时返回空正文。保留原冻结标签和完整结果，不把这些差异计为通过；该小样本不能证明科学判断准确性。

三批反例的接口报告用量：Direct API 输入 3,030、输出 11,588 token；Codex CLI 输入 52,865、输出 1,535 token（其中缓存输入 13,568）。CLI 附加运行上下文，界面的选定材料估算不能作为总用量上限。私有原文、接口结果及逐题报告保存在 Vault 和仓库之外。

新增 `pnpm test:curation` 只运行内存测试，涵盖来源身份、保存后引用复查、阻止结果重载保护、部分写入恢复、并发手工编辑和长会话节点范围。完整旧测试入口包含递归清理，因此未运行；使用安全的阅读、检索、整理和接口回归替代。

真实 Obsidian 验收：Novae 的 MinerU 原文与原始 PDF 均通过 Direct API、Codex CLI 生成并保存建议，四种组合全部返回可审阅结果。原始 PDF 用首页完整标题补充身份核对；未匹配来源不能调用整理生成。已有笔记覆盖的内容会返回「已有内容覆盖」，不会强行追加。

`tests/obsidian-curation-ui.cjs` 在已有结果上验证未自动勾选、选中差异、完整文件展开、调整窗口后底栏可见、切换范围清除旧选择、重载缓存和维护导航；所有 Wiki 文件内容指纹保持不变。真实科学笔记的应用与撤销留给使用者在具体预览后决定；写入、中断恢复及撤销通过内存故障注入验证。

学习索引在测试库读到 7 个有效学习文档，首次嵌入 22 个片段；再次更新新增嵌入为 0。跨会话查询得到 4 个候选，排除了当前会话，未发生模型回退。此索引不会进入正式事实问答。

当前限制：这不是自动事实审核。模型可能混淆「冲突」「证据不足」等分类，也可能给出无法逐字定位的引用；必须核对原句与适用条件。每批只读取目标中相关的最多八个段落，不能保证发现全文所有重复。范围变化、候选选择和面板打开均不触发自动补写。完整旧测试入口未运行；测试库真实正式笔记的写回由使用者在预览中决定。

`scripts/production-retrieval-check.cjs` 在 Obsidian 内显式运行，使用原有冻结私有语料与问题，并调用生产检索服务。私有结果必须保存在仓库和 Vault 之外。语料变化时停止同条件比较。它不生成答案或改写笔记。

`tests/fixtures/curation-counterexamples.json` 是合成的整理反例，涵盖同义、条件、数值、单位、对象、同源、缺失证据与指令伪装，标签用于检查整理建议，不代表真实科学发现。高相似度不能使建议自动获得写入权限。

每阶段运行类型检查、生产构建和安全定向回归，通过后提交推送。禁止执行包含批量或递归删除清理的测试；实际界面验收与模型评估单独记录。

目标选段接入 BGE 后，较长的高相关段落可能超过整批输入预算。准备阶段会从排序末尾减少完整目标段落，直到文字估算不超过 18,000 token，并明确显示缩减数量和未覆盖范围；预算调整过程不额外截短本轮已选证据。即使只保留一段仍超限时才要求缩小学习节点范围。此估算不包含 CLI 附加上下文、图像或推理开销。

PDF 中连续英文句子的视觉换行保留在同一个原句片段内，不再逐行分配编号。模型每条建议最多引用八个片段，超限时给出明确提示；无效 JSON 会显示格式错误并允许重试，不自动修补后写入。0.34.0 的小规模实测中两后端均出现过可定位的建议，但 Direct API 最后一次返回了无效 JSON；该失败保留在验收记录，不能据此前成功声称所有模型请求均通过。
