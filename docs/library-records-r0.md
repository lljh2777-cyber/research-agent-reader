# R0 第三批：人工决定的持久记录

实施日期：2026-09-11，开发版本 `0.52.0`。承接 [R0 聚合与只读适配](library-r0.md)，实现人工阅读状态、主要笔记选择及其保存与恢复。文献详情和编辑控件仍属于 R1；本批提供可调用的接口和工程验收，不表示整个 R0 的科学质量基线已完成。

## 接口与保存位置

| 模块 | 责任 |
|---|---|
| [`record-store.ts`](../src/library/record-store.ts) | `PaperRecordStore` 接口、格式校验、只读历史查询、追加修订和身份读取 |
| [`record-service.ts`](../src/library/record-service.ts) | 根据当前聚合结果准备编辑凭据，校验人工选择，处理并发决定 |
| [`reader.ts`](../src/library/reader.ts) | 将持久记录加入文献视图，返回 `recordStates` 和可见读取问题 |
| [`catalog.ts`](../src/papers/catalog.ts) | 后续入库复用保存的身份，并核对经 DOI/PMID/PMCID 或 `paperId` 连接的整组冲突 |
| [`test_paper_records.js`](../tests/test_paper_records.js)、[`test_paper_record_storage.js`](../tests/test_paper_record_storage.js) | 内存故障／并发场景与隔离磁盘、独立进程恢复验证 |

插件暴露 `preparePaperRecord(paperId)` 和 `savePaperRecord(edit)`。准备结果包括当前文献、修订头、可选冲突版本和 `contextHash`。保存时必须带回这一凭据，并明确给出阅读状态、主要笔记选择或冲突版本；打开列表和准备编辑均不写入。

`readingState` 沿用 `unmarked / not_started / reading / completed / revisit`。`primaryNoteId` 省略表示保留、`null` 表示清除、字符串表示选择当前文献组内的 `wiki/sources/*.md`。它是导航偏好，不是审阅凭据，也不改变笔记内容或处理深度。

底层存储根由 `SourceStorage` 注入；当前插件只在自己的数据目录写入：

```text
<plugin-directory>/paper-records/<paperId>/
  v-<uuid>.json
  v-<uuid>.ready
```

每次修订记录格式版本 `1`、修订 ID、全部前置修订哈希、保存时间、文献人工记录和内容摘要。`.ready` 保存该修订摘要；JSON 与标记一致才算提交。身份快照包括已有 `paperId`、规范化标识、标题及可选 citekey。后续状态保存不能改写身份快照。修订 ID 仅标识保存尝试，不是新的文献 ID 体系。

存储使用已有固定根、限制大小和拒绝链接的文件接口，只追加文件，不替换旧版本、不删除文件、不回收锁。读取缺失目录返回空结果；只有显式保存才创建记录目录。`papers/`、Wiki、会话、原文包清单、设置和科研索引不参与人工状态写入，也没有 `_research/` 双写或迁移。

## 身份及编辑前提

1. 第一条人工记录必须来自当前视图里唯一、无身份冲突的已有 `paperId`。接口不能把调用方传入的任意 UUID 当成已确认文献。无 ID 旧资料的显式身份登记和新元数据记录入口留待后续添加流程。
2. 当前目录存在影响身份判断的读取故障时，保守停止人工保存。已说明的旧 MinerU 核验缺口和独立批注格式缺口不属于这类编辑阻塞；它们仍在查询结果中显示。损坏的已提交人工历史阻止保存，不回退成一份看似正常的旧状态。
3. 编辑凭据覆盖身份、对象归组、当前决定头及笔记内容哈希。准备之后笔记被编辑、关联变化或人工状态被另一编辑更新，旧凭据即失效。正在生成的讲解进度不属于人工决定的版本凭据。
4. 保存前重新读取目录和记录；主要笔记只能选当前组内的真实笔记。此前选择的笔记消失或改属其他文献，必须重新选择或明确清除，不能继续把旧路径当成有效选择。
5. 后续来源入库读取这些持久身份。即使最后一个原文包不再存在，仍可按精确标识沿用原 `paperId` 和 citekey。关联通过精确标识和已有 ID 展开，标题不合并文献；整组标识、多个 `paperId`、多个 citekey 或被其他已保存记录占用的 citekey 都会阻止自动关联。

只读的 `recordStates` 返回每篇记录的修订头、未提交尝试及是否损坏。发生人工决定冲突时，文献身份仍可显示，但不采用任何一方的阅读状态或主要笔记，返回 `record_conflict` 诊断。该状态不影响已有科学证据的等级。

## 并发、中断与恢复

| 情况 | 行为 |
|---|---|
| 同一决定重复保存 | 用最新凭据保存相同值时复用当前修订，不再追加 |
| 旧编辑提交 | 前置哈希变化后拒绝保存，要求重新准备 |
| 两个进程同时保存 | 各自使用独占新文件；如都提交，历史形成两个头。返回或下次读取会报告冲突，不按时间或文件顺序选胜者 |
| 选择冲突版本 | 必须指定当前某个 `chosenHead`；新修订同时引用全部当前头，保留双方历史。可以选择该版本后再修改人工字段 |
| JSON 写到一半或尚无提交标记 | 显示未提交尝试，不采用其状态；旧已提交状态可用，后续重试写新文件，残留文件保留 |
| 提交标记错误、内容摘要不符、父版本缺失或未知格式 | 视为已提交历史损坏，保留文件并停止保存；不自动修复或降级，需另行核对和恢复 |
| 插件／进程重启 | 从正式提交及父版本关系重建当前状态，不需要此前内存、修改时间或缓存 |

这是一份有冲突检测的追加日志，不是跨进程串行数据库事务。某个保存返回后，另一个更晚完成的并发写入仍可能产生冲突；重新查询会显示双方。断电、网络同步盘以及整个 Vault 的跨文件原子快照未作保证。笔记选择也不能绕过打开或写笔记时既有的来源校验。

每篇最多 1,024 个保存尝试，每份 JSON 最多 32 KiB，标记固定 64 字节；记录根最多 4,096 项。超过上限明确停止，没有自动清理。文献查询沿用总扫描预算；供来源入库使用的历史身份扫描另限 8 MiB，超限不分配替代身份。

## 验收

`pnpm test:library` 通过原有 16 个投影场景、11 个读取场景、新增 13 个人工记录场景，以及 1 组隔离磁盘测试。新测试覆盖已有 ID 复用、首次保存、主要笔记选择与清除、编辑后内容变化、重复保存、未知身份、身份冲突、写入中断、损坏标记、两个写入者、首次保存并发、显式冲突选择、断裂历史及持久身份参与后续入库。

隔离磁盘测试复用真实 `FileSourceStorage`，验证独占写入、竞争保存、旧文件字节保护，并启动独立 Node 进程重新读取相同修订头。夹具保留，不执行删除。通过来源入库 3 组、JATS 8 组、全文获取 6 组、相关阅读回归、类型检查、生产构建及发布审计。含递归清理的旧全量测试入口仍未运行。

原生 Obsidian 测试库部署 `0.52.0` 后，两次只读扫描分别为 429 ms、364 ms，每次 135 次文件读取、14 次目录读取、3,621,986 字节；对象和诊断一致。部署及查询前后 879 个受保护文件哈希、已有布局和阅读服务实例一致。查询未创建记录目录；未知 ID 的准备和缺少凭据的保存均被拒绝。原生错误检查无插件错误。

该测试库目前没有人工文献记录，本机测试未替真实论文写入“已完成”等状态；实际保存及重启恢复以独立夹具为验收依据。两次耗时仅是本机观察，不能推广为大库或同步盘性能承诺。

## 后续边界

工程基础已具备持久人工决定；后续 `0.52.1` 已交付[旧 MinerU 按需核验、外部批注兼容及混合格式性能测量](library-compatibility-r0.md)。R0 仍需建立真实科学质量样本，并明确大包、冷启动与增量性能缺口，再进入 R1 的可见文献详情和编辑控件。人工身份补全、标题更新、正式笔记审阅写入及存储迁移不在本批。

证据来源为项目代码、工程测试和原生接口运行结果，科学处理深度不适用。没有新增论文结论或研究笔记，因此科研索引和 Vault 日志不更新；原文及旧会话不变。
