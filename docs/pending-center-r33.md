# R3.3：跨阶段待处理中心

2026-09-12，开发版本 `0.71.0`。接通已有保存记录的只读聚合与返回原对象，让用户从一处找到待核对、待续办和待整理的内容。R3 整体继续开发。

## 使用流程

从首页“打开待处理中心”、文献库“待处理”，或命令“打开待处理中心”进入。可以搜索文献、路径和事项，按五个阶段筛选，刷新或取消读取。列表保留完整路径或记录标识；同名记录分别显示。

| 阶段 | 当前聚合范围 | 返回位置 |
|---|---|---|
| 书目与全文 | 未核验人工书目；完整扫描确认未发现已保存原文的书目 | 对应文献详情 |
| 获取与保存 | 未完成获取、无匹配、失败或取消记录；已获取但尚不能确认保存的结果 | 指定全文获取记录 |
| 入库与转换 | 本地添加待保存或登记；未完成入库任务；完整扫描未发现与指定 PDF 匹配的转换正文 | 本地添加记录、任务结果或原文详情 |
| 摘录待整理 | 尚无完成整理记录的 R3 独立摘录 | 对应摘录与个人备注 |
| 审阅与复查 | 文献关联冲突、来源缺失或核验失败、笔记待人工审阅、来源关联变化、待审阅整理批次与需恢复修订 | 文献详情、摘录或指定整理记录 |

点击返回前重新读取并比较所选记录。记录已变化、完成或无法读取时，保留窗口并提示刷新，不选择同名替代。返回之后，原功能继续负责核对、保存、转换、审阅和恢复；中心没有“全部完成”、隐藏事项或自动重试按钮。

## 读取与导航契约

- 聚合文献库、全文获取日志、本地添加日志、摘录、整理记录和已加载入库任务。各区独立读取，一处失败保留其他结果并列出提示；完整读取前不把缺失数据解释为没有待办。
- 文献库未完成核验时，不推断“缺少原文”和“缺少转换正文”。PDF 转换关系按该 PDF 的来源 ID 判断；全文获取结果只在保存路径唯一对应已核验来源，且文献身份一致时省略。获取成功本身不代表保存或登记完成。
- 本地添加历史复用原来的操作与完成凭据解码，提取为只读函数；不同设备或损坏记录只报告问题，不接管保存。全文历史使用生产记录解码，不初始化获取服务，不读 PDF 或启动下载。
- 整理记录读取沿用首页的边界检查，以原始文件摘要绑定选择；不为浏览中心初始化整理、阅读恢复或本地添加服务。显式返回原功能后，其既有初始化和恢复规则仍生效，例如整理窗口可能把遗留生成记录标记为中断。
- 摘录复用 R3.2 列表与完整文件摘要，通过摘录路径及 ID 关联来源状态。来源已变化的摘录进入复查；已完成整理的记录通常不再列出。旧批注保持原入口，本步不扩大摘录写入格式。
- 一次最多读取 256 条全文获取记录、200 条本地添加历史；摘录沿用 2000 个候选、每份 128 KiB 的限制，整理沿用 256 个文件和 64 MiB 总量边界。任务只取已加载的前 1000 条，中心最终最多保留 5000 项。达到限制明确提示；界面先展示 40 项，可继续展开，读取提示先显示 100 条。
- 刷新共用一次进行中的读取。失败或取消保留上次结果并禁用旧结果的返回操作；关闭后丢弃迟到回调。记录凭据与目标 ID 共同检查，不把标题作为身份。
- 没有新增持久目录、状态机或 schema，不修改原文、摘录、人工阅读状态、整理决定及任务结果。工作区布局属于正常导航保存。只读扫描不是跨文件事务快照，返回原功能仍需执行其自身核对。
