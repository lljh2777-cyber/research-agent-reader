## 真实流程

| 操作 | 结果 |
| --- | --- |
| MinerU 当前节点 → 核对原文 → 导出卡 | 本文第 13 页文字被实际读取；引用和节点范围通过本地校验；点击卡片打开节点导出预览 |
| PDF 当前节点 → 核对原文 | 三轮请求完成，实际读取第 2 页文字，返回可追溯引用；重载后页图渲染与定位按钮可用 |
| 正式知识检索 → 整理卡 | 混合检索找到对应正式来源笔记；候选编号解析为路径；界面预选一个节点和目标，完成依据与预算准备，未调用整理生成或写入正式笔记 |
| 助手卡 → 继续主线 | 交接到现有生成引擎；首次结果因引用不一致被拒绝，重试同一节点成功；主线数只增加一个 |
| 关闭窗口 → 切换模式 | 请求继续运行，执行记录仍归属原会话 |
| 重载插件 | 六条验收请求的回答、引用、用量及操作状态恢复，零恢复错误；Obsidian 未捕获运行错误 |
| 调整窗口尺寸 | 460 × 440 CSS 像素下正文保持可滚动，输入框和发送按钮位于可见范围 |

同一“核对一处原文并准备导出”任务的单次对比：默认思考时 4 次调用，接口报告输入 11,936 / 输出 12,611 token；启用原生 Schema 和非思考协调后 5 次调用，输入 15,047 / 输出 327 token。第二次多出一轮无效证据编号请求，被本地拒绝后纠正。此结果是小样本观测，不是稳定性能或费用保证。

整理实测曾出现相同错误目标反复提交，已增加候选编号解析、参数轨迹和重复错误停止机制。修复后完成正式笔记定位与预览交接。后续规则进一步明确：正式整理优先检索正式知识，历史学习仅按任务需要查找。

## 已知边界

- 助手每次独立处理当前任务，历史用于查看；普通连续追问继续使用原来的主线/支线输入框。
- 首版助手读取文字与图注，查看原文图像由已有阅读能力提供；不自动标记“已理解”“已核对”或升级 x-ray。
- 模型仍可能给出不合法或缺乏支持的引用；被拦截后保留失败状态，由用户重试，不自动付费循环修复。
- 本次真实新助手调用覆盖一个 Direct API 接口、PDF 与 MinerU。其他 Provider 及 Codex 的兼容性由定向回归覆盖，没有重新做所有后端的真实生成矩阵。
- 本轮只核对整理/导出预览，未实际采纳正式笔记修改或新增导出文件。现有写入、去重和修订服务的回归测试通过。
