# 交互式代码阅读

按三个阶段交付：源码与行号证据 → 主支线交互讲解 → 版本恢复、导出与关联。共享现有阅读导图、会话和后端，不执行项目代码。

## 第一阶段：代码来源基础

`src/code-reading/source.ts` 提供 Python/R 单文件与小型项目的只读加载。项目读取 `.py`、`.R`、README 以及常用依赖声明，不读取数据集、环境目录、隐藏目录或符号链接。配置白名单包括 pyproject.toml、setup.cfg、DESCRIPTION、environment.yml/yaml 和 requirements 文本。

- 每个片段保留真实文本、从 1 开始的行号、字符区间和文件哈希；保留 CRLF/LF 换行，UTF-8 BOM 不计入正文字符。
- 来源指纹覆盖本次源码清单及内容；新增、修改和缺失的源码均会使版本失效，被排除的数据文件变化不影响会话。
- 旧片段保留原版本内容。每轮使用之前重新核对文件；变化后提示创建新版本阅读，不把旧行号绑定到新文件。
- 首版上限为 160 个文件、单文件 512 KiB、总计 4 MiB；一次片段最多 80 行、8000 字符。超限要求缩小范围，不静默截断源码。目录索引也有大小限制。
- 首版不解析 Notebook/R Markdown，不推断完整调用图，不导入项目模块或运行代码。所有解释的处理深度为 `static-read`。

`pnpm test:code-reading` 使用内存文件系统，覆盖行号、换行、范围、版本变化、排除项、链接、编码、文件与上下文上限；没有文件清理操作。完整旧测试入口包含递归清理，不用于本阶段验收。

## 第二阶段：交互讲解（0.42.0）

控制台的“代码分析”默认进入共享交互阅读空间，也可使用命令“打开代码交互阅读”。选择 Python/R 文件或项目目录；“仅打开来源，不调用模型”建立阅读空间后，可通过“浏览源码”检查文件和行号，再从“开始讲解”推进。选择“打开并继续阅读”则直接生成路线和首个单元。

Direct API 与 Codex CLI 复用既有阅读后端，明确加载仓库内精简的 `skills/code-guided-reading/SKILL.md`。主线箭头、主输入框建立支线、支线内续问、划选历史回答建立子支线、双模式、单击选中/双击小窗、停止与重试沿用共享机制。

代码正式会话保存到插件目录的 `code-reading-sessions/`，测试记录仍在 `reading-test-sessions/`；已有 PDF 会话位置不变。原文对照展示保存时的代码和行号；源码变化后历史保留，后续模型调用被阻止，需要新建版本会话。导出保存独立 `wiki/qa/` 学习记录，可选择关联现有笔记；当前不自动整理或改写正式代码笔记。代码原文不会通过系统默认程序打开，避免意外执行脚本。

原有批量文档流程保留在“更多阅读选项 → 一次性代码笔记（Toolkit）”。首版代码交互会话暂不接入论文专用阅读助手、知识整理建议与联网补充；知识库检索可按本轮需要补充方法背景。

验证：类型检查、构建、20 组阅读回归、代码来源/会话测试、控制台回归与发布审计通过。`tests/obsidian-code-reading.cjs` 在 Obsidian 中完成 37 项检查：Python 项目和 R 单文件的源码预览、行号、规划和箭头、支线、双模式、导出预览与恢复；四个源码文件哈希保持一致。该脚本使用确定性模型替身，两个配置标签不代表真实 API 或 Codex 服务调用已验证。所有示例程序仅被读取，没有执行。
