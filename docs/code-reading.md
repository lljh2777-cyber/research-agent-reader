# 交互式代码阅读

按三个阶段交付：源码与行号证据 → 主支线交互讲解 → 版本恢复、导出与关联。共享现有阅读导图、会话和后端，不执行项目代码。

## 第一阶段：代码来源基础

`src/code-reading/source.ts` 提供 Python/R 单文件与小型项目的只读加载。项目读取 `.py`、`.R`、README 以及常用依赖声明，不读取数据集、环境目录、隐藏目录或符号链接。配置白名单包括 pyproject.toml、setup.cfg、DESCRIPTION、environment.yml/yaml 和 requirements 文本。

- 每个片段保留真实文本、从 1 开始的行号、字符区间和文件哈希；保留 CRLF/LF 换行，UTF-8 BOM 不计入正文字符。
- 来源指纹覆盖本次源码清单及内容；新增、修改和缺失的源码均会使版本失效，被排除的数据文件变化不影响会话。
- 旧片段保留原版本内容。每轮使用之前重新核对文件；变化后提示创建新版本阅读，不把旧行号绑定到新文件。
- 首版上限为 160 个文件、单文件 512 KiB、总计 4 MiB；一次片段最多 80 行、8000 字符。超限要求缩小范围，不静默截断源码。目录索引也有大小限制。
- 首版不解析 Notebook/R Markdown，不推断完整调用图，不导入项目模块或运行代码。所有解释的处理深度为 `static-read`。

`pnpm test:code-reading` 使用内存文件系统，覆盖行号、换行、范围、版本变化、排除项、链接、编码、文件与上下文上限；没有文件清理操作。完整旧测试入口包含递归清理，不用于本阶段验收。

## 第二阶段：交互讲解（0.42.0）

控制台的“代码分析”默认进入共享交互阅读空间，也可使用命令“打开代码交互阅读”。选择 Python/R 文件或项目目录；“仅打开来源，不调用模型”建立阅读空间后，可通过“浏览源码”检查文件和行号，再从“开始讲解”推进。选择“打开并继续阅读”则直接生成路线和首个单元。

Direct API 与 Codex CLI 复用既有阅读后端，明确加载仓库内精简的 `skills/code-guided-reading/SKILL.md`。主线箭头、主输入框建立支线、支线内续问、划选历史回答建立子支线、双模式、单击选中/双击小窗、停止与重试沿用共享机制。

代码正式会话保存到插件目录的 `code-reading-sessions/`，测试记录仍在 `reading-test-sessions/`；已有 PDF 会话位置不变。原文对照展示保存时的代码和行号；源码变化后历史保留，后续模型调用被阻止，需要新建版本会话。导出保存独立 `wiki/qa/` 学习记录，可选择关联现有笔记；当前不自动整理或改写正式代码笔记。代码原文不会通过系统默认程序打开，避免意外执行脚本。

原有批量文档流程保留在“更多阅读选项 → 一次性代码笔记（Toolkit）”。首版代码交互会话暂不接入论文专用阅读助手、知识整理建议与联网补充；知识库检索可按本轮需要补充方法背景。

验证：类型检查、构建、20 组阅读回归、代码来源/会话测试、控制台回归与发布审计通过。`tests/obsidian-code-reading.cjs` 在 Obsidian 中完成 37 项检查：Python 项目和 R 单文件的源码预览、行号、规划和箭头、支线、双模式、导出预览与恢复；四个源码文件哈希保持一致。该脚本使用确定性模型替身，两个配置标签不代表真实 API 或 Codex 服务调用已验证。所有示例程序仅被读取，没有执行。

## 第三阶段：源码划选、历史与导出（0.42.1）

完成一个主线单元后，在“浏览源码”中划选代码，点击“追问选中代码”，填写问题并“建立支线”。起点固定为打开源码时所选的已完成节点，没有有效选择时使用最新完成的主线。所选节点属于支线时，会建立其子支线；普通支线小窗输入仍用于续问。

- 选区独立于 AI 回答批注，保存文件相对路径、真实行号、文件哈希、精确字符区间与代码文本。Windows 换行和重复代码均按位置匹配，代码中的下划线、反斜杠等不会被当作 Markdown 清除。
- 每次提交先核对来源；引擎强制携带所选代码依据，再补充其他相关片段。失败可在同一节点重试，重复点击提交不会多建支线。
- 实测发现部分模型可能返回合法 JSON、但正文在代码处提前结束。现在检查行内代码和代码块是否闭合；发现问题则保留失败节点，重试附带具体格式反馈，不推进主线。此项只检查可识别的格式缺口，不等同于对讲解事实自动判真。
- 回答上方可展开所选源码；支线后续对话和子支线背景保留选区。输入草稿按起点和选区保存，重新选择相同代码可恢复草稿。
- 导出沿用独立 `wiki/qa/` 新文件、关联候选、重复检测与修订记录。增加 `analysis_depth: static-read`、所选源码和当时保存的完整引用片段；文件路径为非链接文本。导出不重新读取已经变化的源码，也不覆盖已有代码笔记。

离线验证覆盖选区精确匹配、强制提供选区依据、祖先与续问背景、保存失败、恢复和源码变更后的历史导出。20 组既有阅读回归、控制台回归、类型检查、构建及 28 项发布审计通过。Obsidian 确定性模型场景扩展为 49 项，包含实际 DOM 划选、子支线创建、防重复提交、引用与恢复，所有源码哈希不变。

`tests/obsidian-code-reading-live.cjs` 为独立的真实后端冒烟检查，不属于离线测试入口。它仅发送仓库内极小的 Python/R 示例，分别使用当前配置的 Direct API 和 Codex CLI 规划并生成首个单元；保留标注为测试用途的会话，不执行示例、不导出笔记、不清理文件。

2026-09-08 实测记录：Codex CLI（当前配置 `gpt-5.6-terra`）生成 6 单元路线并完成首个单元，引用与源码完整性检查通过。Direct API（当前配置 `qwen3.7-flash`）调用通路正常，但首次正文有未闭合代码标记；修复后复测及一次带反馈的重试均因正文缺少实际证据标记被拒绝。**该 Direct 模型的真实输出验收尚未通过**，保留可重试节点，没有绕过校验或推进主线；确定性模型的通过结果不能替代这一限制。模型可能将未提供的依赖实现说得过于确定，静态阅读仍需对照源码。当前 Direct 流式接口未提供实际 token 用量，不将缺失统计当作零消耗。

验收入口：控制台 → 代码分析 → 选择 Python/R 文件或小型项目 → 主线箭头 → 支线提问 → 浏览源码并划选追问 → 查看引用 → 切换模式 → 重载恢复 → 导出学习笔记。大型项目、Notebook/R Markdown、运行验证、正式代码页自动整理留待后续阶段。

## 来源选择（0.42.2）

“原文位置”保留手动输入，并提供“本机文件”“本机文件夹”（代码来源）和“从 Vault 选择”。本机按钮打开系统选择窗口；Vault 按展开逐层读取目录，点击文件或“选为项目”，再确认回填路径。PDF 只列出 PDF，MinerU 只列出 article.md，代码只列出 Python/R 文件及文件夹。隐藏目录与符号链接不列出，Vault 外来源请用本机选择。

选中来源只回填路径，不创建会话或调用模型。“仅打开来源”与“打开并继续阅读”仍是明确的后续操作；MinerU 包验证、源码范围和指纹核对继续在打开阶段执行。取消选择保留原路径；切换类型或关闭原窗口会丢弃过期选择结果。“重新定位原文”复用相同选择器。

验证：类型检查、构建、21 组阅读专项测试、3 组代码阅读测试和发布审计通过。`tests/obsidian-source-picker.cjs` 在测试库完成 14 项实际界面检查，覆盖 Vault 项目文件夹、PDF、article.md、关闭与类型切换、路径回填及重新定位入口；没有新增会话。系统窗口调用参数、文件类型过滤与取消结果通过模拟接口测试，实际系统窗口的人工点击选择仍由用户验证。所有测试均无批量或递归清理操作。

## 独立入口与阅读空间（0.43.0）

控制台和命令面板中的“PDF 深读”“代码分析”分别打开自己的标签页。再次点击入口返回该空间当前的会话；标签页尚未打开时，只恢复对应类型最近打开的正式会话。连续点击不会重复创建标签页。

- PDF 深读的新建窗口只提供 PDF 和已验证的 MinerU article.md；代码分析只提供 Python/R 文件与项目目录，各自保留手动输入、本机选择和 Vault 目录选择。
- 两侧的会话库、归档与开发测试列表分别筛选论文或代码。代码空间不显示论文交互演示。控制台的最近阅读概览仍可同时展示两类记录，点击后进入对应空间。
- 两个空间分别保留会话、草稿、导图模式、视野和小窗。切换标签页不停止生成；学习记录跳转会打开目标所属空间并定位节点。
- 原有布局只有会话 ID 时，根据该会话的来源恢复所属空间。会话文件无需迁移；底层主线、支线、存储和后端继续共用实现。

专项验收使用标注为测试用途的会话与确定性模型回复，不调用真实 AI、不执行源码。包括入口隔离、来源类型、会话筛选、草稿与模式、生成中切换、记录跳转和旧布局兼容；另对整个测试库重载后的双标签页恢复进行验证。Obsidian 的插件热重载可能清空活动插件标签页，不能代替应用布局恢复测试；此时可再次点击对应入口打开已保存会话。

验证通过：类型检查、生产构建、22 组阅读回归、3 组代码阅读回归、控制台回归及 28 项发布审计。原生 Obsidian 检查覆盖入口隔离 14 项、来源选择 14 项、代码交互 49 项、论文节点交互 101 项；测试库重载后两类会话恢复通过。历史界面测试改为按论文或代码类型查找标签页，本阶段只重跑上述相关原生场景。未运行含递归清理的旧全量测试入口。
