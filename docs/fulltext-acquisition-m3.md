# 全文获取 M3：开放 PDF 回退与既有入库接续

开发版本：`0.46.0`。本阶段完成「论文标识 → PMC / Unpaywall PDF → 校验与预览 → 选择模型和输出 → 现有入库」。总体设计见[架构与开发流程](fulltext-acquisition-design.md)，PMC 基础实现见 [M2](fulltext-acquisition-m2.md)。

## 使用流程

1. 在「设置 → 全文来源」填写自己的联系邮箱、保存，并启用 Unpaywall 回退。PMC 本身无需邮箱或模型配置。Unpaywall 查询会发送 DOI 和该邮箱；邮箱保存在插件本地设置，不进入获取任务日志。
2. 从控制台或命令打开「获取全文」，输入 DOI、PMID、PMCID 或官方论文链接，选择稿件范围。默认仅出版版本；作者接受稿需明确允许。
3. 核对论文身份和候选来源。优先发现 PMC PDF；PMC 没有可用候选时查询 Unpaywall。从选中的候选开始，文件获取失败会尝试列表后续候选。若 PMC 文件失败后才找到新的 OA 候选，会再次等待用户选择。
4. 获取成功后可直接「预览 PDF」。此时不需要模型，也没有生成原文包或 Wiki。
5. 点击「继续入库」，选择已测试的 Direct API 模型、原文 Markdown / 文章 Wiki 和补充说明。生成原文 Markdown 需要 MinerU，并单独确认 PDF 上传。
6. 现有流程继续执行标题页视觉确认、Crossref 身份核对、去重、转换和草稿保存。首页线索匹配不会代替用户确认回执。

获取面板显示关联入库任务及其状态，可打开任务结果。入库失败或中断后，获取任务仍为「已获取」；再次续办复用同一 PDF，建立新的入库任务，不重新下载。续办保留输出选项、说明、仍可用的模型以及转换参数，重新要求上传授权和身份确认。双击或同时打开多个窗口不会启动并发入库。

配置变化作用于新查询；已有任务保留创建时的来源开关。下载前仍读取当前邮箱和启用状态，因此关闭 Unpaywall 会阻止未完成的远程 OA 查询。已完成快照可以继续离线复用。

## 来源与版本政策

使用 Unpaywall API v2 的 DOI 接口及联系邮箱参数，遍历 `oa_locations`。只取明确的 `url_for_pdf`；`url` 或 `url_for_landing_page` 不作为 PDF 地址。接口及字段依据 [Unpaywall API 说明](https://data.unpaywall.org/products/api)和[数据格式](https://unpaywall.org/data-format)。

- `publishedVersion` 对应出版版本；`acceptedVersion` 仅在用户允许作者接受稿时纳入；`submittedVersion` 与未知版本排除。
- 出版版本排在接受稿前，同一版本优先出版社；遍历所有位置后按地址和版本去重，不只使用 `best_oa_location`。
- 一次记录最多接收 100 个位置、生成 20 个合格候选，超过上限明确失败。未提供许可时显示缺失提示，不推断使用权。
- 不抓取出版社网页、不猜测 PDF 链接、不使用账号登录或签名地址。没有合格候选仅说明本次接口及策略范围内未找到 PDF，不表示论文没有开放全文。
- 候选只持久化来源域、地址 SHA-256、完整响应 SHA-256、稿件类型、许可及时间。选择后重新查询；地址、版本或响应记录变化时要求重新发现候选。

PMC 的清单与 MD5 检查继续保留。两条来源路径都核验本地 SHA-256、PDF 格式、可解析性、页数和首页身份线索。明显身份冲突停止；线索不足保留 `needs_confirmation`。所有获取快照的正文检查仍为 `not_checked`。

## 模块与边界

| 文件 | M3 责任 |
|---|---|
| `src/fulltext/unpaywall-provider.ts` | 联系邮箱校验、精确 DOI、位置筛选、排序、去重与下载前复查 |
| `src/fulltext/url-policy.ts`、`transport.ts` | 动态 HTTPS 目标、逐跳地址检查、固定请求头和共享字节预算 |
| `src/fulltext/contracts.ts` | OA 来源定位信息、兼容旧快照的运行时解码、入库引用 |
| `src/fulltext/pmc-backend.ts`、`service.ts` | PMC 优先、OA 回退、候选切换、活动预算、已获取文件复用与任务关联 |
| `src/fulltext/intake-adapter.ts`、`intake-modal.ts` | 快照到入库参数的绑定、输出和模型选择、独立授权、失败续办 |
| `src/fulltext/modal.ts`、`pdf-preview.ts` | OA 来源展示、被动 PDF 预览、关联任务状态 |
| `src/plugin.ts`、`src/runtime/persistence.ts` | 装配服务、入库前检查、TaskRun 引用、历史保留与窗口关闭 |
| `src/agent/pdf-identity.ts`、`agent-loop-service.ts`、`mineru-publish.ts` | 授权副本必须匹配获取哈希；新路径保留副本与暂存目录 |
| `src/settings/`、`src/runtime/settings.ts` | 独立来源配置，默认关闭 Unpaywall |

仍使用 M2 的 schema v2 PDF 快照，新增 OA 候选字段；已有 PMC 快照和 M1 演示保持兼容。获取记录和文件保存在插件 `fulltext/production/` 下。TaskRun 另存 `acquisitionSource`，包含获取任务、快照、字节数和哈希；获取任务保存 `intakeRunIds`。入库请求记录也携带同一引用。

适配器在打开入库、启动模型前重新核验快照和路径。授权副本复制时核对预期字节数与哈希，处理短写入；请求不能去掉或替换任务绑定的引用。旧入库的视觉确认回执仍绑定本次新任务，不能从获取结果伪造。

## 资源与文件保留

| 项目 | 当前行为 |
|---|---|
| 固定接口主机 | Europe PMC、Crossref、PMC S3、Unpaywall API |
| OA PDF 主机 | 允许合格位置中的公网 HTTPS 域名；每次重定向重新验证，可跨公网来源域 |
| 连接检查 | DNS 答案全部为公网；选定地址绑定实际 TLS 连接并核对对端；拒绝私网、字面 IP、认证信息、片段、非默认端口及已识别的签名/凭据查询参数 |
| 请求上下文 | 不继承系统 / Obsidian 代理，不发送 Cookie、认证头或 Referer；邮箱仅出现在 Unpaywall API 查询中 |
| 响应大小 | 元数据单响应 2 MiB；PDF 单文件 64 MiB；整个候选序列累计接收 PDF 字节 128 MiB，包含失败候选 |
| 时间 | 来源发现含排队 20 秒；总活动时间最多 5 分钟，等待人工选择暂停；单次 PDF 传输 120 秒，原有连接、空闲和解析时限继续生效 |
| 失败处理 | 网络、类型、传输或校验失败可继续后续候选；身份冲突、总预算或阶段超时停止；新候选使用新的尝试 ID，旧文件保留 |
| 自动历史淘汰 | 带获取引用的入库任务不进入自动文件回收；`data.json` 保持最多 300 条记录的既有硬上限 |

获取快照不会传给旧临时文件销毁函数。新入库路径创建独立授权副本，并明确启用保留策略；成功、失败、中断后释放句柄，保留副本及 MinerU 暂存目录，包括成功后留下的空目录。没有完成标记的内容不能成为正式原文包。关联保存失败不会把原本已获取的 PDF 改成获取失败，也不会启动模型。

此策略只覆盖 M3 新入口触达的路径；旧入口的清理行为没有整体重写。这里的 PDF 和暂存内容不会自动回收，后续清理应由用户明确处理。没有增加统一 SourceCatalog、XML/HTML 转换或模型无关的「仅保存原文」入口，这些属于 M4 及后续阶段。

## 验收方法与实际结果

2026-09-09 使用以下分层验收；真实来源验收为显式脚本，不进入默认单元测试。测试不删除文件或目录。

- `pnpm test:fulltext`：六组专项。覆盖邮箱缺失、地址隐私、所有 OA 位置、稿件范围、清单变化、候选失败切换、PMC 文件失败后的 OA 再选择、累计字节限制、私网及重定向拒绝、快照哈希和关联保存失败。
- 入库保留专项使用内存文件系统运行实际授权复制和原子发布函数：短写入、磁盘写入失败、复制失败、标题冲突、取消、目标占用、重命名失败与成功；失败文件与暂存容器保留，删除调用为零。它不执行真实 MinerU 提取或远程上传。
- 原生 M3 入库 27 项检查通过，覆盖未配置模型、独立上传授权及条件显示、重复点击、实时状态、失败续办、转换参数沿用、重新授权、停止及两种宽度。使用真实插件任务生命周期和内存记录，三个模拟后端调用，真实模型与 MinerU 调用均为零。截图复查发现并修复了复选框被文本框样式拉宽、隐藏授权行仍占位的问题。
- 原生全文入口 / 演示 14 项、旧入库续办 28 项、设置导航与布局 76 项检查通过。设置仍有六个常用入口，十三个页面可搜索与跳转。
- 类型检查、生产构建通过；入库五组、控制台两组、设置及阅读 22 组专项通过。旧全量测试入口含禁止的清理行为，未运行，不宣称全量通过。

真实 OA 样本为 DOI `10.21105/joss.01143`，标题 *ArviZ a unified library for exploratory analysis of Bayesian models in Python*。Unpaywall 返回 JOSS 出版版本 PDF，许可字段为 `cc-by`。实际下载 561,683 字节、5 页；SHA-256 为 `6712d61de7cdcb1d15d4f24ed27161794a1c9ccd6fadfbde2b681dd138225ffb`。原生 PDF.js 完成格式与首页身份线索检查，已实际查看预览截图。来源发现三次元数据调用，选择后一次 Unpaywall 复查及一次 PDF 传输；重载后的复用与预览均为零网络调用。

另检查 DOI `10.1051/0004-6361/202348125`：本次 API 返回的出版位置没有直接 PDF，带 PDF 的位置标为 `submittedVersion`，因此返回无合格候选。该结果只表示本次位置字段与版本政策不满足条件，不是对该论文开放状态的判断。

原有 PMC 样本 `PMC10009416.1` 在重载后通过 13 项恢复及预览检查，三种标识复用相同文件，元数据请求和 PDF 传输均为零。新增多篇记录后发现旧验收脚本误点列表首个预览按钮，已改为按目标任务定位并通过复测。

部署前备份三个构建文件，最终部署哈希与当前构建一致。与 M3 开始前相比，123 个既有非配置、非构建文件内容未变；`data.json` 除用户授权的 Unpaywall 开关和邮箱外保持一致。已检查邮箱未进入仓库及获取日志。28 项发布审计通过，Obsidian 未捕获错误；验收窗口已关闭，临时焦点模拟已恢复。

真实测试只核验元数据、文件与界面，没有调用模型或 MinerU，没有生成论文科学笔记。处理范围为 `metadata-only` 加文件完整性及首页线索检查，不属于 `abstract-level` 笔记或 `x-ray` 深读。原始架构提案、研究 Vault 的索引和研究日志未修改；实际 PDF、获取记录和截图保留在测试环境，联系邮箱不提交到代码仓库。

下一阶段 M4 将处理统一来源目录与解析产物，并提供独立的原文保存路径；本次未实施这些能力。
