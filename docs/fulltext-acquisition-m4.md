# 全文获取 M4：来源中立身份与独立原文保存

实现版本：`0.47.0`，2026-09-09。本文记录本阶段的实际行为；总体设计见[架构与开发流程](fulltext-acquisition-design.md)。

## 使用流程

1. 在全文获取面板完成一篇 PDF 获取，选择「仅保存原文」。无需配置模型或 MinerU。
2. 核对来源记录、作者、年份、精确标识和稿件类型。插件展示此快照的真实 PDF 页面，可以选择前 3 页。
3. 图像完成显示后，点击「确认页面与记录一致，保存原文」。关闭窗口会停止未进入最终提交的保存。
4. 完成后，PDF 位于 `papers/<citekey>--pdf--<摘要>/source.pdf`，`papers/index.md` 增加普通路径记录。没有生成 `article.md`、文章 Wiki 或科学结论。
5. 若提示「原文已保存，登记待完成」，通过「查看原文保存与登记」重新核对并补登记。完整 PDF 不会重复复制。

需要转换或文章 Wiki 时，继续使用「继续入库」。该入口独立选择输出、模型和 MinerU 上传授权。原文保存与后续入库分别完成，PDF、转换正文和 Wiki 不互相冒充完成状态。

## 模块与身份规则

| 模块 | 职责 |
|---|---|
| `src/papers/identity.ts` | 共享来源身份、确定性摘要、精确标识关联与 citekey |
| `src/papers/catalog.ts`、`vault-catalog.ts` | 只读发现正式 PDF 包及旧 Markdown / Wiki 的关联 |
| `src/papers/confirmation.ts`、`identity-modal.ts` | 来源中立 v2 回执及真实 PDF 页面展示 |
| `src/papers/source-intake.ts`、`source-save-modal.ts` | 保存计划、明确确认、独立发布和原文索引补登记 |
| `src/sources/storage.ts`、`pdf-package.ts`、`reading-guard.ts` | 有界文件 IO、严格清单与 PDF 阅读前核验 |
| `src/papers/agent-intake.ts` | 新获取入口的确定性入库决定，以及旧 v1 的来源目录适配 |

论文 `paperId`、书目 `citekey` 与来源包 `packageKey` 分开。DOI、PMID、PMCID 有共同精确标识时才建立关联；另一共同字段冲突时停止。标题相同不会自动合并。同一论文发现不同 citekey 或不同 paperId 时，需要先核对现有记录。

相同 DOI 的不同稿件类型、PMC 来源版本或 PDF 哈希分别保留。OA 位置没有统一的版本号时，以获取时的 OA 记录摘要作为保守区分依据，因此记录更新可能形成新的包。完全相同的已提交来源复用原包，后续获取记录关联到它；不会改写原包的首次确认与来源证据。

旧 Markdown / Wiki 的精确标识从前置属性读取；旧 Wiki 可通过 `source_path` 提供旧 MinerU 路径。无可靠标识的旧文件不会因标题相似自动合并。旧属性损坏、标识冲突或超出读取预算时会停止，用户修复后重试。这里没有迁移或改写旧笔记。

新获取入口不再调用模型判断身份或决定重复关系。Europe PMC 的已核验记录可独立作为身份依据，不要求 Crossref 必须命中。模型只负责已选 Wiki 的正文和译名生成，仍受原有证据与创建规则限制。

旧本地 PDF 入库仍保留 v1 的 Crossref、工具回执与人工确认门槛；正式 PDF 目录为它提供确定性的书目关联，并保留模型查重建议的差异说明。PDF 包不被伪造成旧正文命中。尚未把本地 PDF 选择器接到新的「仅保存原文」动作。

已转换正文仅在原 PDF 哈希、大小和解析参数均相同，且旧 MinerU 包通过完整验证时复用。新转换目录摘要包含 PDF 哈希与解析参数，书目 citekey 不随目录变化。现有匹配转换的提取器版本沿用其原清单，本阶段没有新增“强制以新版提取器重算”或统一转换任务管理。

## 确认、提交与恢复

v2 回执绑定 `requestId + snapshotId + primaryArtifactHash + identityDigest + displayedEvidenceDigest`。页面证据包含实际 PNG 摘要、像素摘要、页码、总页数、尺寸、比例和 PDF.js 版本。仅显示文字摘要或传入布尔值不能替代页面确认。旧 v1 验证器不接受 v2 回执；新入库的 v2 回执也写入其任务结果，便于回看。

正式 PDF 包包含：

```text
papers/<packageKey>/
  source.pdf
  _source/
    transaction.json
    acquisition.json
    validation.json
    identity-page.png
    manifest.json
```

私有恢复计划位于插件目录的 `source-intake/<requestId>/`，保存设备、快照、确认页和索引计划。正式文件采用独占创建：先写所有权事务，再写 PDF 和其余证据，逐个核验，最后创建 `manifest.json`。没有有效提交清单的目录不可作为完成来源打开；未知包类型、文件缺失、修改或额外文件也会阻止加载。

中断恢复只复用本事务中已完成且哈希一致的文件。未知目录、不同设备计划、用户修改或截断文件不会被自动接管或覆盖。若只留下空目录而尚无所有权事务，也会停止；保留文件需由用户核对处理。本阶段没有自动清理。

最终提交开始后，关闭窗口不会撤销已在提交中的操作。清单写入失败仍是保存失败；清单已完成但索引登记失败则是独立的待登记状态。补登记先验证原包，再比较当前索引内容，保留原有文字；同一登记行不会重复添加，已被用户改写的本条记录不会自动覆盖。

单 PDF 上限 64 MiB，确认 PNG 上限 16 MiB，单清单 / 私有计划上限 256 KiB，原文索引上限 64 KiB；目录最多 4096 项。已匹配论文最多核验 40 个来源包。旧候选扫描最多 2000 个 Markdown 文件、总量 64 MiB。窗口关闭或保存完成后释放缓存 PDF 字节，过多同时核对的原文会提示先关闭其他窗口。

## 验收

- `pnpm test:sources`：三组专项，覆盖 v2 绑定、无需 Crossref 命中、同 DOI 多版本、旧目录关联、无模型保存、清单最后提交、短路拒绝、取消、设备归属、故障恢复、索引补登记、用户修改保留和禁止错误降级。文件系统专项在保留的独立临时目录运行完整保存与严格读取，包含 Windows junction 拒绝；不删除文件或目录。
- `tests/obsidian-source-intake.cjs`：真实 Obsidian 界面 21 项检查。读取已有公开 JOSS PDF，以真实 PDF.js 渲染确认页，测试无模型入口、两种宽度、关闭窗口、重复点击、索引失败、重启补登记和新入库 v2 展示器。正式包、人工确认回执及索引的模拟写入全部位于内存；真实模型、MinerU、网络请求均为零。
- 真实界面截图已复查。用于渲染的 PDF 为 DOI `10.21105/joss.01143` 的既有获取快照，5 页；本阶段未重新下载。
- 原生获取后入库 27 项、旧入库续办 28 项回归通过，使用模拟后端，不运行真实模型或 MinerU。
- 最终构建重载后，M4 原生检查再次通过；既有 PMC 快照的 13 项恢复 / 预览检查及 JOSS OA 快照复用通过，两者均为零网络请求。
- 获取六组、入库五组、阅读 22 组、控制台两组专项通过；类型检查与生产构建通过。含禁止清理行为的旧全量测试入口未运行，不宣称全量测试通过。

三个构建文件已备份并部署到测试库，部署文件哈希与当前构建一致。与 M4 开始前相比，155 个非构建文件（含 `data.json`、原有设置和任务历史）内容不变。已检查联系邮箱未进入仓库或获取日志。发布审计 28 项通过，Obsidian 未捕获错误。

本阶段开发和测试没有生成正式论文科学笔记，证据范围为代码执行、文件完整性和首页显示，属于 `metadata-only` 及文件验收，不属于 `x-ray`。仓库文档已更新；研究 Vault 的科学索引、CSV、BibTeX 与研究日志不属于此次开发范围，未修改。原始架构提案保持原状。

M5 将接入 XML/JATS 来源及正文规范化；M6 再处理结构化来源的交互深读。Zotero / RIS / BibTeX 新入口与批量处理不在本次范围。
