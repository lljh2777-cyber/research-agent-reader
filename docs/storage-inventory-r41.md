# R4.1：只读存储盘点与迁移预览设计

2026-10-05，开发版本 `0.82.0`。本步骤交付独立命令行盘点工具和首批测试库报告，开始 R4。尚未实现复制、路径切换、回退或正式迁移，不把盘点完成视为 R4 验收通过。

## 已交付

- `scripts/storage-inventory.cjs`：只读扫描实际指定的插件目录，输出逐文件大小、修改时间、分类、候选位置及问题；可选只对持久记录候选计算一次 SHA256，不哈希全文包、缓存、配置或整个 Vault。
- `scripts/storage-inventory-rules.cjs`：按现有生产存储职责分类，从明确字段提取身份与引用。未知文件保持待复核，缓存目录内的陌生文件也不自动归为缓存。
- `tests/test_storage_inventory.js`：保留隔离磁盘夹具，包含独立 Node 进程运行；不调用模型、联网或执行文件清理。
- `pnpm storage:inventory` 和 `pnpm test:r4`：提供开发入口；插件界面和运行时存储路由保持上一阶段行为。

命令要求明确传入实际插件位置，不假设每个 Vault 都使用 `.obsidian`。扫描直接使用只读文件接口，不调用 `ReadingRepository.load()` 或其他可能在读取时初始化目录、恢复任务、改写中断状态的生产仓库。

## 使用

在仓库根目录运行。报告父目录须提前存在，文件必须是新文件，且位于 Vault 和源码仓库之外：

```powershell
pnpm storage:inventory --vault E:\paper-test --plugin-dir .obsidian/plugins/research-agent-reader --output E:\research-reader\r4-inventory-20261005\another-inventory.json --fingerprint
```

`--target` 指定候选 Vault 相对根，默认 `_research`，只生成预览路径，不创建目录。`--fingerprint` 可省略；默认仅盘点，不计算内容哈希。现有报告不覆盖。退出码 `0` 表示本次范围内未发现结构问题，`2` 表示报告已保存但需要处理问题，`1` 表示参数、读写等错误。无论退出码如何，报告始终标为 `migrationExecutable: false`。

报告不导出正文、问题、模型回答、提示词或凭据值；仅从 `data.json` 提取历史数量、是否配置工具库、允许的目录设置。路径、记录 ID 和摘要仍可能包含私人研究信息，报告应保存在本机，不提交到公共仓库。不访问 SecretStorage 或外部工具配置，不在报告输出联系人邮箱。

## 检查边界

从根到文件逐级检查符号链接、Windows junction 和特殊文件，读取前后比较节点和修改属性；扫描完成再检查已访问文件与目录。Windows 8.3 短路径仅在指向同一实际节点时接受，输出位置再次按真实父目录核对。此检查用于盘点，不能替代迁移时的停写与锁定。

读取有文件数、深度、单文件／总字节数及引用数上限。达到上限、无权限、JSON／UTF-8 损坏、来源变化、未知条目、同名冲突、pending、提交标记缺失、标记摘要不一致、孤立标记或未完成建页均进入报告。目录存在不代表内容有效。

支持显式来源路径、阅读会话 ID、主要笔记、整理目标与修订关系、草稿材料、建页草稿版本、主题目录等引用。绝对外部路径仅标为未检查，不访问外部机器路径；`demo://reading` 只有在会话明确标为演示时作为内嵌来源。尚未创建的计划目标单独标注，不冒充现有文件。

报告目前**不执行生产格式、内容摘要、父版本拓扑、全部引用闭包及记录语义校验**。对 `.ready` 的配对和保存摘要比较只属结构检查，不能证明内容摘要正确。即便问题数为零，也可能存在不兼容版本、历史冲突或未发现的依赖。首批候选位置是设计预览，不能直接作为可执行复制清单。

## 后续迁移流程设计

1. **生产校验与依赖闭包：** 将候选记录送入各模块的纯校验函数或只读适配器，验证历史、固定材料、唯一来源与引用。特别保留回答摘录对旧会话的依赖，以及整理、草稿、建页与目标文件之间的关系。对 `data.json`、任务输出和本机所有权单独设计，不因新根改变设备 ID。
2. **保留副本演练：** 只在新隔离副本建立迁移清单，绑定来源根、格式版本、完整文件集合、指纹、目标和依赖。中断文件、未知格式、目标冲突、来源变化或空间不足均保留报告并停止。
3. **复制与核对：** 明确停写后先复制，逐项验证新旧内容与引用；复制日志可重入，旧文件保留。尚未具备依赖闭包的获取／入库事务保持原路由。
4. **单写入端切换：** 每类数据只选择一个写入根。兼容读取不能导致双写或以旧副本覆盖新记录。切换记录和格式版本经过副本演练后再接入运行时。
5. **回退：** 停写并核对切换后新增内容；能安全保留新增历史才恢复路由，否则维持新位置只读并提供恢复报告，不能直接指回旧目录。

下一步是 **R4.2：生产格式与引用闭包校验，并在保留副本演练读取恢复**。正式 Vault 路由切换遵循路线中的具体预览和批准要求，本步骤没有发起切换。
