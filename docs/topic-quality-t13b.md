## 执行边界

1. [`prepare-topic-quality-run.cjs`](../scripts/prepare-topic-quality-run.cjs) 检查已冻结的基线、教学规则与输入摘要，将现有路线和教学服务打包到新的库外目录。计划同时记录源码、运行器、构建产物与运行时字节摘要。参考要点和模型输入分别保存。
2. [`topic-quality-runner.cjs`](../scripts/topic-quality-runner.cjs) 显式选择已验证的 OpenAI-compatible 模型，使用原有凭据解析和 HTTP 适配器。它以独立宿主对象捕获请求，不替换正在使用的插件传输层或设置。
3. 两份固定路线通过实际 `TopicLearningService` 保存和确认，再使用 `TopicStudyService.generate()` 依次调用“下一单元”与“追问”。不调用模型生成路线，不额外生成摘要，不改写祖先回答；每题只保留第一次尝试。
4. 请求必须与固定目标、路线、问题和实际祖先回答一致；主支线关系按生产日志重放。只允许文字、原教学 JSON 结构及已验证的结构化输出选项；不允许图片、工具、搜索、流式调用或额外请求。
5. 实际请求正文先独占写入并同步到磁盘，再交给现有传输层。记录响应正文、HTTP 状态和字节摘要，不保存请求授权头或密钥。代理的原始响应可能带有推理字段，原始材料留在本机；审阅文档只呈现教学正文。
6. 空答、格式错误、截断、拒答、HTTP 错误、取消、写盘失败或协议变化停止后续题目。已有目录不可覆盖，重载或状态查询不自动恢复请求；已有发送回执但缺少完成记录时，服务端结果按未知处理。
7. 教学服务的持久化日志与 QA 回执均位于库外，不在测试 Vault 创建教学会话、导出笔记、理解标记或索引。测试库中现有文件与布局在运行前后核验。

每题沿用生产请求的 `max_tokens: 5000`、HTTP 超时 120 秒与教学服务总超时 180 秒。客户端最多发起九次请求，不自动重试；上游代理的实际模型身份、计费和内部调用次数无法从客户端独立确认。接口未报告费用时保留未知值。

## 复现与取消

先在项目根目录完成构建和准备；输出父目录须存在，目标目录必须使用新名字。

```powershell
pnpm build
pnpm test:topic-quality
node scripts/prepare-topic-quality-run.cjs E:/research-reader/topic-qa-new/plan
```

准备器在普通 Node 环境运行；Obsidian 只加载纯 Node 运行器和已打包的本地服务，不在宿主中启动 esbuild。

在测试 Obsidian 开发控制台显式执行：

```javascript
const qa = require('E:/research-reader/research-agent-reader/scripts/topic-quality-runner.cjs');
qa.startInObsidian(app, {
  planDirectory: 'E:/research-reader/topic-qa-new/plan',
  planHash: '替换为准备器返回的完整摘要',
  outputDirectory: 'E:/research-reader/topic-qa-new/run',
  profileId: '替换为已验证配置的 ID'
});
```

调用立即返回，九题后台串行运行。使用 `qa.status(运行目录)` 查看各题状态，使用 `qa.cancel(运行目录)` 取消当前请求及后续题目。运行期间不要重载脚本模块、刷新 Obsidian 或卸载插件。检查已存在的开始记录、请求、响应、结果及中断记录后，才决定是否显式开展另一批测试；不要盲目重投已提交题目。

生成审阅包不调用模型：

```powershell
node scripts/report-topic-quality.cjs E:/research-reader/topic-qa-new/run E:/research-reader/topic-qa-new/plan <planHash> E:/research-reader/topic-qa-new/review.md
```

[`report-topic-quality.cjs`](../scripts/report-topic-quality.cjs) 从实际学习日志重建每题之前的状态，核对固定路线、祖先回答、主支线位置、首次请求／响应与供应商报告用量，再独占创建审阅文件。模型正文放入动态长度代码围栏，避免回答中的 Markdown 变成报告结构或执行内容。请求／响应字节变化、非首次回答、额外理解标记或摘要不一致会拒绝生成报告。

数据预处理的核对依据为 [scikit-learn 官方注意事项](https://scikit-learn.org/stable/common_pitfalls.html)：测试集不得参与拟合预处理参数，训练集得到的变换应用于两者。梯度与更新的核对依据为 [PyTorch 官方优化教程](https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html)：反向传播形成梯度，优化器步骤调整参数。本轮只把这些网页用于开发者复核，没有发送给被测模型。

初读 N01 后另核对 [PyTorch 梯度截断接口](https://docs.pytorch.org/docs/stable/generated/torch.nn.utils.clip_grad_norm_.html)：该操作直接修改参数已有的梯度，不是损失函数 `criterion` 的一般职责。这是开发者发现问题后的补充核查，未反向修改冻结参考。

N03 的补充核查依据为 [PyTorch 自动微分教程](https://docs.pytorch.org/tutorials/beginner/basics/autogradqs_tutorial.html)：常规计算图不能省略条件地重复反向传播，同图复用需说明 `retain_graph`，跨批次则重新进行前向计算；梯度默认累积，因此清梯度和复用旧梯度的条件需要交代。这里只核对文档，没有执行模型示例代码。
