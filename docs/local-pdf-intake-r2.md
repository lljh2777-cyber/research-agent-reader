# R2 第三批：本地 PDF 添加与恢复

2026-09-11，开发版 `0.63.0`。在[本地来源与共用保存器](local-pdf-core-r2.md)基础上开放完整用户流程，已部署至测试库；公开 beta 仍为 `0.31.0`。

后续状态：`0.64.0` 已将文献库添加按钮收为[统一添加文献入口](paper-intake-r2.md)，既可从本地 PDF 开始，也可保存书目信息后沿用确认身份添加 PDF；原本地命令继续可用。下文保留 `0.63.0` 当时流程与验收范围。

## 使用流程

1. 在文献库点击“添加本地 PDF”，或运行同名命令。使用本机文件选择窗口，也可输入 PDF 绝对路径，单文件上限 64 MiB。
2. 输入 DOI、PMID、PMCID 或已经支持的论文链接。查询向 Europe PMC／Crossref 发送标识；PDF 仅在本机读取，无模型请求、上传或转换。
3. 版本默认“未核验”。出版版本与作者接受稿需要用户主动声明，身份核对不代替版本或许可判断。
4. 核对书目信息和实际 PDF 页面，必要时切换核对页。图片成功解码显示后才允许确认保存；换页立即撤销旧页面的确认状态。
5. 点击“身份一致，保存 PDF 原文”。相同本地内容和版本已有完整包时改为明确复用。保存后可跳转到准确文献记录并打开原文，保持阅读状态未标记，不生成 Wiki。
6. 在“本地 PDF 添加记录与恢复”继续未完成的保存或登记。恢复不重新查询网络，不生成新快照。文件移动后可重新选择，但必须与原快照的大小和 SHA-256 一致。

原文件尚在本机时，重载后可以直接继续。已完成记录表示当时登记成功；再次操作会核验来源包及原文件，不把历史完成状态当作实时文件健康结论。记录损坏或设备不匹配时展示问题，不接管或覆盖。

## 实现与持久化

- `src/papers/local-pdf-intake.ts` 负责查询、本地准备、固定快照恢复和设备内操作记录。PDF 确认与发布仍交给 `SourceIntakeService`，不创建假的下载任务。
- `src/views/local-pdf-intake.ts` 负责文件选择、书目及版本展示、页面解码、明确保存、历史续办和取消／关闭后的迟到回调守卫。
- `src/plugin.ts` 接入服务、命令与卸载收束；`src/views/paper-library.ts` 提供入口，扫描或人工编辑期间禁用添加按钮。`styles.css` 适配窄窗口。

预览和取消不写盘。首次点击保存时，在插件目录的 `local-pdf-intake/<snapshotId>.json` 只增创建原始路径、设备标识及完整本地快照；原文发布与索引登记成功后另建 `<snapshotId>.saved.json`。完整原始路径只在设备绑定的操作记录中保留，不进入可迁移的原文包。显式重选可以使用不同路径，但不会覆盖原操作或改变快照的文件名和来源身份。历史最多读取 200 条，单次插件生命周期最多打开 100 个计划，遇到上限明确停止，不自动清理文件。

共享发布器继续保留事务、页面证据和最后提交的清单；恢复缺失文件之前核对所有已写内容。保存已完成但索引失败时，界面明确显示“PDF 原文已保存，登记未完成”，允许重试或重载续办。完成回执失败同样可从原记录恢复；遇到损坏的记录不原地修复。关闭处于最终提交中的窗口仍允许事务收束，不把已保存文件撤回或重复复制。

内存测试使用模拟查询、PDF 解析及栅格；界面测试使用小型 DOM 替身验证迟到响应、图片解码门槛、换页失效、图片失败和登记错误文案，不把它们计作真实渲染证据。

实际渲染在 Windows、Obsidian `1.13.7`、`paper-test` 的 `0.63.0` 插件中完成。Browser 插件不可用，项目也没有已配置的 Playwright；沿用 Obsidian CLI 的原生 DOM、截图及调试接口，没有安装依赖。测试桌面窗口截图为 2561×1529 像素，另将弹窗收窄至 390 CSS px，内容区 345 px，无横向溢出。页面非空、目标库与版本正确，没有错误覆盖层，调试器未捕获运行错误。

真实流程使用测试库的 21 页 DESeq2 PDF，实时查询其 DOI，实际 PDF.js 解析并渲染标题页，页面标题、作者与 DOI 一致。系统文件选择窗口的返回值由自动化注入；其余文件读取、页面显示、按钮点击、发布、索引和库中打开均使用实际实现。确认按钮由开发验收自动化点击，不代表用户独立人工审阅或论文科学质量审阅。

验证包括：首次保存前无记录；显式确认创建原文包；模拟索引失败后保留原文和待继续记录；重载后按相同快照补齐登记；错误文件重选被拒绝；改名的相同内容文件可以继续；文件选择取消和忽略取消的迟到查询回复不产生预览或新记录；再次登记失败可重试；文献库准确定位后可实际打开该 PDF。存储中断、设备不匹配等其余故障以服务回归覆盖，未在真实磁盘上制造断电或损坏。

本轮原生脚本和截图保留在 `E:\research-reader\r2-local-pdf-ui-20260911`。首次执行器把预期失败文案中的 `Error:` 误判为脚本异常，修正为只检测顶层异常后继续，原始结果保留；通用零写入检查也按预期报告新增包与索引变化，随后按明确的预期写入清单检查。最终结果：测试库原有 915 个受保护文件中 914 个哈希不变，仅 `papers/index.md` 精确追加已确认的登记；新增 6 个原文包文件和 4 个操作／事务文件。原包与人工笔记不变，原有 13 个标签页恢复，测试插件三个部署文件与构建结果一致。

## 后续开发

R2 仍需统一添加入口，并把已查询身份接入获取全文、补充本地版本、打开已有来源及后续转换／笔记动作。查无结果的未核验手工记录、跨设备真实同步、大型或异常 PDF 的广泛兼容尚未完成。跨阶段待处理中心继续属于 R3。

这是软件实现与工程验证，来源保存保持 `metadata-only`，没有进行论文全文深读或生成科学结论。正式知识库、Wiki、科研索引与研究日志未更新；仅测试库原文索引因验收保存而追加。无模型调用，无需新的用户确认。
