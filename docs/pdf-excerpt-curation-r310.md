# R3.10：PDF 摘录补充到已有笔记

更新日期：2026-09-12。开发版本：`0.78.0`。

## 使用流程

从“摘录”选择已保存的 PDF 原句，点击“补充到已有笔记”。选择完整目标路径、插入段落并明确勾选原句；个人备注默认不选。预览列出目标笔记、相关索引和日志的修改前后内容，确认后保存修订。该流程不调用模型。

关闭预览保留整理批次，可从知识整理重新打开；重新打开仍须勾选和预览。来源、摘录整份文档或目标变化时，旧操作停止。已写入部分文件的修订保留为待恢复，重新加载后逐文件核对并续写；不会再次追加同一段原句。已完成修订可以预览撤销，目标有后续人工编辑时拒绝覆盖。

摘录详情新增 PDF 整理历史：精确关联批次、补充和撤销记录，展示当时修改，支持打开当前目标。手动“整理完成”继续表示用户工作状态，不因一次补充自动完成摘录或核验科学结论。

## 来源与目标约定

| 来源 | 可补充的目标 | 核对内容 |
|---|---|---|
| 未登记 PDF，例如旧提取包中的独立 `source.pdf` | 已有概念、方法和综合笔记 | PDF 字节与大小、页码与总页数、页内原始文字项、准确位置、整份摘录快照 |
| 已登记 PDF 原文包 | 上述笔记，以及明确关联同一 PDF 的论文来源笔记 | 上述核对，加上原文包清单、全部资产、保存事务、身份与版本凭据 |

论文来源笔记必须具有一致标题和明确的 `source_path`、`pdf`、`source_pdf` 或 `pdf_path`；多个已填写路径须全部一致。已有 DOI／PMID／PMCID、引用键和来源版本凭据不得冲突；不接受混有 JATS 或文章投影凭据的目标。仅标题或 DOI 相同不足以指定 PDF 版本。`metadata-only` 来源笔记仍禁止补写正文，原 YAML、标题和阅读深度不变。

位于受管理包的 PDF 不因清单缺失、损坏或资产变化而退回独立文件。独立 PDF 在核对期间变成受管理来源也会停止原批次。正式磁盘读取使用既有 `FileSourceStorage` 路径与文件替换检查。

引用以文字记录呈现，包含文件页码／总页数、页内 UTF-16 字符位置、SHA-256 和摘录路径。路径使用非链接代码文本，不在原文根与 Wiki 根之间新建链接。已登记来源另附原文包及版本；未登记来源明确说明身份尚未关联。原句按字面转义，个人备注使用独立标签，不生成论文结论或声称完成图表核验。

## 实现与兼容

新增 `src/curation/pdf-excerpt.ts` 负责 PDF 来源校验与目标身份判断；既有摘录上下文增加可选 PDF 凭据和 `sourceMode: pdf`，使用独立规则版本 `pdf-excerpt-curation-v1`。旧 Markdown 整理键与格式保持可读，不迁移旧文件。

`src/curation/excerpt.ts` 负责固定引用、准备和重复核对；服务与写入器沿用原批次和修订存储。预览及写入的 PDF 验证接收取消信号，来源 PDF 或已登记包的变化通知会提示重新检查。恢复重新核对来源，历史撤销只核对需还原的文件，PDF 后来缺失也不妨碍查看历史或撤销未被后续编辑的目标。

`src/annotations/excerpt-browser.ts` 和 `src/views/excerpt-curation.ts` 开放入口、PDF 页码上下文与整理历史。没有新增模型后端、学习会话或文件写入根。
