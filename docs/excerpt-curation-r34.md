# R3.4：摘录补充到已有笔记

2026-09-12，开发版本 `0.72.0`。从一条已保存的 Markdown 摘录开始，明确选择已有笔记和插入位置，预览后确认补充；使用现有整理服务和修订写入器，不调用模型。R3 尚未整体收尾。

## 使用流程

1. 在“文献库 → 摘录”选择记录，点击“补充到已有笔记”。未保存的备注需先保存或放弃。
2. 按完整路径搜索并选择已有来源、概念、方法或综合笔记，选择在哪个正文段落后补充。原句、保存时的上下文和个人备注都可查看。
3. 明确勾选本条摘录；个人备注默认不选，用户可以另外勾选。点击“预览选中补充”，查看目标笔记、需要补充的索引入口及日志的变化和完整前后文件。
4. 点击“确认补充到笔记”。成功后可打开目标或查看准确修订；若中断，从知识整理的修订记录预览并恢复。撤销同样先预览，已有后续编辑时拒绝覆盖。

预览会保存可恢复的整理批次，尚不改写目标正文。关闭后可从知识整理返回该批次；再次打开仍需明确勾选。已应用批次直接引导查看修订历史，需复查批次引导回到当前摘录重新准备。

## 来源与写入契约

- 新增独立的摘录输入适配，不创建阅读会话。整理记录使用 `excerpt-curation-v1` 规则，固定摘录完整文件摘要、原句、个人备注、来源快照、目标全文及插入段落。模型生成接口拒绝这类输入；旧阅读会话的模型建议流程保持原规则。
- 原句和个人备注采用固定格式分区呈现。Markdown 控制符按字面转义，保留文字，不让原句或备注中的链接、标题、脚本或控制标记变成新的笔记结构。个人备注标明为用户记录，不冒充论文证据；剪藏原句标明外部资料。
- 补充只追加在选定正文段落后，保留原属性、标题、其他正文和链接，不创建新知识页、不替换已有段落、不升级阅读深度。来源位置、UTF-16 字符范围、Markdown 文本摘要和摘录路径随正文保存；原文路径使用不可点击的代码文本，不建立原文包与 Wiki 之间的链接。
- 摘录沿用 R3.2 的严格单记录读取与 128 KiB 上限，原文读取不超过 32 MiB；目标准备限制为 160000 字符并检查文件大小。原文完整文本、选区、上下文及确定性 ID 必须一致，摘录文档有其他编辑也会使旧预览失效。
- `Clippings/` 与 `papers/` 下单层普通 Markdown 核对文本版本。`papers/<key>/article.md` 必须通过现有 MinerU 或 JATS 阅读器的完整包验证；其他包内 Markdown 不降级为普通文本。包内图片的完整性核验不等于视觉解释，本流程不声称检查科学图表。
- 论文来源笔记要求明确的来源路径或已核验包的对应笔记，标识冲突不能被路径匹配覆盖；JATS 复用既有论文和版本一致性检查。只有元数据的来源笔记不可补写，剪藏不能直接补写论文来源笔记。概念、方法和综合笔记仍由用户判断内容相关性，软件不会自动证明科学支持关系。
- 复用 `CurationService` 的保存、串行操作、变化检查与历史读取，以及 `CurationWriter` 的逐文件预览、写前凭据、恢复日志和撤销。应用前重建预览；每个写入步骤重新检查摘录、来源和目标，在 `Vault.process` 回调内比较待更新文件并核对文件对象。来源或目标中途变化会停止剩余写入，已写内容保留修订凭据，不覆盖恢复。
- 取消或关闭会中止后续操作；若已经进入写入，不能保证零写入，应从修订记录核对。多文件写入使用可恢复日志，不是跨文件或跨设备的原子事务。恢复只接受原快照或本次准确结果，撤销保留后续手工修改的保护，原有索引入口不撤回。
- 相同预览的重复确认复用修订；目标已经包含本条摘录的标准来源记录时，不再自动追加。没有对自由改写的旧正文做语义去重。原始摘录与归档状态保持不变，向一个目标补充成功不等于整条摘录的整理工作已结束。
