## 文件与调用边界

初次保护断言要求全部 897 个文件不变，结果未通过：实际进入两份 PDF 历史会话导致两个会话 JSON 更新；恢复原布局时重新选中的文章会话随后也保存了最近打开时间。最终没有新增文件，其余 894 个受保护文件哈希一致，原有 13 个标签页 ID 和类型恢复，三个部署文件与构建结果一致。

代码检查定位到阅读器 `selectSession` 保存 `lastOpenedAt`，仓库事务同时保存 `updatedAt`。补做逐文件前后快照的重复打开检查，三份会话均只变化这两个时间字段，原文引用和回答内容不变。首次运行仅保存了完整文件哈希，不能据此精确重建首次变动的全部字段，因此保留首次失败报告，没有伪造“897 文件不变”或猜测旧时间回写。

文献库浏览仍是只读。明确进入阅读会话后沿用既有最近使用与界面持久化行为；这与“切换页面不调用模型”分别检查。主原生场景记录模型／供应商调用为零，控制台捕获期无错误。未修改正式知识库的论文、笔记、索引或日志，不涉及论文科学审阅或证据深度升级。

## 可复查入口与性能

`pnpm test:r1` 运行显式白名单中的 12 组测试：文献投影、读取、旧格式兼容、浏览、阅读状态、主要笔记、代码关联、首页工作台、操作兼容、整理摘要、阅读域及入口。样本位于内存或保留的隔离目录，无批量删除、网络或模型请求。

本轮同时通过 `pnpm typecheck`、`pnpm build`、`pnpm release:check`（28 项）。`node --expose-gc tests/benchmark_library.js 1000` 使用 1000 组合成资料，产生 4003 个对象和 3002 行；四次读取耗时 114／93／91／88 ms，每次读取 4022 个文件。真实测试库一次扫描约 605 ms。这些是本机单次观测：合成内存测试不代表磁盘冷缓存，当前仍为完整重扫，不能据此承诺大型真实库性能。
