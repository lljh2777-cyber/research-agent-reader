# R0 第七批：真实模型答题与可追溯复核材料

实施日期：2026-09-11。插件运行版本保持 `0.52.2`。本批增加开发用的离线准备、显式答题和报告工具，不修改阅读界面、导读规则或正式存储流程。

承接[固定质量样本](reading-quality-baseline-r0.md)和[JATS 公式修复](jats-formulas-r0.md)。固定输入仍使用历史 `rar-jats-2` 证据，不能将本轮结果写成 `rar-jats-3` 或连续导读的质量评估。参考要点与科学答案均待独立人工复核，R0 尚未整体验收。

## 执行与数据边界

1. `prepare-reading-quality.cjs` 只读核验全部 27 个固定文件、18 题及其证据位置；模型输入与已有冻结输入逐字一致，不包含参考要点或禁止越界项。
2. `prepare-reading-quality-images.py` 使用已安装的 PyMuPDF `1.27.2.3` 解码原图，并将要求的 PDF 整页以 180 dpi 转为 PNG。6 道图像题涉及 5 个不同视图，保存原文和图像字节摘要、尺寸、转换参数。原图直接保留原始字节，不进行内容编辑。工具不会安装依赖。
3. `reading-quality-runner.cjs` 在 Obsidian 中显式选择已验证的 OpenAI-compatible 配置，复用现有适配器和 SecretStorage。每题使用独立上下文和一次非流式请求，无网页搜索、自动重试、模型自评或答案修复调用。
4. 每题先检查图片，再保存原始输入和开始记录；请求通过契约检查并写盘后才交给传输层。保留实际请求正文和成功响应正文的字节摘要，不保存授权头或读取、导出凭据。第三方返回内容可能包含其推理字段，原始响应留作本机诊断，报告只显示回答正文。
5. 失败、取消、空回答、截断或拒答会停止后续题目。输出以独占创建方式保存；已有目录不能直接重跑。中断后先核对已有回执，已经提交但没有完成记录的题目按服务端结果未知处理，不自动重投。
6. 原始材料、运行目录和报告位于仓库与 Obsidian Vault 外。界面不会创建测试阅读会话或论文笔记，正式聚合列表不会包含本次答题记录。

这是一套**已提供证据的固定问答测试**，不覆盖来源检索召回、自动选证、完整论文阅读、连续教学、知识整理和 R1 的界面交互。

## 复现方式

在项目根目录执行准备命令；父目录须已存在，输出目录必须是新名字。

```powershell
node scripts/prepare-reading-quality.cjs E:/research-reader/quality-baseline-20260911/sources E:/research-reader/quality-baseline-20260911/qa-plan-new
pnpm test:quality-runner
```

Windows 默认 Python 为 `D:/python/python.exe`，Linux 为 `python3`；可通过第三个参数明确指定解释器。精确 PyMuPDF 版本用于固定页面渲染，版本不符会停止。

准备完成后，在目标 Obsidian 的开发控制台执行以下代码。替换路径、准备工具输出的 `planHash` 和自己已验证的配置 ID。密钥不出现在代码里。`require` 只加载纯 Node 运行器，离线准备器依赖 esbuild，不应在 Obsidian 中运行。

```javascript
const qa = require('E:/research-reader/research-agent-reader/scripts/reading-quality-runner.cjs');
qa.startInObsidian(app, {
  planDirectory: 'E:/research-reader/quality-baseline-20260911/qa-plan-new',
  planHash: '替换为准备命令输出的完整摘要',
  outputDirectory: 'E:/research-reader/quality-baseline-20260911/qa-run-new',
  profileId: '替换为已验证的配置 ID',
  questionIds: ['D04', 'S02', 'C04'],
  maxTokens: 2200
});
```

调用立即返回，题目在后台串行执行。`qa.status(运行目录)` 查询状态，`qa.cancel(运行目录)` 取消当前请求并停止后续题目。脚本只接受 HTTPS 或明确的本机回环 HTTP 地址，每题客户端超时 120 秒，单次最多选择 18 题，输出请求值限定在 128–4096 token。服务端及中间代理如何执行上限须单独核实，这些值不构成费用承诺。

每次选择题号均是新的显式执行。先检查已有目录里的 `manifest.json`、`started.json`、`request.json`、`response.txt`、`result.json` 和 `summary.json`；不得为了取得完整结果而盲目重复已提交题目。运行期间不要卸载插件、刷新 Obsidian 或重新加载脚本模块。

导出报告不调用模型：

```powershell
node scripts/report-reading-quality.cjs E:/research-reader/quality-baseline-20260911/qa-run-new E:/research-reader/quality-baseline-20260911/qa-review-new.md E:/research-reader/quality-baseline-20260911/qa-plan-new
```

报告先核验保存的请求、响应与图像摘要，正文包含固定问题、首次回答、对应原文片段、引用格式观察及人工复核空栏。图像从**实际请求正文**恢复到同名 `-assets` 目录并嵌入报告，不用计划中的图像描述冒充提交凭据。模型文字和原文片段放在动态长度代码围栏中，避免其中的 Markdown 被误当作报告结构。请将报告与其图像目录一并保留；原始运行记录另行保留。

## 复核重点与验收边界

试题初读已发现需要人工裁定的候选问题，首次回答保持原样：

- `D03` 前段正确引用重复数 `≤2` 时不参与离群值检测，后段却改写为 `<2`，并将 `2` 放入下一分组；回答内部的边界条件不一致。复核应逐段检查，不能只看开头正确列出的阈值。
- `D04` 末段把不收缩的单侧高离散度异常条件，归纳为仅在曲线周围两个标准差内且信息充分时才收缩；应核对 `D04-E1/E2` 中收缩强度与高于曲线的例外，避免前文正确、末段引入额外条件。
- `D05` 根据选定页面回答排序重叠率后，使用“原文通篇未提及”描述整篇论文的准确率与 FDR 内容；本题提供的证据不足以支持这种全文范围的否定。
- `S02` 在正确区分每核 RAM 后，进一步给出乘以核数的总内存估算及对展示目的的解释；固定图注未提供进程峰值的测量与并发假设，不能把示意估算当作作者实测结论。
- `C04` 保留了表格和正文的 OR 差异，同时猜测差异可能来自四舍五入；已有证据没有独立回归输出，原因只能保留为未核实推测。

以上是开发过程中依据选定原文和图像记录的复核线索，不是独立审阅结果，不给出通过率，也不针对本批回答临时修改冻结指令。后续由独立复核者分别裁定原文支持、数字单位、适用条件与否定、图表解释、越界推断及未回答问题，记录审阅者、日期与证据依据。完成审阅后再决定是否需要修正规则，并使用另一个明确标记的运行版本作对照。
