# Agent 辅助适配验收（0.36.0）

本轮范围为工具纠错、共享失败限制和阅读操作结果跟踪；全局连续对话仍是后续方向。

## 工具与执行基础

- 证据读取返回可复制的参数；非法编号、错误整理目标和错误主线起点返回结构化纠错提示。
- 文献入库和阅读助手共用失败请求计数；同一参数交换字段顺序也只能失败两次，成功后清除对应计数。
- 不增加自动付费的格式修复请求；原有预算、取消和校验继续生效。

## 操作结果

- 主线节点、整理批次和导出文件在模型调用或笔记写入前完成关联保存。
- 主线推进同时检查原起点，防止交接期间主线变化后推进错误位置。
- 助手卡从实际业务记录读取状态，区分生成、审阅、写入、失败、停止、撤销和文件变动。旧卡无关联时不推断完成。
- 未执行的预览可以重新打开；旧预览不能通过迟到回调覆盖新预览或继续写入。已关联的卡进入对应结果，重试沿用原功能。
- 业务与助手状态分开；不因整理建议生成成功就声称正式笔记已更新。

## 自动化覆盖

`pnpm test:assistant` 使用四组内存测试，覆盖工具边界、Schema、两类 Agent 的失败限制、执行关联、错误重试、来源变化、撤销、重载和迟到回调。

阅读回归增加主线起点竞争与关联保存失败，导出回归核对写入前关联及重复文件复用，整理回归核对生成前关联、缓存复用和关联失败不调用模型。其余阅读、整理、检索和 Provider 回归沿用安全入口。

旧 `test_agent_loop.js` 含递归清理，未执行；以 `test_agent_feedback.js` 的内存测试覆盖此次入库循环改动。没有运行旧完整测试入口、安装依赖或删除文件。

这些测试验证流程正确性，不能直接换算为模型任务成功率。真实 API 样本与桌面交互结果另行记录。

桌面验收补查失败恢复时，补齐了导出失败后的预览重试，以及从助手重新打开整理记录后继续跟踪新批次。重试导出前先核对原文件是否已实际写成；写入仍在运行时不能重试，旧回调不能覆盖新尝试。

真实整理请求首次被引用结构校验拒绝，失败状态正确同步，未写入正式笔记。进一步把整理 Schema 中的证据、原句和段落限定为本批的实际编号，并保持证据与原句的配对关系；旧式逐字引用兼容保留。格式开销纳入 18,000 token 的文字输入估算，具体引用错误分别报告。原生 Schema 仅在已验证接口启用，其他接口仍由本地校验兜底。

桌面窗口在 460 × 440 CSS 像素下输入和按钮可见、正文可滚动；普通尺寸下操作卡和刷新入口可用。既有六条助手记录成功恢复，旧卡继续明确显示只有交接状态。导出预览未保存新笔记；正式笔记未应用修改。

整理在增加本批编号约束后，从原失败卡手动重试成功。卡片关联到新批次并显示四项待审阅；两项通过可应用校验，另两项仍因数值或图表依据不足被阻止应用。首次失败和新批次均保留。该重试接口报告输入 14,809 / 输出 4,369 token；首次失败为输入 13,469 / 输出 5,103 token。没有自动付费修复、采纳或修改正式笔记。

主线卡实际推进成功，主线从三个节点增加到四个，新节点内容保存后卡片自动转为已完成；重复点击被拒绝，没有再增加节点。最终重载恢复十一条助手记录，导出待操作、整理待审阅和主线完成状态均正确，零恢复错误，Obsidian 未捕获运行错误。
