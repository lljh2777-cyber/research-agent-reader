# 本机 CLI 批注

更新：2026-10-13。当前版本 `0.88.0`，批注支持 CodeBuddy 的 Step-5-Preview、Qoder CLI CN 的 Qwen3.8-Flash，以及 OpenCode 的 Step-5-Preview 和 mimo-v2.6-flash。

本轮候选由用户提供：CodeBuddy 的 Step-5-Preview、Qoder CLI CN 的 Qwen3.8-Flash，以及 OpenCode 的 Step-5-Preview 和 mimo-v2.6-flash。免费权益以用户当前账号为依据，插件不据此承诺永久免费。

## 共用调用层

插件内的 `CliTextService` 接收准确模型 ID、批注指令和已准备的上下文，由适配器选择 UTF-8 标准输入或显式查询参数传递正文。已知 npm 启动器解析到包声明的 Node.js 入口；原生程序直接执行，参数不交给命令 Shell 解释。每个请求使用独立会话，在新的空工作目录中运行，不以原文目录作为工作目录。

复用既有进程树控制，支持超时、取消和关闭时等待完整进程退出。插件不删除临时工作目录。完成结果由后端适配器解析，失败、超时、取消、无效结果和空解释均拒绝交付。

类型检查、生产构建与共用层定向回归通过；真实 Node 子进程验证中文、多行和命令字符的标准输入传递，无模型请求。新增三平台 CI 覆盖开发分支和版本标签。此步只交付底层，CodeBuddy、Qoder 和新 OpenCode 模型的界面及真实批注验收留待后续步骤。

## CodeBuddy

在「设置 → Research Agent Reader → 批注 AI」选择 CodeBuddy，核对程序路径并选择 Step-5-Preview。实际参数为 `--model step-5-preview`，界面名称与调用 ID 分开。其他模型可填写准确 ID，更改只影响批注；沿用本机登录，插件不导出登录凭据、不自动安装或升级程序。

每次使用打印模式及流式 JSON，限制工具和 MCP，禁用 Hooks、后台任务、会话持久化与自动升级。当前 CodeBuddy 会向空自定义 Agent 注入工作流工具，因此还明确拒绝这些工具，并核对返回的工具列表；新版本若暴露未知工具会拒绝交付。当前只提供文字解释，已有浅层联网开关必须关闭。

输出必须有唯一成功完成记录；工具调用、截断或与所选模型不符的记录不能保存。批注保留请求模型和实际报告模型，用量与费用仅记录 CLI 提供的字段，缺失保持未知。中文缺少对应英文依据时在后端调用前停止。

Windows 启动描述写入私有临时工作目录，由进程树控制器读取，避免编码长参数超过系统启动限制；文档正文继续通过标准输入传递。临时描述和目录保留，不批量清理。原文目录不作为 CLI 工作目录。

## 验收与失败记录

类型检查、生产构建、共用层和 CodeBuddy 定向测试，以及既有批注、来源完整性、联网、双语和设置回归通过。真实 Node 子进程验证中文输入及 Windows 长参数；模拟进程覆盖取消、关闭、失败、空结果、截断和模型冲突。

Windows / Obsidian `1.14.4` 测试库通过原生设置和批注控件的 DOM 事件核对入口与模型选择。首次设置检查发现选项误加到任务默认策略，未调用模型，修正后复验。随后两次真实请求因工具列表未完全关闭而拒绝保存；补上工作流工具拒绝规则。Windows 长参数失败发生在模型请求前，新增回归后复验。测试驱动还修正了错误等待与“保留”按钮选择器，已生成回答复用保存，没有为驱动问题重新调用模型。

首次请求没有保留原始进程流，不能补报其精确用量；其余进程记录与失败材料保存在私有测试目录。当前固定样本只能检验工程通路及有限语义，不能代替独立科学／教学审阅；模型把高低比较扩写为随表达升高的连续趋势，仍须人工复核。

最终请求确认 `step-5-preview` 和空工具列表；原生“保留”保存后，批注正文、请求模型、报告模型与用量记录读回一致，源文件不变。后端选择和批注经插件重载恢复，原工作区保持，原设置恢复。此轮共三次真实生成尝试：前两次被工具面核对拦下，最后一次通过；另有一次启动长度失败未发起模型请求。最终 CLI 报告输入 3146、输出 603 token，费用字段为 0；记录各字段原值，不推定全部尝试的总费用。测试库保留合成原文及一份批注。

未进行完整宿主重启、macOS／Linux 原生桌面或独立科学／教学审阅。本地旧全量入口含批量清理而未运行，公开完整检查由三平台 CI 和标签工作流执行；私有 MinerU 夹具未配置。

## Qoder CLI CN

`0.87.0` 使用本机 `qoderclicn`，每次明确传入 `--model Qwen3.8-Flash`。该名称来自已安装 CLI `1.1.69` 的模型列表；不会用 `Auto` 或同名 BYOK 自定义记录替代。支持自动检测 `.qoder-cn` 的原生安装位置与手动路径，沿用已有登录。

使用 `-p` 和流式 JSON，关闭工具、MCP、Hooks 与会话持久化，自动模型重试为 0。本机版本没有 `--max-turns` 参数，因此不传。正文作为 `--` 后的查询参数传入，标准输入关闭；Windows 启动描述会保留本次提示词及上下文，应视为私有文件。参数长度超过 Windows 上限时在启动前停止。

从初始化和回答中核对报告模型，若报告冲突则拒绝保存；缺少报告时明确显示实际模型未知。费用汇总中的 `qfmodel` 是供应商记账键，不作为模型名称；不会用它推定实际模型。当前 CLI 报告 token 全为 0，费用为 0，插件按原值记录，这不能证明实际没有消耗 token 或保证永久免费。

原生测试库先后有两次标准输入尝试在 120 秒超时，均停止进程、没有保存。改为显式参数后首次成功返回，初始化与回答均报告 `Qwen3.8-Flash`，工具列表为空；最初因费用键被误当模型而拦下。修正后回放同一进程输出，原生“保留”完成保存、正文与来源回读、设置与批注重载恢复、源文件不变及原布局保持，没有追加模型请求。固定样本保持“相关不能证明因果”，但末段的学科背景没有明确标为一般知识，仍待独立审阅。

类型检查、构建、共用层、CodeBuddy、Qoder、来源完整性、联网、双语与设置定向回归通过。失败日志与原始输出私有保留；前两次超时的实际用量未知，不能把最终费用 0 当作所有尝试的总费用。

## OpenCode

`0.88.0` 在已有 OpenCode 批注入口增加两个候选，完整调用 ID 分别为 `opencode/step-5-preview-free` 与 `opencode/mimo-v2.6-flash-free`，取自本机 `1.19.0` 模型目录。官方配置且关闭浅层联网时使用共用文字调用层；联网与 CC Switch 保留已有执行方式。新设置的批注默认选择 Step-5-Preview，已有选择和空值保留，空值沿用 OpenCode 页保存的准确 ID；没有失败后自动换模型。当前文字调用使用模型默认推理参数，不传旧 Agent 路径保存的 variant。

通过 `run --pure --format json --model <完整 ID>` 执行独立会话。每次正文作为 `--` 后的查询参数传入，未用的标准输入直接连接系统空设备；关闭管道仍可能使 Windows／Bun 等待输入。Windows 私有启动描述因此会保留上下文。Scoop 启动器仅在目标属于该应用安装目录时解析为原生程序；无法确认则停止并要求指定原生路径。

为官方文字批注使用隔离配置缓存，沿用原认证数据并关闭项目配置加载。配置缓存按宿主进程复用，避免每次重复准备 SDK，工作目录和会话仍各自独立。提供空 MCP 配置，关闭外部插件、默认插件、自动升级、自动共享和旧数据裁剪。OpenCode 本身仍会保存会话，并可能在私有配置目录准备自身插件 SDK 依赖；插件不删除会话、临时目录或依赖文件。

本机试验中，移除全部工具会收到免费层 403。[上游问题记录](https://github.com/anomalyco/opencode/issues/50627)也报告了相同现象，但这不是服务端行为的独立证明。采用官方权限配置 `ask`，保持正常 CLI 工具声明；不设置 `--auto`，非交互模式[自动拒绝权限请求](https://github.com/anomalyco/opencode/blob/v1.19.0/packages/opencode/src/cli/cmd/run.ts#L755)，不修改认证或伪造服务标识。插件另拒绝含工具事件的输出，只交付唯一 `stop` 完成记录的纯文字；这与 CodeBuddy／Qoder 的空工具列表不同。

OpenCode 的 JSON 事件不携带实际模型名称。批注保存准确请求 ID，用“CLI 未报告实际模型”显示这一缺口，不把请求 ID 当作返回模型。验收可额外读取本机会话的模型字段，不增加模型请求。CLI 报告的 token 与费用按原值保存，缺失不补为 0。CLI 的官方参数与配置依据见[命令文档](https://opencode.ai/docs/cli/)和[配置文档](https://opencode.ai/docs/config/)。

原生测试库此前有六轮超时，没有保存批注；曾尝试管道输入、显式查询及配置缓存，最终用系统空设备解决未用输入的等待。另有免费层 403、上游 `Invalid credential` 401 和一次 `read` 工具请求；CLI 自动拒绝后者的权限，插件拦下其输出，没有保存。初次 mimo 回答带最大步骤流程报告，界面驱动对 Markdown 字符的检查也失败；将步骤上限改为 2，首轮不再注入上限报告，并修正显示检查。后续回答仍补充过多未标记背景，遂加强原文／一般知识标识和“不追加读取”的指令。所有失败材料与原始进程流私有保留，没有清理或改写来掩盖失败。

本轮 OpenCode 共十三轮界面调用流程：六轮超时、一轮 403、一轮 401、一轮被拒工具请求、四份文字回答。早期有两份 mimo 回答用于发现流程报告与背景标识问题；最终 mimo 和 Step 各一份回答完成原生“保留”保存、正文和用量回读、源文件不变、模型选择与批注重载恢复，原设置和工作区恢复。额外 `export` 读取本机会话，分别确认 `opencode/mimo-v2.6-flash-free` 与 `opencode/step-5-preview-free` 的 `stop` 完成记录，没有追加模型请求。

最终 Step 原始记录报告输入 6431、输出 210、推理 379、缓存读写 0；mimo 报告输入 3817、输出 177、推理 20、缓存读取 2560、写入 0，费用字段均为 0。批注侧保存输入／输出、缓存和费用字段，其他字段在原始进程流保留。失败尝试的实际用量未知，不汇总为全部免费。最终回答分开标明原文依据与一般知识，但 Step 仍把较高表达的组间比较扩写为连续趋势，并对观察性研究的时序限制过度概括；mimo 的一般背景也引入了原文未说明的随访情境。未作独立科学审阅或人工改写生成内容。

类型检查、生产构建、共用层、三个 CLI 适配器、既有批注、来源完整性、联网、双语、设置、供应商及公共运行边界的定向回归通过。新增实际子进程空设备 EOF 与 Scoop 解析回归，保留取消、退出和 Windows 长参数覆盖。没有重做完整宿主重启、最终构建在新宿主进程中的冷缓存生成、其他平台原生桌面或真实联网／CC Switch 生成；后两者通过保留原执行路径的回归。独立翻译／科学／教学审阅继续待完成。
