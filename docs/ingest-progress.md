# 文献入库阶段进度（0.43.2）

控制台在功能入口下方显示当前入库的阶段进度；点击任务记录，也能在结果窗口查看实时进度。首次入库和“继续完成入库”共用同一套事件和显示。

## 用户可见行为

- Direct API 依次显示：读取 PDF、核验与去重、确认身份、解析原文、整理笔记、保存结果。根据用户选择，省略未要求的原文解析或笔记阶段；已验证的既有输出可复用并跳过生成。
- 进度条表示已走过的阶段，当前阶段单独高亮；不推算时间、token、页数或百分比。只有任务完成状态保存结束后才显示满格。
- 等待人工核对时显示“等待你的确认”；可在原身份确认窗口完成核对后继续。
- MinerU 显示正在解析、校验并发布原文包，不编造服务未提供的页级进度。
- 面板及原文献入库入口均可停止任务。失败或中断保留最后所在阶段及原因，入口恢复可用。
- 控制台保留最近一条有进度记录的入库结果，支持直接查看结果。旧版无进度记录的历史任务不补造阶段。
- CLI 使用不确定进度条并展示已有状态回报。当前外部执行器没有统一的六阶段回执，因此不按 Direct API 的阶段计算完成度。

## 更新和保存

阶段信息由插件实际执行事件生成。阶段切换和等待状态变化时，通过串行保存队列保存任务快照；工具和模型中间步骤仅更新内存及进度区域，不重新扫描知识库，不增加模型调用。结束时最新阶段随任务结果及完成日志保存，重载时恢复；旧运行任务仍按已有机制标记为中断。

进度事件按任务 ID 隔离，结束后到达的迟到事件被忽略，同一任务的旧阶段不能覆盖新阶段。任务结果窗口在结束时同步更新标题、正文和可用操作，避免一直显示旧的“运行中”。

## 验证与边界

- 类型检查、生产构建、5 组入库回归、2 组控制台回归及 28 项发布审计通过。
- 内存回归覆盖阶段选择、等待、单调推进、终态、迟到事件、重载字段恢复、每阶段保存和中间步骤不额外保存，以及真实插件后端事件转发。
- 原生测试覆盖首次入库和续办的状态、进度、停止、错误、成功满格、实时结果窗口和 360/720 像素布局；使用模拟后端，不运行真实模型、PDF 处理或 MinerU。
- 已在 Obsidian 中检查进度面板截图，测试期间保持用户设置与任务历史不变。阶段进度不改变身份核验、去重和内容写入条件。
- 沿用禁止批量或递归删除的测试边界：未运行包含递归清理的 `test_agent_loop.js`、全量旧测试及任务历史批量回收测试。此次使用纯内存与模拟后端覆盖相关状态路径。
