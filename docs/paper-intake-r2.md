# R2 第四批：统一添加入口与确认身份衔接

2026-09-11，开发版 `0.64.0`，已部署测试库。文献库现在提供一个“添加文献”按钮，将书目查询、本地 PDF、在线全文和已有原文连接起来；公开 beta 仍为 `0.31.0`。

## 用户流程

1. 打开“文献库 → 添加文献”，或运行“添加文献”命令。没有文献标识时也可先进入“从本地 PDF 开始 / 恢复添加”，使用上批文件选择与恢复流程。
2. 输入 DOI、PMID、PMCID 或已支持链接，向 Europe PMC／Crossref 查询书目信息。查询本身不创建文献记录或获取任务。
3. 已有关联的完整 PDF／JATS 原文会列出来源和版本，可直接打开。打开前重新核验内容、清单和 paperId，不能用变更后的包替代预览时选中的来源。
4. 明确保存书目信息后，可在文献库查看，或选择“查找这篇文献的全文”“为这篇文献添加本地 PDF”。旧文献身份和人工决定复用，保存不生成 Wiki、推断译名或标记已读。
5. 本地分支锁定已确认文献，选择文件、声明版本并核对实际 PDF，沿用共用保存器。这个步骤不再次查询元数据；PDF 仍在本机读取，版本默认未核验。
6. 全文分支显示确认过的论文，锁定标识；用户继续选择 PDF／JATS、图片策略及稿件范围，再明确点击“查找全文”。打开窗口不自动查询候选或下载。候选、许可、部分结果和保存确认继续使用既有流程。

取消或失败不会撤回已经保存的书目记录。后续操作准备失败时留在原窗口并允许重试；进入后续窗口后按各自流程继续。旧“添加文献信息”“添加本地 PDF”“按标识获取论文全文”命令保留，没有改写已有历史入口或任务 ID。

## 服务与记录约定

`MetadataIntakeService` 的预览补充已有来源摘要；身份与来源原始数据保留在私有预览表中。`context()` 返回前再次核对来源目录与持久 paperId，调用方修改界面对象不能改变确认身份。`source()` 对照本次预览中的包及新读取的清单；插件再通过文献库的实际打开守卫进入指定原文。

`LocalPdfIntakeService.prepareForPaper()` 接受确认身份和 paperId，不调用身份解析器。文件仍需完整读取、PDF 校验及页面确认；来源目录关联必须保持为该 paperId，否则在持久保存之前停止。首次从本地文件开始的旧查询路径不变。

`AcquisitionService.startConfirmed()` 采用经过验证的身份，并在新的获取日志中持久化可选 `confirmedIdentity`。身份必须包含请求标识，已解析身份也必须与它一致。重试、重载和 JATS 显式刷新沿用这份确认；普通独立全文查询仍按原流程解析身份。只有确认快照完全一致的任务才可用于该分支的活动去重或缓存复用，避免旧任务悄悄替换当前确认信息。明确关闭 Unpaywall 回退的请求不会在衔接时丢失该选择。

当前查询的确认快照可能比已保存书目记录更新；保存复用时保留旧记录，后续操作使用用户本次看到并确认的查询快照。它们不会因为查询时间不同而互相覆盖。旧获取日志没有 `confirmedIdentity` 时继续兼容读取，本批不迁移旧记录。

界面复用 `MetadataIntakeModal`，统一模式增加文件入口、已有来源及保存后动作；旧书目模式仍可独立使用。所有下一步按钮共享进行中状态，修改输入、取消和关闭使旧回调失效。原生验收发现复用延迟加载的文献阅读器时可能仍停在旧文档；现在先等待 `loadIfDeferred()`，再更换到目标原文。

自动测试采用内存存储与模拟传输，使用真实服务、来源关联、发布器和校验逻辑；PDF 解析／栅格使用替身。样本文件保留，不执行删除清理。

原生环境为 Windows、Obsidian `1.13.7`、`paper-test`，使用 `0.64.0` 构建。Browser 插件不可用，`pnpm exec playwright --version` 返回命令不存在，沿用已有 Obsidian CLI 原生接口，没有安装依赖。桌面截图 2561×1529 像素；390 CSS px 弹窗内容宽度 345 px，无横向溢出。页面身份和版本正确、内容非空、无错误覆盖层，调试器未捕获运行错误。

真实 DOI 查询完成后，已有本地 PDF 从新按钮实际打开；保存书目记录后进入本地 PDF 分支，真实读取已保存的 21 页 PDF 并识别可复用来源，没有额外身份查询，也没有重复保存文件。系统文件窗口的返回值仍由自动化注入。再次查询同一 DOI 保存复用已有记录，原记录没有新增修订。

全文分支沿用实际查询结果，真实 PMC 来源发现返回出版版候选；打开窗口时没有创建任务，明确点击查找后才持久化获取记录。首次查找和重载后的显式重试均未调用身份解析器，确认快照一致，没有自动下载。验收最后主动停止该任务，保留取消记录。PDF／JATS 的完整下载与保存衔接由模拟传输回归覆盖，本轮没有再次联网下载全文。

另用已查询／已保存的身份作为只读替身，验证网络失败提示、取消后的迟到响应、互斥按钮、保存后文献库定位、已有 JATS 实际打开和窄窗口。首次重载比较误用了前一次书目查询的时间戳，修正为实际传递的确认快照后通过，失败输出保留。首次 JATS 点击后仍停在旧文档的失败也保留；等待阅读器加载的修复后，从旧文档重载状态验证立即切换成功，并在恢复完成后仍保持目标 JATS 与可见正文。

脚本、原始结果、身份记录及截图保留于 `E:\research-reader\r2-unified-intake-20260911`。最终哈希检查：测试库原有 925 个受保护文件均不变，包括所有原文、索引、笔记和旧日志；新增 2 个书目记录文件，以及单个验收获取任务的 20 个追加日志／标记文件。每条新获取修订的确认身份一致，最终状态取消，未产生下载快照。原有 13 个标签页恢复，部署三个文件与构建结果一致。

## 后续边界

R2 尚未收尾。下一步从已有文献详情直接补充来源和继续处理，复用持久书目身份，减少重复进入查询窗口；再衔接转换、笔记和登记的独立续办。查无结果的未核验手工记录仍未开放。跨阶段待处理中心继续属于 R3。

此批是软件开发和工程验收，书目及原文身份仍为 `metadata-only`，没有形成论文科学结论或完成全文审阅。正式知识库、Wiki、科研索引和研究日志未更新；本轮测试原文索引同样未修改。无模型调用，没有待用户确认的操作。
