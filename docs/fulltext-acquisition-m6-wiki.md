# M6 第二步：JATS 初始文章 Wiki

实现版本：`0.50.0`，2026-09-10。本步骤将已保存的 JATS 原文接入初始文章草稿、完整预览、正式 Wiki 保存和现有入库登记。交互阅读已在 `0.49.0` 交付；JATS 阅读助手与既有笔记修订仍待适配。

## 使用流程

1. 在「获取全文」选择 JATS，核对主文章身份和缺口并保存原文包。
2. 在图文阅读器点击「文章 Wiki」，或在交互阅读中点击「生成文章 Wiki」。打开窗口只核对原文与重复项。
3. 选择已通过连接测试的 Direct API，填写可选关注问题，点击「生成新草稿」。选定原文片段会发送给该模型，不调用 MinerU。
4. 核对完整 Markdown、中文译名和「实际读取的原文片段」，点击「保存文章 Wiki」。本步骤只创建 `wiki/sources/<citekey>.md`，不覆盖已有笔记。
5. 点击「预览入库登记」，检查修改前后内容，再确认登记。独立 Vault 更新本库索引和日志，状态为 `indexed`；工具包正确绑定到当前 Vault 时可同步 CSV / BibTeX，状态为 `registered`。

已有 Wiki 时提供打开和登记入口。生成失败后可保留旧记录重新生成；关闭窗口不终止后台生成，也可显式停止。任务历史的「查看草稿／继续保存」可恢复草稿，没有模型配置也可完成已生成草稿的核对、保存和登记。

## 来源与证据边界

- 使用正式 JATS 包既有的 v2 人工结构化身份确认凭据；不伪造 PDF 栅格、页码或 Crossref v1 回执。
- `jats_read` 仅接受概览、目录和正文块参数，不能选择任意路径。必须成功读取概览，才能补读正文和提交草稿。
- 概览最多读取前四个摘要段落；没有摘要时使用正文开头。每段最多 4500 个 UTF-16 字符；概览明确说明只读取片段。单次工具输出不超过 23500 字符，本次草稿累计不超过 50000 字符、40 个实际片段。
- 工具调用前后验证完整来源包。草稿要求真实工具回执、实际观察到的片段以及匹配原文投影的证据编号；标题必须原样保留，`title_zh` 不得为空，主要正文小节必须带证据引用。
- 主程序生成 Markdown 和来源属性，模型不能指定文件路径或覆盖文件。属性包含来源清单、投影、XML、论文身份摘要、源版本及证据的块 ID、字符范围、XML 位置和文本摘要。
- 深度固定为 `abstract-level`。本步骤不读取图像，图注或表格文字不能代表图像或全文方法已核验；缺口保留在草稿中。引用校验只证明片段已读且没有被替换，不能自动证明科学推论或中文译名正确，用户仍需在预览中审校。
- `papers/` 与 `wiki/` 之间保持普通来源路径，不创建跨根 Markdown 链接或 wikilink。

## 状态和恢复

`src/jats/wiki-service.ts` 独立管理草稿，使用插件私有目录中的 `jats-wiki/<packageKey>/<requestId>/`。请求、草稿、写入意图、保存回执和失败记录分别保存，采用只创建新文件的方式；读取历史不会创建目录。

保存前重新生成并校验预览，重新检查来源、论文关联和已有 Wiki。正式文件创建前再次检查来源与重复项，创建后回读并验证来源。若笔记已创建但保存回执失败，重载后仅在笔记与原有写入意图完全一致时补齐回执；用户编辑过的内容不会被覆盖。已保存记录再次操作只核对笔记存在，不将历史草稿写回文件。

来源变化会阻止新生成、预览核对、保存或登记，私有历史文件仍然保留。登记沿用已有批次快照和内容比较机制，每次写入前重新验证 JATS 来源；部分失败可续办。恢复草稿、补齐保存回执和入库登记均不再次调用模型。

主要文件：`src/jats/wiki-evidence.ts`、`wiki-service.ts`、`wiki-modal.ts`、`wiki-source-guard.ts`。共享 Wiki 渲染与创建位于 `src/agent/tools.ts`，登记位于 `src/agent/ingest-registration.ts` 和 `src/views/ingest-registration.ts`。普通阅读器、交互阅读和任务历史提供入口。

## 验证结果

- `pnpm test:jats` 6 组通过。新测试覆盖实际工具循环、伪造回执和引用、标题与正文约束、并发生成、草稿重载、来源变化、保存前同名文件出现、用户编辑、保存回执中断、停止生成及登记失败续办。
- `test:ingest` 5 组、`test:reading` 22 组、`test:code-reading` 3 组、`test:sources` 3 组、`test:fulltext` 6 组、`test:dashboard` 2 组通过。
- `pnpm typecheck`、`pnpm build`、`pnpm release:check`（28 项）通过。
- 原生 `tests/obsidian-jats-wiki.cjs` 在 Obsidian 中通过 19 项检查：真实受限工具循环和读取回执、模型失败重试、生成中关闭重开、完整预览、360/680 像素窗口、任务历史、无模型恢复、保存回执失败续办、既有登记窗口和控制器，以及登记后用户编辑保护。
- 原生 `tests/obsidian-jats-reading.cjs` 回归通过 18 项，验证来源选择、真实图片解码、正文与图像引用、主线支线、会话恢复、导出和普通阅读器入口。
- 原生测试使用此前缓存的公开 PMC XML 与同版本资源；模型回答为明确标注的合成测试文本。模型、网络和 MinerU 的真实调用均为 0。原生测试的 Wiki、草稿、登记、索引与会话写入全部保存在内存；Wiki 创建边界和来源验证由对应 Node 模拟测试覆盖，JATS 包存储另有真实文件系统测试。
- 测试部署仅替换三个构建文件，并先备份。核对 155 个其他插件文件与 724 个文献文件，内容不变且没有新增用户数据文件；原架构建议文件保持原样。测试窗口关闭，原有工作区恢复，Obsidian 保持可见，未捕获运行错误。

没有运行含递归清理的全局测试入口。没有实测真实模型的科学内容质量，也没有新增真实论文笔记、科研结论、书目或索引。该开发步骤无需用户补充配置或批准。
