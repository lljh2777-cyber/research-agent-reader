# R3.13：学习摘录的人工修订历史

更新日期：2026-10-05。开发版本：`0.81.0`。

## 使用流程

在“学习回答摘录”中修改人工稿，预览并确认后保留版本。“人工修订历史”按新到旧展示起始快照、人工改写、清空和恢复记录；展开后可查看完整文本。历史是人工内容的记录，不代表科学或教学核验。

恢复时点击“载入版本 N 到修订框”，核对文本，再点击“预览人工修订 → 确认保存人工修订”。载入和预览均不写入文件。确认后追加一个新版本，记录恢复来源，保留其间版本。清空当前人工稿也留下历史；恢复到与当前相同的文本不增加重复版本。

修订框已有未保存内容时，历史载入会停止；未保存的个人备注可以保留。保存人工稿不覆盖备注，未保存输入仍阻止关闭或跳转。继续编辑载入的历史文本，按普通修订保存。重新读取或保存备注会使旧恢复预览和版本选择失效，当前输入仍可保留；需要明确记录恢复来源时，应重新选择历史版本。

## 存储与兼容

- 沿用 `wiki/qa/answer-excerpts/`，每份摘录在同一文件中保存历史及当前人工稿。原始 AI 快照、选区和个人备注保持各自的角色。
- v1/v2 摘录在浏览、预览和无变化保存时不迁移。首次实际修改人工稿升级为 v3，捕获当时仍存在的人工稿或空稿作为起始快照。此前已覆盖的文本无法重建。
- v3 的 `humanHistory` 追加 `baseline`、`edit` 或 `restore` 记录；恢复引用该历史中的较早版本。`humanRevision` 始终与最后一条历史一致，旧整理适配器仍读取当前内容。
- 校验版本顺序、时间、非空文本、恢复引用与当前稿一致性，拒绝损坏历史或被改写的可见正文。保存复用整文件版本检查和 `vault.process`，冲突、取消和写入失败保留已有内容；丢失成功响应时读取实际结果确认。
- 最多 64 个历史版本（含起始快照），每次人工稿不超过 20,000 字符，整个摘录仍不得超过 2 MiB。达到任一上限时拒绝新增修订，保留历史和输入；不自动压缩或裁剪。版本数上限下，备注、完成标记与无变化操作仍可用，文件大小约束始终适用。
- v3 需要本版本或兼容版本读取；旧插件不认识新格式，不能作为历史文件的编辑端。未升级文件保持旧格式。

## 与整理流程的联动

实际改写、清空或恢复后重新待整理；无变化保存保持完成标记。回答缺失或已变化时，待处理中心继续显示复查项，历史不丢失。

已有笔记补充仍固定整份摘录版本。即使修改后恢复成相同文字，旧预览也会失效，用户需重新准备整理。新知识页草稿保留保存时的固定材料，不因后续人工修订而改变；新起草和新页预览只展示明确选择的当前 AI、人工或备注角色，不把整段历史混入正文。学习内容仍排除本插件正式证据检索，没有新增模型请求。
