# R3.2：摘录列表、回到原文与个人备注编辑

2026-09-12，开发版本 `0.70.0`。本批补齐已保存 Markdown 摘录的查找、查看、准确定位和备注编辑。无需模型或网络，不修改原文包，也不新增持久数据目录。R3 整体继续开发。

## 使用流程

从“文献库 → 摘录”、命令“打开摘录（原句与个人备注）”，或已有摘录小窗的“查看摘录与编辑备注”进入。搜索原句、来源路径或个人备注，选择一条后查看原句、保存时的上下文及来源核对结果。

个人备注可以直接编辑。保存成功后更新列表；失败保留输入。若其他窗口或同步修改过摘录，保存会停止，点击“重新读取（保留草稿）”后，可同时看到最新已保存备注和自己的草稿，再决定保存或放弃。有草稿时不能切换记录或关闭窗口，需先保存或明确放弃；搜索不会清除当前草稿。插件卸载和宿主关闭会释放窗口，未保存草稿仍只存在于内存，尚无草稿持久恢复。

“回到原文”会打开对应 Markdown 编辑器并选中准确文字。来源改变或缺失时保留历史记录，停止自动定位；可以继续编辑这份历史摘录的个人备注。完整文件路径始终可见，不选择同名文件或另一个相似段落。“打开摘录文档”直接打开该摘录文件。

## 读取、编辑与定位契约

- 列表只读取 `wiki/annotations/ann-excerpt-<48 位摘要>.md` 中的 R3.1 独立摘录，每个文件必须只有一个合法记录。旧批注继续从原有批注入口或文献库查看。损坏、重复和超过上限的文件列出读取提示，不静默当作正常记录。
- 一次最多扫描 2000 个候选，每份文档最多 128 KiB，列表每页先展示 50 条。列表读取不核验全部来源；选中详情时才读取对应 Markdown，文本核对不等同于 PDF、资源包或科学结论核验。
- 编辑快照记录整个摘录文件的 SHA-256。保存在 `Vault.process` 回调内比较当前整份文件与目标路径，连附录等外部编辑也会触发冲突，文件移动或替换停止写入。只替换个人备注分区和既有更新时间，保留原句、上下文、来源位置、版本、AI 内容、归档字段、未知元数据和额外正文。
- 单次界面只执行一个操作，保存期间禁用重复提交。提交前取消不会写入；写入已完成但响应丢失时，只在文件与本次拟写结果完全一致时承认成功。提交后再被改动会提示重新核对，不宣称成功覆盖了后续编辑。
- 原文定位重新读取摘录与来源，校验全文本摘要、固定位置、原句和确定性 ID；打开编辑器后再核对来源、摘录和编辑器当前文本。编辑器存在不同内容时不设置选区。文件系统没有跨文件事务锁，核对完成后的新变化仍需要后续复查，不能保证跨设备同步原子性。
- Markdown 打开复用插件已有的自动阅读器绕过入口，避免 `file-open` 把编辑器切换成自定义阅读器。没有修改全局自动打开设置，也没有在原文与 Wiki 之间生成链接。
