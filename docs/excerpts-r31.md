# R3.1：无模型保存 Markdown 摘录

2026-09-12，开发版本 `0.69.0`。R3 首批接通独立的“保存摘录”，支持 `papers/` 和 `Clippings/` 下 Markdown 阅读界面的纯文本选区，包括现有正文阅读器。保存保留原句、上下文、章节、准确字符位置、文本版本与可选个人备注，不调用模型或修改原文。

## 使用流程

划选文字 → 点击“批注” → “保存摘录” → 核对原句并填写可选备注 → “确认保存摘录”。同一文本版本与位置的重复操作复用既有记录，不用当前输入覆盖已保存备注。保存后可以展开上下文或打开摘录文档；重新划选同一位置也能找回它。

首批个人备注直接在摘录文档的“手动批注”分区编辑，版本凭据与原文片段保持不变。摘录小窗不提供旧批注的 AI 重写或归档动作。原有手动批注、AI 解释和旧批注文件继续沿用既有流程，不批量升级或改写。

## 数据与来源契约

- 新摘录仍是 `wiki/annotations/` 下的既有批注块格式，新增可选 `excerpt` 凭据，不新建持久数据根。每份摘录独立创建文件，目标 ID 来自来源路径、文本版本和选区位置的确定性摘要。
- 文本版本算法标记为 `markdown-utf8-sha256`，对读取到的 Markdown 字符串按 UTF-8 编码计算 SHA-256；字符偏移使用 JavaScript UTF-16 索引，记录文本长度。这个值不冒充 PDF、MinerU 或 JATS 完整包的指纹。
- 选区沿用首版同段纯文本及 600 字符上限；上下文向前后各取最多 1300 字符，个人备注最多 10000 字符。保存时重新读取原文，要求版本、位置与文字一致；不自动迁移到另一个相似段落。
- 来源与原句为 `original_quote`，填写的备注为 `personal_note`；AI 字段初始为空，不从模板或备注推断模型内容。外部材料、AI 和综合判断的进一步分区与编辑属于后续步骤。
- Markdown 正文属性中的文件路径作为普通来源记录，原文与 Wiki 不互建链接。上下文在元数据中完整保留，正文使用转义的预格式文本显示，避免注释控制标记被误认成新批注或把上下文中的链接变成导航。
- 文献库先核对新摘录的文本版本和位置。本次读取过对应 Markdown 正文并且来源通过验证时，摘录可以归到该来源；对于 MinerU，仍需显式完整核验原文包。缺少可核对的文本或位置时保留历史待复查，文本变化同样提示“需复查”，不改变摘录。缺少固定版本的旧批注继续保持原有未核验状态，外部 schema-2 版本不重新解释。

保存采用单文件只创建、不覆盖。创建前复读来源；重复点击、并发创建或写入已完成但响应丢失时，读取目标文件并核对完整凭据，吻合才复用。损坏或冲突目标保留并报错。关闭小窗会取消尚未进入文件写入的操作，已提交的文件则保留供再次查找。文件系统不提供跨原文和摘录的事务锁；最后一次来源读取之后发生的变化由后续版本核对标记，不能声称永远不会遇到并发变化。
