# R0 第四批：旧资料兼容与读取性能基线

实施日期：2026-09-11，开发版本 `0.52.1`。承接[只读聚合](library-r0.md)与[人工记录](library-records-r0.md)，本批补齐旧 MinerU 按需完整核验、外部批注的只读适配和可重复的工程性能测量。本文记录第四批边界；后续样本准备见[第五批科学阅读质量基线](reading-quality-baseline-r0.md)。R0 未整体验收；文献详情及操作控件仍在 R1。

## 已实现的接口

插件接口为 `inspectPaperLibrary(signal?, verifyMineruPath?)`。省略第二个参数时沿用普通盘点；传入 `papers/<citekey>/article.md` 时，只对所选旧包调用与阅读器相同的 `MineruPackageLoader`。路径无效、目标不存在或已变为新来源类型时明确失败或返回读取问题，不自动选择其他包。

| 模块 | 本次职责 |
|---|---|
| [`src/library/mineru-verifier.ts`](../src/library/mineru-verifier.ts) | 连接现有完整加载器和有预算的只读存储 |
| [`src/mineru/package-loader.ts`](../src/mineru/package-loader.ts) | 接收可选文件读取回调和取消信号，默认阅读器调用保持兼容 |
| [`src/library/annotation-reader.ts`](../src/library/annotation-reader.ts) | 读取本插件批注块和外部 `annotation_schema: 2`；保留内容角色与来源信息 |
| [`src/library/reader.ts`](../src/library/reader.ts) | 所选旧包核验、字节预算、异常隔离及批注适配 |
| [`tests/test_library_compatibility.js`](../tests/test_library_compatibility.js) | 外部格式反例、真实完整加载器、资产损坏、预算和取消 |
| [`tests/benchmark_library.js`](../tests/benchmark_library.js) | 多规模混合格式的首次读取、重复读取、单笔记修改后重扫和内存快照 |

完整核验继续检查清单、验证记录、原文、MinerU JSON、所有清单产物及包内 PDF，保留原有路径、哈希、图像尺寸和资源限制。默认阅读器不必传入新参数。聚合适配器使用受信任的只读回调，全部文件字节进入同一次扫描的预算与统计；文件存在性、大小和可信路径检查仍由加载器执行，其元数据访问不计入 `filesRead`。

核验成功后仍比较读取前后的 `article.md + manifest.json` 指纹，再允许旧会话按原有类型和指纹匹配。其他包保持未核验；之后普通查询也不会沿用一次核验结果作为永久状态。取消或耗尽预算使整次查询中止，不能被内部可选缓存的异常处理变成“已核验”。损坏原文不会降级成普通 Markdown。

本批使用完整加载器，因此会生成阅读器所需的内存结构和图像 Blob；结果不被新适配器缓存或持久保存。没有创建对象 URL、阅读工作区、恢复任务或调用模型。首次查询、重复查询和局部文件变化目前都需要重新扫描，不声称已实现增量索引。

## 外部批注的兼容边界

支持带 YAML 属性的 `annotation_schema: 2` 文件，校验记录 ID 与文件名、来源路径与 noteId、仓库标识、原样保存的版本字符串、引句和位置范围，以及人工／AI 分区。版本不支持、锚点不一致、分区缺失／重复／交叠、混合两种批注格式均返回文件级诊断，不选择某段剩余内容冒充完整记录。

返回的内容角色包括原文引句、个人笔记和 AI 讲解；来源信息单独保存在 `annotationProvenance`。外部 `source.revision` 即使看起来像 SHA-256，也不据此认定它是本插件定义的内容指纹。仓库标识和版本算法尚未确认时，批注保持独立；同名本地路径不能让它借用论文身份，也不能据此宣布历史引句已变化。

现有 Dashboard 批注继续使用原解析器，原文、人工和 AI 内容的职责不变。此兼容层不编辑外部批注，不把 AI 讲解提升为原文证据，也不迁移、合并或重新保存旧文件。

## 工程验证

`pnpm test:library` 通过 45 个内存／兼容场景及独立磁盘持久记录测试。新增 5 个兼容场景实际调用完整 MinerU 加载器，使用带清单、验证记录和图片的隔离包；确认只有选中包的图像被读取，图像损坏会阻止核验，在资产读取期间取消或耗尽总字节预算会中止查询。临时夹具保留，没有执行删除。

同时通过类型检查、生产构建、28 项发布审计、全文获取 6 组、来源入库 3 组、JATS 8 组、MinerU 阅读器、批注来源完整性及阅读 progress/catalog/entry 回归。MinerU 阅读器测试中的可选私有夹具未提供，已跳过；旧全量测试与包含删除操作的旧包限额入口未运行。新增完整加载器夹具和真实测试库提供本次改动的定向验证，不能据此声称所有旧测试均已执行。

### 可重复的混合格式测量

运行 `pnpm benchmark:library`。三个规模分别在独立 Node 进程执行，固定使用实际入库服务生成的小型 PDF 与 JATS 工程包，加一份未核验的旧包，每组加入一个剪藏来源、一篇同 DOI 笔记、一条历史 PDF 会话和一条 Dashboard 批注。业务数据全部留在内存；正式扫描只拿到 `read/list`，重复结果必须一致，单篇笔记修改后必须能看到新哈希。

本机为 Windows、Node `v24.18.0`、AMD Ryzen 7 7735H；各进程启用 `--expose-gc`。下表为本次单次运行的观察值，单位为毫秒；不设置依赖机器速度的通过阈值。

| 对象数 | 首次扫描 | 两次重复扫描 | 修改一篇笔记后重扫 | 每次文件／目录读取 | 修改前读取字节 |
|---:|---:|---:|---:|---:|---:|
| 403 | 28 | 18 / 17 | 18 | 422 / 17 | 368,706 |
| 2,003 | 79 | 65 / 58 | 60 | 2,022 / 17 | 1,751,506 |
| 4,003 | 117 | 100 / 92 | 93 | 4,022 / 17 | 3,480,006 |

4,003 对象首次扫描的进程堆占用约 8.2 → 30.5 MiB，RSS 约 87.7 → 120.7 MiB；四次观察中的最高结束快照分别约 60.1 MiB 和 177.8 MiB。快照包含测试框架与用于确定性比较的保留结果，不是加载器独占内存或峰值。首次扫描不含模块编译及夹具准备，内存存储不模拟磁盘延迟，更不是操作系统冷缓存或实际大 PDF 性能。

单笔记修改后读取调用数完全不减，仅多读 31 字节。这明确记录了当前增量更新的缺口，不能把更短耗时解释为已有增量缓存。原生大包与混合格式小夹具互为补充，尚缺真实大型 PDF/JATS、同步盘、冷启动和长时内存测量。

## 下一步及未完成的验收

第五批已完成 3 篇合法全文、每篇 6 题的样本与离线证据检查，保留转换失败和待人工复核状态，见[科学阅读质量记录](reading-quality-baseline-r0.md)。本第四批只完成文件完整性、关联和资源行为检查，没有读取论文来形成科学结论；后续样本检查也不能代替真实模型答题或独立人工裁定。

进入 R1 时，普通扫描和按需核验都应异步执行，提供等待和取消状态；不能在页面渲染中自动完整核验全部旧包。扫描结果可用于展示，但打开来源和执行写入仍要重新检查。增量索引及验证缓存需要另做失效规则、来源变化和内存验收，不能通过省略现有完整校验来降低计数。

本次修改范围为插件源码、测试、版本文件和开发文档。没有改动正式 Vault、论文笔记、原文包或研究目录规则，因此科研索引及 Vault 日志不更新。证据来源是项目代码与工程运行结果，科学处理深度不适用；没有待批准的数据迁移或包安装操作。
