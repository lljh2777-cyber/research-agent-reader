## 旧题错误的开发者核对

这些核对为修正决定提供依据，属于开发者事实复核；不是独立教学审阅，也不修改已有回答或冻结参考要点。原答和具体问题位置见 [T1.3C 逐题观察](topic-teaching-t13c.md#逐题开发者观察待独立裁定)。

| 问题 | 核对结果 | 对开发的影响 |
|---|---|---|
| M01 把输入与目标的差异当作训练误差 | 常见监督学习先由输入产生预测，再按损失函数比较预测与目标；输入本身可能与目标维度不同 | 属于量的职责混淆，不能靠格式检查判定正确 |
| N01 说损失数值直接决定更新强度 | 不能由损失单个数值推出更新幅度；还取决于梯度、学习率与优化器状态 | 回答长短或是否列出步骤都不能代替事实核对 |
| N02 把梯度说成最快下坡方向 | 对可微函数和欧氏度量，非零梯度指向局部最陡上升方向；普通梯度下降使用负梯度。原答的下坡定义与减去梯度公式冲突 | 属于核心概念错误，必须作为教学验收未通过的问题保留 |
| N03 把是否 step 当作是否累积的条件 | 常规 PyTorch 中反向传播累积梯度，step 更新参数，zero_grad 清梯度；更新参数不等同于清梯度 | 状态生命周期需要独立核对，不能给所有优化器套同一个简单更新公式 |
| M06 未区分选模型与最终评估 | 用于模型或超参数选择的数据不能同时冒充未参与选择的最终测试；可采用独立验证集或训练部分内部的交叉验证 | 保留模型选择与最终评估的原冻结要点，不因回答漏讲而删掉要点 |
| M04／M05 对资料和时效信息作出承诺 | 当前主题请求只有目标、路线和祖先对话，不读取库内文件、网页或执行环境；提供标题不等于已取得可读取全文 | 这是产品能力与回答承诺不一致；T2 未实现前不能承诺已能自动查证或定位页码 |

M01 的量与 N03 的分工以 [PyTorch 优化教程](https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html)和 [清梯度教程](https://docs.pytorch.org/tutorials/recipes/recipes/zeroing_out_gradients.html)复核。M06 以 [scikit-learn 交叉验证说明](https://scikit-learn.org/stable/modules/cross_validation.html)复核。来源能力依据当前 [`teaching.ts`](../src/topic-learning/teaching.ts) 请求内容和 [`study-service.ts`](../src/topic-learning/study-service.ts) 调用链静态检查，不将一般阅读后端可选联网功能视为主题请求已启用。

N01／N02 还可用简单数学反例核对：设损失分别为 `θ²` 和 `θ² + 100`，两者在同一点的梯度均为 `2θ`，损失值不同但普通梯度下降更新相同。在 `θ = 1` 时，正方向使 `θ²` 增大；学习率 `0.1` 的负梯度步骤得到 `θ = 0.8`。这是开发者构造的解析推导，不是模型实际运行或调用 PyTorch 得到的结果，也不说明任意步长均使损失下降。

## 新题设计与证据边界

[`t1-transfer-v1.json`](../tests/fixtures/topic-quality/t1-transfer-v1.json) 包含两个新学习目标、每组两个主线与两个支线问题：

| 题目 | 检查重点 |
|---|---|
| S01 相关与因果 | 不从共同变化直接推出因果；例子保留共同原因等替代解释 |
| S02 零相关 | Pearson 线性关联与独立不同，非线性反例需要分布条件 |
| S03 未配置知识库 | 不虚构引用，也不承诺只给标题就能自动读取并精确定位 |

| P02 迭代器耗尽 | 遍历状态与原列表内容分开，iter 旧迭代器不会复位 |
| P03 实际运行要求 | 不编造执行结果或 Python 运行版本，推演与实测分开 |
| P04 再次遍历 | 新迭代器、新生成器对象与旧对象复位不同，外部状态影响可重复性 |

| S03 | 承认未读取知识库，未虚构论文页码，也未保证仅凭标题自动定位 | 当前这次回答守住了主要能力边界，不据此宣称所有来源问题均可靠 |

| P01 | 用列表与游标说明遍历状态 | 把所有可迭代对象都讲成不记位置的静态仓库，忽略迭代器本身也可迭代；把索引加一当作协议通则，且未解释耗尽异常就让用户自检 |
| P02 | 正确说明耗尽没有清空原列表，区分列表与同一迭代器再次遍历 | “for 绝不修改列表”需要限定仅遍历动作，循环体仍可修改；对旧迭代器调用 iter 不复位的边界未直接说明，自检“重置”措辞仍需复核 |
| P03 | 明确没有执行环境，未编造 Python 版本，区分规范推演与实际运行 | 默认直接 next 的耗尽说明符合所举情境；对异常捕获等条件的省略不推广为所有调用都会中断程序 |
| P04 | 正确区分新列表迭代器与新生成器对象，知道旧生成器不自动复位 | 又称必须销毁旧对象，类比容易误导；未交代外部输入可影响新生成器的结果，继续沿用静态仓库的过度概括 |

S02 的常量输入反例可直接核对 [SciPy 文档中的 ConstantInputWarning](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.pearsonr.html)：分母为零时系数未定义，不能说成接近零。P01 的推广问题可核对 [Python 迭代器教程](https://docs.python.org/3/tutorial/classes.html#iterators)：迭代器可由自身的 `__iter__()` 返回自己，生成器也是迭代器，不能把全部可迭代对象定义为不记忆状态的数据仓库。这里仅核对文档和原答，没有执行示例或自动替换回答。
