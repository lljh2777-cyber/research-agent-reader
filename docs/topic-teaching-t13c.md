# T1.3C：教学规则版本化与同题对照

开发版本 `0.56.1`，实施日期 2026-09-11。承接 [T1.3B 首次答题](topic-quality-t13b.md)，本轮根据开发者初读做通用规则修订，建立可回放的 v1 / v2 对照。独立教学审阅仍待完成，当前继续保持开发预览；规则修订不是教学验收结论。

## 修订内容

[`teaching-rules.ts`](../src/topic-learning/teaching-rules.ts) 保存不可变的 v1 与 v2 规则。v2 把当前问题放在路线目标之前，要求先说明概念适用范围、保持例子和指标一致、区分流程阶段及状态变化、交代代码重复调用的条件，并根据用户基础减少无关术语。资料或实时信息不足时直接解释缺口，不再要求模型补齐另一单元的讲解模板；自检变为按需，不催促标记完成或假定用户已理解。

规则不包含机器学习九题的参考答案、具体 API 的正确答案或题目编号，也没有追加模型自评、答案修复或重试请求。JSON 返回结构、主支线选取、路线、问题、上下文上限与 `max_tokens: 5000` 保持原契约。v2 的首轮请求只改变系统教学规则；后续问题使用各自运行实际得到的祖先回答。

这是一项开发修订实验。独立审阅继续作为结束开发预览的门槛；在此前可以修正已有证据指向的问题、冻结候选规则并保留对照。不能把开发者的修订决定、工程回放或小样本观察改写为独立审阅通过。

## 历史兼容

`study.ts` 校验并保留每次请求原有的 `promptVersion`，接受明确登记的 v1、v2，拒绝未知版本。新请求和显式重试使用 v2；旧正文、失败回执、日期、用量、用户理解标记及内容摘要不会被重写。一个会话可以保留旧 v1 回答并继续生成 v2 追问。

请求详情显示教学规则版本。新导出的 v2 尝试附带版本信息；只有 v1 尝试的导出保留既有字节格式，避免升级后相同内容产生无意义的新文件。已被手工修改的导出仍保留，不被模型或程序覆盖。

`0.56.0` 无法识别 v2 请求，因此生成 v2 记录后直接降级会使该记录被旧版拒绝读取。没有向后改写、自动迁移或删除过程。完整恢复仍依赖原始追加日志。

## 冻结与复现

[`t1-v1.json`](../tests/fixtures/topic-quality/t1-v1.json)、历史冻结观察及第一次真实运行观察保持原样。新增 [`t1-v2.json`](../tests/fixtures/topic-quality/t1-v2.json) 只改变基线 ID；两组目标、九题顺序、路线、参考资料、判断要点和失败反例与 v1 完全一致。独立参考状态继续为暂定，新增规则不能事后修改判断标准。

[`topic-quality-baseline.cjs`](../scripts/topic-quality-baseline.cjs) 可分别检查两版；准备真实运行默认选取当前规则匹配的 v2。旧运行目录使用其已冻结的本地运行时做只读重放，不用当前规则重建成旧请求。

```powershell
pnpm test:topic-study
pnpm test:topic-records
pnpm test:topic-quality
node scripts/topic-quality-baseline.cjs prepare <新的库外目录> topic-t1-v1
node scripts/prepare-topic-quality-run.cjs <新的库外计划目录>
```

显式运行与取消方式沿用 [T1.3B](topic-quality-t13b.md)。每题只保留首次响应，失败停止后续步骤，不自动重试。旧目录不能复用为新输出位置。

[`compare-topic-quality.cjs`](../scripts/compare-topic-quality.cjs) 对两份已验证材料生成逐题并列审阅包；拒绝改变题目、路线、判断要点、模型配置或运行模式的比较，也不把未完成或失败答题伪装成完整九题对照。

```powershell
node scripts/compare-topic-quality.cjs <v1运行目录> <v1计划目录> <v1计划摘要> <v2运行目录> <v2计划目录> <v2计划摘要> <新的库外对照文件.md>
```

报告展示首次正文、字符数、接口用量及原冻结要点，不自动评分。两次顺序运行未固定随机种子，代理背后的模型身份及稳定性未独立核实；后续题的祖先回答不同，所以不能把差异全部归因于系统规则，也不能据此声称统计显著或适用于所有主题。

## 逐题开发者观察，待独立裁定

以下仅记录实际输出差异和问题定位，不给出通过率，也不更改冻结要点或原答。v2 的表达收敛与事实可靠性必须分开判断。

| 题目 | v2 相对 v1 的变化 | 仍需处理的内容 |
|---|---|---|
| M01 输入、目标与预测 | 开头先限定监督学习，水果例子较短 | 把训练写成比较“输入”与“目标”的差异，混淆预测与输入；不能因范围说明改善就判为事实正确 |
| M02 泛化 | 延续水果例子，不再使用未定义的回归准确率，也没有宣称用户已掌握 | 沿用 M01 的输入／目标错误；用规则失去弹性等比喻推断过拟合机制，仍把有限观察外推为确定结论 |
| M03 归一化泄漏 | 保留先划分、仅用训练集拟合变换、再应用两组的核心顺序 | 指标“必然”虚高的过度确定性仍在，固定比例随机划分也未交代适用条件；自检又换入新任务 |
| M04 空库引用 | 从 1,274 字符缩至 214，回答集中于来源缺口，没有捏造论文与页码 | 承诺只要配置知识库或指定文献名称就能精准定位段落页码；本轮未读取资料，T2 尚未接入，承诺超过当前能力 |
| M05 最新排名 | 更直接说明无法核验当前第一，删去了“本地运行模型”的身份断言 | 仍未经查询就宣称特定外部榜单实时更新各任务前列模型，并部分转回下一课程；没有伪造链接不等于时效信息已核验 |
| M06 第二主线 | 保持水果例子，正文更短 | 仍未解释模型选择／验证与最终测试的分工；把训练指标必然虚高、评估下降必有特定原因写得过于绝对 |
| N01 预测与损失 | 不再把梯度截断归为损失函数职责，移除原来较多的进阶术语 | 又声称损失数值高低直接决定优化强度，未区分数值、局部变化率和更新规则；“客观错误程度”也缺少指标与任务条件 |
| N02 梯度与更新 | 将损失、梯度和更新分段，提及局部性与学习率 | 把梯度定义为最快下坡方向，却随后使用减去梯度的公式，方向解释相互矛盾；还把自动微分讲成模拟全部参数微小挪动，类比与实际算法边界不清 |
| N03 backward 与更新 | 核心回答仍明确 `backward()` 不自动更新参数，删除了未交代条件的同图连续调用练习 | 把是否调用 `step()` 当成跨轮梯度累积的条件，未交代 `zero_grad()`；同时将简单梯度下降公式泛用于所列优化器，不能算职责问题已解决 |

N03 的职责复核使用 [PyTorch 官方优化教程](https://docs.pytorch.org/tutorials/beginner/basics/optimization_tutorial.html)及 [清梯度说明](https://docs.pytorch.org/tutorials/recipes/recipes/zeroing_out_gradients.html)：反向传播计算并累积梯度，优化器更新参数，清梯度是独立操作；不能用是否更新参数代替是否清梯度的判断。这里只核对官方文档，没有执行模型示例，也没有把核对网页加入被测输入。M01、N01 和 N02 的问题还可直接从量的职责及回答内部矛盾定位，最终教学裁定仍待独立审阅。

## 后续决定

T1.3C 的工程目标已完成：规则版本可追踪、历史可恢复、同题对照可重放。当前开发分支的新请求使用 v2，但它仍是未通过教学验收的候选，公开 beta 未更新。两版问题与 v2 新增错误均保留，不能宣传本轮已提高事实正确率，也不能将 T1 整体验收标记完成。

下一步优先核对事实错误与来源能力承诺，组织独立审阅；后续候选除了旧题回归，还需预先冻结未参与修订的新题。仅增加通用提示规则没有解决本次模型的可靠性问题，应区分规则、模型能力与需要真实资料读取的问题，再决定具体开发范围。T2 的资料支持仍单独排期，不能让当前对话承诺尚未实现的检索与页码定位。
