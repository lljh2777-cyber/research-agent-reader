# 全文获取 M2：PMC PDF 获取与本地预览

开发版本：`0.45.0`。已完成「论文标识 → 身份与版本核对 → PDF 获取 → 校验快照 → 无模型预览」。总体规划见[架构与开发流程](fulltext-acquisition-design.md)，M1 演示仍可独立使用。

## 使用流程

1. 从控制台辅助工具打开「获取全文」，或执行「按标识获取论文全文」命令。
2. 输入 DOI、PMID、PMCID 或对应的官方论文链接。默认只查询出版版本，也可明确允许作者接受稿。
3. 点击「查找全文」，核对标题、作者、年份、标识及各候选的 PMC 版本、稿件类型、许可和撤稿提示。即使只有一个候选，也需要选择「获取 PDF」。
4. 获取成功后点击「预览 PDF」，在本地翻页查看原文。首页线索不足时显示「已获取，身份待核对」，不会把它显示为身份已确认。

关闭获取面板不停止任务；可重新打开查看进度、停止或重试。插件关闭会中断未完成任务，重新启动后由用户主动重试。完整快照可离线恢复与预览。

当前支持 PMC 公开提供的 PDF。没有 PMCID、只有 XML、没有所选稿件类型、来源返回错误或版本范围超限时，会说明本次查询结果；可以打开官方页面进一步查找。M2 不会查询 Unpaywall，不会抓取任意出版社页面。预印本暂不纳入此路径。

## 模块与责任

| 模块 | 实际责任 |
|---|---|
| `contracts.ts` | 身份、PMC 版本、PDF 产物和 schema v2 快照的运行时解码；兼容 M1 演示 |
| `identity-resolver.ts` | Europe PMC 精确查询；Crossref DOI 查询与差异提示；完整作者列表和来源时间 |
| `pmc-provider.ts` | 按精确 PMCID 前缀发现版本，读取版本 JSON，按稿件策略生成候选，获取前重查清单 |
| `transport.ts` | 固定主机的直接 HTTPS、DNS 和实际连接校验、限流、重定向、重试、取消与字节流 |
| `file-storage.ts`、`repository.ts` | 创建独立尝试文件、不可变阶段修订与快照、文件哈希和绑定验证 |
| `file-validator.ts` | PDF 文件头和结束标记、可解析性、页数与首页身份线索 |
| `pmc-backend.ts`、`service.ts` | 组合真实来源、协调状态、别名复用、停止重试、提交和恢复 |
| `modal.ts`、`pdf-preview.ts` | 身份与版本核对、实际字节进度、被动 PDF 画布预览 |
| `plugin.ts`、`task-run.ts` | 装配服务、关闭资源、将正式记录投影到控制台历史 |

这些文件位于 `src/fulltext/`，插件装配位于 `src/plugin.ts`。本阶段沿用紧凑模块，不提前创建通用来源市场或共享论文目录。Crossref 使用现有入库流程相同的精确 works 接口，但保留作者列表，不复用其显示用缩略字段。

## 来源、身份与版本

Europe PMC 使用精确 DOI、PMID 或 PMCID 查询并核对返回标识；存在多个匹配或标识冲突时停止。Crossref 缺失或单独查询失败时，有效 Europe PMC 记录仍可使用，并保留提示；两个接口不被视为独立论文证据。作者最多 500 位，超过契约范围拒绝保存，界面只简写展示。

PMC 版本来自精确前缀列表和逐版 JSON，数字大小不表示出版顺序。稿件类型和 PDF 地址取自该版本清单；不硬编码 `.1`，不猜测 HTML 下载链接，不使用已停用的旧接口。每个候选记录清单 SHA-256、PDF MD5、版本和许可；选择后重新获取 JSON，清单有变化就要求重新查询。[PMC AWS 说明](https://pmc.ncbi.nlm.nih.gov/tools/pmcaws/)和[官方数据结构 README](https://pmc-oa-opendata.s3.amazonaws.com/README.txt)描述了所用布局。

格式检查与身份线索分开处理。PDF 通过文件头、结束标记、解析、页数和哈希检查后，匹配首页标题及可用 DOI；明显标识冲突不生成可用快照。文本不足或标题无法精确匹配时保留 `needs_confirmation`。`verified` 仅表示首页身份线索匹配，不是用户视觉确认，也不是论文全文证据验证；所有快照的 `bodyCheck` 都是 `not_checked`。

## 请求与资源边界

| 项目 | M2 行为 |
|---|---|
| 主机 | `www.ebi.ac.uk`、`api.crossref.org`、`pmc-oa-opendata.s3.amazonaws.com` |
| 连接 | HTTPS 直连；无 Cookie、认证信息、系统或 Obsidian 代理继承；DNS 答案必须全部为公网地址，选定地址绑定到 TLS 连接 |
| 重定向 | 最多 3 次，每跳检查，仅允许同一来源域 |
| 元数据 | 并发 2，单响应 2 MiB；单次传输 12 秒；429/502/503/504 最多重试一次，遵守不超过 3 秒的 Retry-After，较长等待留给用户重试 |
| PDF | 并发 1，64 MiB；120 秒单次传输，15 秒连接、30 秒无数据超时；有背压写入，按实际字节再次检查大小 |
| 来源发现 | 整个阶段含排队 20 秒；版本最多 10 个，超出范围明确失败 |
| 获取阶段 | 选定后含排队、清单复查与校验共 180 秒；等待人工选择不计时 |
| 本地 PDF | 最多 2048 页，解析/校验 20 秒；首页文本最多保存 8000 字符；单页预览 20 秒、画布长边约 1600 像素 |

PDF 来源允许标准 PDF 类型及二进制类型，包括真实 PMC S3 使用的 `binary/octet-stream`；文件类型通过后仍必须核验原始 PDF 字节与清单哈希。不会解压 ZIP，不执行 PDF 脚本、表单、链接或附件动作。当前无代理适配；只能通过代理访问这些来源的环境仍可能失败。

## 文件与恢复

沿用 M1 的 `fulltext/production/` 追加式存储，新增每次尝试独占的 `a-<attempt-uuid>.pdf` 和 schema v2 的 `s-<uuid>.json` 快照。文件路径从内部 UUID 构造，不用远端标题、URL 或 DOI 作为本地文件名。

下载创建新文件并边写边计算 SHA-256、MD5。完整文件同步、校验后提交快照，最后提交完成阶段。只有已提交且与任务、尝试、身份、候选和文件一致的快照可预览。任务最后一步保存失败但快照完整时，重启可恢复完成状态；文件缺失、变化或绑定不一致时显示中断。

未完成 PDF、失败修订和无完成标记的文件全部保留，不覆盖或自动删除。重试使用新尝试 ID。哈希失败不会将旧文件重新当成可用结果。文件读取同样有实际字节上限，并检查普通文件、符号链接和文件身份。

本地优先目前只覆盖本服务已获取的快照。相同版本策略下，已解析的 DOI、PMID、PMCID 别名可在哈希检查后复用，无需连接来源；这表示使用已保存版本，不承诺自动发现新版本。暂不扫描旧 Vault 文献或磁盘文件，统一 SourceCatalog 属于后续 M4。

正式记录投影为控制台 TaskRun，不写入旧 `data.json` 任务列表，不经过旧历史清理逻辑。演示仍保存在 `fulltext/demo/`。获取快照不进入 `papers/`、Wiki、索引、MinerU 或模型上下文，文件尚未入库。

## 验收与开发接续

- `pnpm test:fulltext`：四组无网络、无磁盘清理的专项；覆盖精确标识、Crossref 缺失、多版本、接受稿策略、缺 PDF、清单变化、地址/重定向拒绝、断流/超限/取消、PDF 冲突/待核对、文件篡改、半写入重试、快照提交及恢复。
- `tests/obsidian-fulltext-acquisition.cjs`：内存演示与正式入口的原生 DOM 回归，不下载真实文件。
- `tests/obsidian-fulltext-pmc.cjs`：显式运行的真实来源验收，不在自动测试入口内。默认获取官方 README 中的 `PMC10009416`；参数 `resume` 要求已有快照，验证重载后无网络复用及预览。文件和记录保留，不清理。
- 既有入库、控制台、阅读专项，以及原生入库续办交互检查用于回归旧路径。

真实测试仅核验获取和展示，不解释样本文献结论。本阶段不产生科学笔记，处理范围相当于 `metadata-only` 加文件完整性和首页身份线索检查，不是 `abstract-level` 笔记或 `x-ray` 深读。原始架构提案、Vault 索引和研究日志未修改。

下一阶段 M3 增加开放 PDF 回退与「继续入库」。开始接入前需要核对原有入库路径的快照授权和失败清理；本阶段的首页 `verified` 不能替代原有入库的视觉确认回执。

### 本阶段实际验证记录（2026-09-09）

类型检查、生产构建、全文四组、入库五组、控制台两组和阅读 22 组专项通过。原生全文入口/演示 14 项、旧入库续办 28 项、真实 PMC 获取与预览 13 项检查通过；插件重载后另通过 13 项恢复与预览检查，元数据请求与 PDF 传输均为零。

公开样本 `PMC10009416.1`，许可 `CC BY`，实际 PDF 为 471,593 字节、10 页；SHA-256 为 `95646dd6fefc136cb522bdcc6caaf504da0ccb710a3df623a298b9dc83c1b1c4`。本地 PDF.js 校验结果为首页身份线索匹配，前两页实际渲染；三种标识复用同一快照，未增加网络调用。首次实测暴露的二进制 MIME 类型兼容问题已修复并加入回归；原失败文件仍保留。

首次部署前备份三个插件构建文件；全部原生验收及重载后再次核对，94 个既有数据文件内容未变，三个部署文件与当前构建哈希一致。28 项发布审计通过，Obsidian 未捕获错误。已检查实际预览截图并关闭测试预览，恢复临时焦点模拟设置。

测试只使用公开来源，没有调用模型或 MinerU；真实 PDF、运行记录和截图留在测试环境，不提交到代码仓库。旧全量测试入口含不符合当前约束的清理路径，采用以上专项验证，不宣称全量测试通过。
