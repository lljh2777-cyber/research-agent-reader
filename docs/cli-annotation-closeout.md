# CLI 批注定向收尾

日期：2026-10-13。版本：`0.88.1`。本轮处理三产品四模型工程接入后暴露的解释越界问题，并补正常宿主重启和首次冷缓存验收；历史调用、失败和用量继续见[本机 CLI 批注](cli-annotation-backends.md)。

## 调整

共用文字批注指令要求保留比较对象、分组、样本范围、数值分母、限定与否定。两组差异不得扩写为连续趋势、剂量反应、原因、机制或干预建议；原文没有明确分组时也不能自行补出。研究类别不能替代具体设计证据，片段未提供的随访、时序、调整变量与方法保持未知，未报告某个步骤不能改写成未做该步骤。一般知识限于必要术语，单独标注，不能借此补写本研究细节。

规则作用于 CodeBuddy、Qoder 和官方 OpenCode 的文字批注，包括这些后端已有的双语调用。原文核验、准确模型参数、工具边界、取消、超时及旧回答保存格式保持。旧批注没有重新生成或人工改写。

Step 在补充提示后仍将一般知识写成“未经调整的组间描述”，因此新增限定的结果拦截：所给原文没有明确的未调整依据，而解释中出现已复现的肯定式断言时，停止交付，界面提示核对原文，不自动重试或换模型。回归同时保留否定、疑问、条件语气及有明确原文支持的表述。双语检查仅以实际英文段落作依据。该文字检查只覆盖这一类已复现错误，不是全面科学核验，不能推导其他设计细节已经正确。

## 固定材料与核对范围

先为每个候选发起一次实际模型请求。OpenCode Step 首次没有返回文字事件，仅有 `stop` 和输入／推理 token，输出为 0，被拦截且未保存；读取该会话确认准确模型后，仅对这一项以相同材料、模型和指令人工复验一次。复验回答却将未报告调整变量写成“未调整观察比较”；这份回答照原样保留，没有当作质量通过。补上“未报告不等于未进行”的指令后，再对 Step 的相同材料复验一次。总计六次请求，不自动重试或换模型，不批量重跑旧题。两个 Step 候选使用同一离散比较夹具：96 人观察性研究中，高表达组的观察风险低于低表达组，片段未提供随访时点和调整变量。核对是否保留两组比较、避免推断连续趋势或因果、避免补写设计。

Qoder 和 mimo 使用测试库已有 Bailey 原文 Markdown 的同一段落，标题和 DOI `10.1038/nature16965` 经原 PDF 第 1 页核对，实际选句与上下文经 PDF 第 2 页核对。Qoder 选取 `6/25 in squamous versus 1/71 in the rest`，mimo 选取 `96 tumours with high epithelial content (≥40%)`。仅检查该段文本含义与来源，不声称已检查所引图、补充材料或整篇科学结论。

每次通过原生设置、批注弹窗的“AI 解释”和“保留”控件执行；选区由驱动从实际文件的文字和偏移构造，属于 DOM 事件验收，不是物理鼠标完整操作。保存后逐字回读回答与 CLI 回执，核对原文摘要和布局；私有原始输出、回答及重启记录留在测试目录，没有提交到公共仓库。

## 结果与残留问题

| 候选 | 定向结果 | 保留的边界 |
| --- | --- | --- |
| CodeBuddy `step-5-preview` | 保留高／低两组比较，明确不推出连续趋势或因果；保存及来源回读通过 | 术语释义仍为模型一般知识，不能外推至其他材料 |
| Qoder `Qwen3.8-Flash` | 正确保留 6/25 与 1/71、鳞状亚型与其余亚型的比较；保存及来源回读通过 | 原段已提供的 Fisher 检验等细节却被放在一般知识段，归属仍不够精确 |
| OpenCode `opencode/mimo-v2.6-flash-free` | 新宿主首次无既有配置缓存的调用成功；保留 96、232、≥40% 的范围区别，保存及来源回读通过 | 首段补充“信号稀释或干扰”的解释，末段将扩展集合称为验证；这些扩展未独立核验 |
| OpenCode `opencode/step-5-preview-free` | 空解释被拦下；后两份文字保留了两组比较，但仍断言未经调整 | 不认定质量通过。两份回答在拦截实现前按原样保存；最终规则回放同一原始输出时拒绝交付，界面无新增批注，无新增模型请求 |

原始输出和保存回答经最终拦截器读回：其他三个候选样本通过这项限定检查，两份 Step 越界表述被拒绝。OpenCode 额外只读导出本轮拥有的会话，确认请求的准确模型与 `stop`；常规 JSON 回执仍不冒充实际模型报告。

六次请求按原始 CLI 字段留档：CodeBuddy 输入 3484、输出 1770、缓存写入 3484；Qoder 输入／输出／缓存均为 0；mimo 输入 6956、输出 272、推理 64、缓存读取 64；Step 三次分别为输入／输出／推理 6610/0/640、6609/214/292、6642/240/257，缓存均为 0。费用字段均报告 0；Qoder 的零 token 不代表实际没有消耗，不能据此承诺永久免费。推理等额外字段留在私有原始输出，批注回执沿用现有字段。

## 正常重启与工程验证

Windows / Obsidian `1.14.4` 两次正常退出，均确认全部宿主进程结束后重新启动，没有强制终止。第一次在新宿主中进行 mimo 的首次配置缓存调用；当时使用首轮收紧规则。末次缺失信息规则与结果拦截通过定向回归及原始输出回放核对，没有为规则变更重复全部真实调用。

第二次以最终构建正常重启，确认宿主和渲染进程均改变、四个模型的保存设置及当前后端恢复、工作区和来源视图状态一致、九份批注正文与回执逐字一致、来源摘要不变。九份包括本轮五份已保存回答和此前四份历史回答，已知质量问题不会因升级被改写。最后恢复原后端设置；重启检查没有模型请求。

类型检查、生产构建、实际失败表述与有据／条件表述回归、三个 CLI 适配器、来源完整性、双语、联网旧路径、设置、交换及公共发布边界定向检查通过。本地旧全量入口含批量清理而未运行，完整公开检查由三平台 CI 与标签发布工作流执行。私有 MinerU 夹具未配置。
