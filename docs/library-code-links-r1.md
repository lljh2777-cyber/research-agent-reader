# R1 文献关联代码入口

2026-09-11，开发版本 `0.61.0`。

文献详情新增「关联代码笔记」。从本条文献已关联的论文笔记出发，展示 Obsidian 链接缓存中直接相连的代码项目／脚本笔记与代码学习导出。列表显示完整代码笔记路径、论文笔记路径和链接方向，点击「打开代码笔记」打开该文件。

## 关联范围

- 代码笔记位于 `wiki/code/projects/` 或 `wiki/code/scripts/`。
- 代码学习导出位于 `wiki/qa/`，缓存属性包含 `reading_source_kind: code`；导出时选定的关联笔记会形成正文链接。
- 只使用 Obsidian 已解析的直接链接，两个方向均支持；同一目标被双向链接时分别列出关联方向。链接出现次数不增加重复条目。
- 不根据相同标题、文件名、模型回答或方法页的间接链接推断归属；身份冲突的文献不展示关联。
- 仅列出当前存在的 Markdown 文件；代码会话仍由代码阅读空间管理，不作为论文阅读会话合并进文献记录。

## 浏览与打开

浏览只读取现有文件目录与链接缓存，不改写论文、代码、人工决定或会话，不运行项目和模型。链接只表达笔记间的导航关系，不证明官方实现、科学一致性、代码正确性或审阅通过。

缓存可能延迟或尚未完成解析，因此空列表表示「本次缓存未找到」，不证明没有关联。编辑链接后可等待 Obsidian 完成解析，再刷新文献库。打开前重新扫描文献目录和当前缓存，核对同一文献、同一论文笔记、同一代码路径及方向；关联变化、文件缺失或取消时停止，不寻找同名替代。该检查仍基于缓存，不是正文链接的即时重新解析。

每次最多检查 50,000 条相关源节点的链接，每个详情最多展示 100 条关联；达到上限会提示。代码关联读取错误单独展示，不阻断论文目录或改变文献身份规则。

## 开发验证与后续

内存回归覆盖双向链接、同名不同路径、代码导出分类、普通 QA 排除、失联、缓存不可用、身份冲突、路径安全、非传递关联、旧目标拒绝与读取上限。文献读取、浏览、主要笔记与人工阅读状态回归、类型检查、生产构建和发布结构检查同时执行。
