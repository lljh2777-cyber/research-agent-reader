# R3.11：新知识页的可恢复草稿

更新日期：2026-09-13。开发版本：`0.79.0`。

## 使用方式

在「知识整理 → 新知识页草稿」或命令“打开新知识页草稿”中开始。可以新建空白草稿，也可从原文摘录或学习回答摘录详情点击起草入口。选择概念、方法或综合类型，填写标题和正文，预览后确认保存。

原文摘录默认附带原句，个人备注单独选择；学习摘录默认附带 AI 回答片段，可选择已有人工修订和备注。材料以保存时的完整文件快照和所选角色保存，正文可以继续编辑，保存后的材料不被正文编辑替换。预览显示当前选择的内容，未选角色仍保留在原始快照中供来源核对。第一版每份草稿最多附带一份摘录。

草稿列表支持按标题或 ID 搜索、按准确 ID 打开。已保存记录可以关闭后重开，或从待处理中心的“知识页草稿”分类返回。未保存输入有关闭保护；“放弃未保存输入”回到最近读取的内容。插件卸载或重载不会保证恢复尚未保存的输入，界面明确提示先保存。

## 预览、版本与恢复

预览分别显示正文与附带材料；修改过的草稿还展示最近读取的保存版本。输入或角色变化会清除旧预览。保存只写插件记录，不创建 `wiki/concepts/` 等正式页面，不改索引或日志，也不调用模型。

旧窗口保存时若检测到新版本，保留当前输入并停止写入。使用“重新读取（保留输入）”核对最新版本和历史，自行合并后再预览确认。每次保存追加版本，不覆盖以前内容；可查看各版完整文本，或把指定版本复制为新的未保存草稿。草稿版本历史与学习摘录“人工修订稿”的历史是不同功能，本轮未补写后者。

文件已写完但提交未完成时，列表和待处理中心显示未完成保存。从版本记录预览该次内容后明确恢复；恢复复用原记录，不重复新增版本。同一保存的响应丢失也按准确内容复用。多个竞争版本、损坏正文、缺失前置版本或异常提交标记不会被自动选为最新；可以查看有效版本并另存新草稿，原记录保留。没有自动合并、删除或覆盖修复功能。

材料状态与草稿保存分开。“核对附带材料”读取当前摘录及对应原文或回答版本；当前来源无法读取或已变化时，历史快照继续保留，用户仍可编辑草稿。PDF 显示文件页码、页内位置和文件版本；这类核对不代表原文包身份或科学结论已核验。学习材料始终标明 AI 或人工记录，不是论文证据。

## 存储与边界

复用 `SourceStorage`／`FileSourceStorage` 的固定根、路径检查和仅创建接口，新增插件目录内 `knowledge-drafts/<draft-id>/`。每个保存版本有按内容摘要命名的 JSON 和 `.ready` 提交标记，记录父版本摘要；读取不初始化目录，不修复或清理文件。旧草稿、原文摘录、学习摘录和知识修订记录均不迁移。

标题最多 200 字符，正文最多 40,000 字符，材料原文件读取上限 2 MiB，单个保存记录上限 4 MiB。每份草稿最多 64 次保存，单次历史读取预算 16 MiB；列表最多读取前 100 个草稿 ID，总结果预算 32 MiB。达到边界时明确提示并保留记录，可按 ID 打开或复制另存。接近上限的长期使用性能尚未实测。

草稿 JSON 位于插件目录，未进入原有 Markdown 知识检索、学习索引、论文来源聚合或正式知识修订目标范围。预览通过纯文本节点展示，不执行正文中的 HTML、脚本或外部资源。材料通过已有摘录解析器验证，原文、AI、人工修订和个人备注不会被转换为另一种来源类型。
