# 交互式 PDF 深读

交互阅读将论文主线讲解、节点追问和知识库证据保存在同一学习会话中。主线通过箭头逐步推进；追问形成可独立恢复的支线。

## 开始阅读

1. 在 Dashboard 点击 **PDF 深读**，或通过命令面板打开 **PDF 交互深读**。
2. 点击 **新建阅读**，选择原始 PDF 的完整路径，或当前库的 `papers/<citekey>/article.md`。选择可用的 Codex CLI 或已通过连接测试的 Direct API 配置。
3. 点击 **打开并继续阅读**。相同来源且指纹未变化时，默认恢复已有未归档会话，并沿用原模型；勾选“为同一原文重新建立会话”才重新开始。新会话先生成阅读路线，再讲全文总览；展开 **阅读路线** 可查看各单元的中心问题。完成后点击最新主线节点右侧的 **→** 继续一个单元。已有提纲的会话沿用原路线。
4. 主输入框显示当前追问目标。在这里提问会建立新支线；支线小窗内输入会继续当前支线。选中历史回答文字后显示“追问／复制”工具条，点击 **追问选中文字** 才打开引用输入框，发送后建立以该回答为起点的子支线。
5. 点击正文中的数字引用，或展开回答下方的 **查看原文依据**，查看原文片段、页码或图像。MinerU 来源可以跳转到阅读器的对应页面；知识库补充可以打开原笔记。无法匹配的引用保持原样显示。
6. 点击右上角的下载图标（**导出学习笔记**），选择当前节点、当前支线或完整会话。在右侧检查完整预览，点击 **查找关联笔记** 查看知识库候选的章节、片段与来源，勾选需要的关联后保存。相同范围和内容会打开已有笔记；内容变化时另存修订并保留上一版。新文件保存到 `wiki/qa/` 并追加 `wiki/log.md`，正式论文的 `x-ray` 状态独立保留。

## 两种界面

回答下方可标记「已理解／待回看／仍有疑问」，与 AI 生成状态独立保存。导图底部可筛选这些状态，其他节点淡化以保留关系和位置。在引用窗口点击「固定原文对照」，会打开可拖动、右下角缩放的独立对照窗；后续点击引用更新此窗，可用「上一处／下一处」回看。对照窗与历史随会话恢复。来源指纹核对通过后可手动勾选「我已对照此处原文」；这不等于论文 X-Ray 核验，也不会自动标记整段回答正确。

默认左右各半：左侧始终是主线会话，右侧是自上而下的主线导图。顶部切换 **导图＋对话** 与 **仅思维导图**；点击论文标题打开会话管理面板。青绿色编号标识主线，暖金色标识追问；左侧显示已完成单元数，可展开阅读路线回看已有单元。导图节点 **单击只选中，双击选中并打开小窗**；主线小窗显示当前单元，支线小窗显示所属支线并定位这一轮。键盘聚焦节点后，空格选中，Enter 打开小窗。单击主线同时更新主输入框的追问目标，单击支线保留原主线输入目标及已有小窗。中间分隔线可拖动，也可聚焦后用左右方向键调整。

两种模式切换采用约 0.36 秒的平滑过渡：对话区展开或收起，导图留白和底部输入区同步调整，按钮的选中背景滑动到对应模式。切换复用现有导图节点与固定小窗，保留缩放、草稿和阅读位置；快速反向切换从当前动画位置继续。系统启用“减少动态效果”时直接切换。调整窗口大小、拖动分隔线或离开会话会结束当前过渡，不影响生成任务。

会话面板默认显示正式阅读，可按标题或来源路径搜索，支持置顶、重命名、归档和恢复。同一来源的多个会话分组显示，历史不自动合并或删除。演示和开发测试在独立分页；旧示例依据演示标记与模拟来源识别，不因标题相似隐藏真实论文。新验收会话写入插件目录的 `reading-test-sessions/`，既有文件保留原位。

**仅思维导图**隐藏左侧主线会话，同样单击选中、双击在小窗查看详情。默认保留一个活动小窗，可通过图钉固定多个窗口用于对照；标题栏可拖动，四边和四角可调整大小，位置与尺寸自动保存。右下角的斜向箭头为明显的缩放入口，聚焦后也可用方向键调整，按住 Shift 可微调。收起或关闭窗口会保留会话和生成任务，只有 **停止** 按钮取消生成。导图右下角可缩放、点击百分比恢复 100%，或定位当前选中节点；支线卡片右下角可折叠后续问答。窄分栏中可水平滚动导图。

导图支持拖动空白处平移，顶部的搜索按钮检索当前会话的标题、问题和回答，包括已折叠节点；点击结果会展开相关支线并定位回答。旁边的按钮返回最新主线。底部 **适应视野** 根据当前可见导图调整缩放，最低 40%；较长会话可配合折叠或搜索导航。支线小窗顶部显示问题来源路径，可点击祖先标题或 **返回问题起点** 回看；这些操作保留已固定小窗的尺寸与位置。

小窗采用紧凑标题栏和输入区，主要空间留给正文。输入框默认单行，长问题自动增高至上限后在框内滚动；Enter 发送，Shift + Enter 换行。清空内容后自动缩回单行。

草稿按主线目标或支线隔离。两种模式共用节点、草稿、固定窗口与生成状态；分栏比例、窗口位置及滚动位置自动保存。右上角 **更多阅读选项** 包含阅读模型、交互演示及一次性深读。**交互演示**创建带有明确标记的示例会话，不调用模型，适合先熟悉操作。

## 来源、记忆与模型

回答下方的「核对／重新解释」及划选菜单可生成独立核对版本；保留原回答，比较后选择「用于后续背景」才影响新主线与新支线，旧支线背景保持不变。更多阅读选项增加「证据覆盖」和「重新定位原文」，分别查看输入与个人核对记录、在内容指纹一致时恢复移动后的原文。详见[入库与深读完善](reading-workflow-improvements.md)。

「更多阅读选项 → 阅读模型」可选择均衡讲解、基础解释、方法细节或结果与证据。偏好随会话保存，只影响后续请求，不重写历史回答或额外调用模型。已有主线提纲保持不变；模型改动提纲、重复已有标题或正文时保留失败节点供重试，完成进度按实际单元数判定。

- 原始 PDF 使用所选文件的文字和按需渲染的页面；扫描页需要视觉模型。选择 `article.md` 时必须通过现有 MinerU 包校验，不会自动替换成 PDF 来源。
- 每轮先选择本文证据。需要解释概念或比较论文时，模型可请求一次有界本地 Wiki 检索，回答显示实际读取路径和检索缺口。补充来源限定为论文笔记、概念、方法、综合等知识目录，排除操作日志、批注和自动学习记录。Direct API 问题支线可按次勾选「联网补充」，沿用供应商的原生联网或 Tavily 配置；主线默认不联网。网络来源与本文、Wiki 分开记录。
- 只有实际发送给模型的图像才记录图像读取标记。当前模型不支持视觉、图像缺失或本轮图像过多时，会停止并提示调整问题或模型。该标记只说明模型接收了图像，不代表人工确认科学结论。
- 新支线保存创建时的最新主线摘要、父节点和相关祖先对话；旧支线不会被后续主线覆盖。较长历史会按需摘要，近期问答优先保留原文。摘要失败会保留原始记录并允许重试。
- 通用规则位于 `skills/paper-guided-reading/SKILL.md`，生产构建将它嵌入插件。Direct API 使用已配置 Provider；独立 Codex CLI 使用只读沙箱和插件提供的上下文，不要求外部 Toolkit。CLI 的正文在最终消息完成后显示；支持流式能力的 Direct API 可逐步显示正文。
- 可通过 **更多阅读选项 → 阅读模型** 修改后续生成的后端。失败、取消或重启后的未完成节点可点击 **重试**，重试更新同一节点；当前节点完成后才能继续同一条主线或支线。

## 保存与边界

会话完整内容保存在插件目录的 `reading-sessions/<id>.json`，与 `data.json` 和独立知识库对话分开。采用串行写入、同步及原子替换；不会自动删除旧会话。Codex 的只读运行材料保存在 `reading-runs/`，同样不自动清理。备份插件时请保留这两个目录和设置文件。

原文件缺失或指纹改变时，旧会话仍可阅读和导出，新增回答会停止。重新选择来源会新建会话，不会把旧证据定位关联到新文件。原始 PDF、MinerU Markdown 和资产均只读。

导出笔记保留问题、回答、学习层级、引用和来源。跨 `papers/`、`wiki/` 等主目录的来源使用非链接路径，避免创建跨根链接。模型生成的 Markdown 经被动化后显示和导出。

关联候选由与问答共用的检索层提供；配置见 [BGE 知识库检索](semantic-retrieval.md)。相似片段只表示可能相关，需读者核对后选择，不会据此合并结论。导出窗口可比较已有版本与新内容、打开各次修订。笔记以会话、导出范围和内容指纹判断重复，重新打开已有笔记会保留其中的手工编辑；正文或关联选择变化时生成新版本，记录上一版路径。早期不含导出指纹的笔记继续保留，不能自动识别为重复。

预览后阅读内容或所选关联来源发生变化时，保存会要求刷新。关联仅指向允许的 Wiki 知识目录，本文来源仍显示非链接路径。关联建议不会写回正式来源笔记，也不自动把 QA 纳入检索索引；正式知识的逐条修订建议与差异预览见 [知识整理](knowledge-curation.md)。

回答下方的关联记录显示该节点已导出的学习笔记、待审阅建议及采纳、复查、撤销状态，可直接打开对应文件或整理记录。状态来自已保存的导出与修订记录，无需模型判断；正文变化后显示「已导出旧版」，没有节点指纹的早期导出显示「旧记录」。正式笔记或证据的变化需要在知识维护面板执行核查后更新复查状态。

「更多阅读选项 → 阅读用量」显示本会话统计；每个回答下方可展开证据选择、讲解、记忆摘要的逐次用量，包括失败和中断的调用。接口报告值、文字估算与未报告分别显示，旧回答不会补造用量。此处不合并 embedding/rerank 开销，CLI 附加上下文、图像和推理以服务商实际计量为准。

失败后重试会再次核对原文，来源、模型和选择上下文一致时复用已经校验的证据选择结果，减少一次选择请求；证据和检索来源仍重新读取，讲解仍会重新请求。已经完成并保存的支线摘要保留。仅切换模式、标记理解状态或查看关联记录不会调用模型。

当前读取上限包括：原始 PDF 64 MiB、每轮最多 3 张图像、单张提取图像 12 MiB，以及有界证据目录和上下文。超过容量时会提示缩小问题或来源范围。模型解释仍需读者对照原文判断。

部分 MinerU 段落的页码无法唯一匹配，或一个文本块跨页；此时保留章节、阅读文本字符范围和原文片段，并明确显示页码缺口，不猜测页号。

## 开发记录

- 阶段 1：实现独立会话模型、主线与支线关系、引用校验、串行原子保存及中断恢复。存储位于插件目录的 `reading-sessions/`，不自动清理历史。保存失败不会提交内存中的新状态。
- 阶段 2：原始 PDF 按页读取文字并按需渲染页面；MinerU 包复用完整校验与已验证图像。每轮检查来源指纹，原文变化时暂停继续生成，已有会话保留。
- 阶段 3：接入双模式阅读视图、主线定位、可固定的支线小窗、分栏与窗口调整、输入目标及草稿保存。提供明确标注的交互演示。
- 阶段 4：通用导读 SKILL 随构建内嵌。Direct API 与独立只读 Codex CLI 共用证据选择和结果校验；箭头一次推进一个单元，失败及取消可重试，图像不足时明确提示。
- 阶段 5：支线保留创建时主线背景和相关祖先上下文，较长历史按需摘要且保留原消息。划选回答后可选择追问或复制；追问支持格式化文字及重复文字定位，无法唯一定位时要求重新选区。仅导图模式有活动小窗时默认收起主输入框，可点击“从主线新建支线”展开；收起保留草稿。
- 阶段 6：本文优先，按需补充本地 Wiki 检索，回答展示检索词、采用的路径及缺口。可导出节点、支线或完整会话到 `wiki/qa/`，新建文件并追加日志；来源路径保持非链接文本，模型 Markdown 经被动化后显示和导出。
- 阶段 7：补齐节点草稿隔离、滚动与选区恢复、长文目录覆盖、生成前后来源复查和 Direct API 长文超时；增加真实 Obsidian 界面及两类来源、两个后端的集成验收。

## 阅读助手（0.35.0）

选中已完成节点后，顶部星光按钮可打开独立 Direct API 阅读助手。它可以读取进度、核对当前节点的本文文字依据、检索正式知识或历史学习，并准备整理、导出、继续主线的操作卡。窗口可缩放，草稿、工具轨迹和请求结果保存到本地；关闭窗口不停止请求。

助手的单次任务与原有支线追问分开：主输入框仍创建支线，箭头仍直接推进讲解。整理卡进入原有证据和差异预览，导出卡带入选定范围。详细使用与调用预算见[阅读助手说明](reading-assistant.md)。

## 自动化检查

阅读模块的回归测试使用内存存储、模拟模型和只读证据，避免递归清理测试目录。每阶段运行类型检查、生产构建和相关回归测试；真实模型及 Obsidian 界面验证单独记录。

```powershell
pnpm typecheck
pnpm build
pnpm test:reading
pnpm release:check
```

`tests/obsidian-reading-scenario.cjs` 需在 Obsidian CLI 的 `eval` 中显式调用，传入 `app`；它创建标记为示例的验收会话，验证真实 DOM 操作，不调用模型或删除文件。完整旧测试入口含有递归清理路径，本轮未运行，采用已检查清理行为的定向回归替代。

`tests/obsidian-reading-design.cjs` 验证数字引用打开依据、跨引用选区还原、回答原文不变、重复标题去除、键盘分栏及窗口入口。`tests/obsidian-reading-long.cjs` 验证 300 节点的折叠、导航与恢复。两者均保留明确标记的示例会话，不调用模型、不导出笔记、不删除文件。

`tests/obsidian-reading-window.cjs` 验证八方向缩放、可视边界与最小尺寸、拖动取消、键盘调节、正文占比、发送按钮可点击区域，以及长草稿增高、缩回和尺寸保存，同样不调用模型或删除文件。
