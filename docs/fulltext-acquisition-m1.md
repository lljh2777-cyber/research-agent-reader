# 全文获取 M1：流程骨架与可交互演示

开发版本：`0.44.0`。本阶段落实[总体设计](fulltext-acquisition-design.md)的 M1，不包含真实 PDF 获取、论文身份核验、原文入库、MinerU 转换或 Wiki 生成。

## 使用入口

- 控制台辅助工具中的「获取全文」，或命令「按标识获取论文全文」：输入 DOI、PMID、PMCID 或 DOI/PubMed/PMC 官方链接，查看规范化标识。无需配置模型。真实来源尚未接入，下载按钮禁用。
- 命令「全文获取流程演示（开发）」：使用虚构文献，选择顺利完成、候选选择、来源失败、身份冲突、无匹配全文五种模拟场景。模拟进度不代表网络传输；「演示完成」表示保存了演示回执，没有 PDF 可以打开或入库。
- 关闭面板后任务继续；重新打开面板可查看和停止任务。插件关闭会结束正在执行的演示；重开后主动重试。上次已保存完整回执的任务可直接恢复完成状态。

演示失败场景的「重试」会再次执行同一个失败场景。要观察成功路径，选择「顺利完成」并开始新的演示。错误场景不会自动变成成功。

## 实际模块与责任

| 文件 | 责任 |
|---|---|
| `src/fulltext/contracts.ts` | 输入解析、任务阶段、候选与演示回执契约、运行时解码 |
| `src/fulltext/service.ts` | 重复请求复用、尝试隔离、候选选择、停止/重试、保存与恢复 |
| `src/fulltext/repository.ts` | 存储端口、记录解码、损坏记录隔离 |
| `src/fulltext/file-storage.ts` | 有界文件读取、追加修订、完成标记、路径和符号链接检查 |
| `src/fulltext/demo-backend.ts` | 可取消的虚构来源，无网络和文件获取 |
| `src/fulltext/task-run.ts` | 正式获取记录投影为现有控制台 TaskRun |
| `src/fulltext/modal.ts` | 输入、阶段、进度、候选与恢复操作 |
| `src/plugin.ts`、`src/actions.ts`、`src/views/dashboard.ts` | 依赖装配、命令、入口与结果路由 |

M1 只保留当前使用的字段。演示候选没有 URL、许可或已验证身份，回执明确标记 `simulated: true`。M2 接入真实来源时再增加 `ResolvedIdentity`、真实候选、文件验证和不可变来源快照；不能把演示回执强制转换为真实来源。

控制台历史读取正式获取存储的 TaskRun 投影，不将副本写入 `data.json`，也不经过旧任务输出的保留/清理路径。演示记录不进入正式历史。既有 PDF 入库入口与所用任务存储继续工作。

## 持久化与恢复

记录位于插件目录的 `fulltext/production/` 或 `fulltext/demo/`；空目录只读打开不会创建存储。每个阶段生成新文件，不覆盖原修订或执行文件删除：

```text
fulltext/<mode>/
  a-<uuid>.<revision>.<write-uuid>.json
  a-<uuid>.<revision>.<write-uuid>.json.ready
  s-<uuid>.json
  s-<uuid>.json.ready
```

JSON 写入并同步后写 `ready` 标记。读取只考虑有完整标记的修订；最新修订损坏、文件名与内容不一致，或同一任务出现两个相同最高修订时，报告诊断而不静默退回旧状态。无标记的半写入文件保留且忽略。

任务与回执分开保存。进入校验阶段先记录预定回执 ID；提交时保存回执，再保存完成阶段。恢复时同时核对任务 ID、尝试 ID、输入标识及候选 ID。回执缺失或绑定不一致时显示中断；有完整回执且只是最后的状态写入未完成时，可恢复完成状态。

停止先设置取消信号，再记录取消结果。进入最终提交区后停止返回不可用，界面提示正在保存；不会承诺已取消正在完成的提交。旧尝试的结果和进度不能进入新尝试。进度更新只在内存中更新并限制通知频率，阶段变化才写盘。

其他设备的任务只读，不自动重试。设备归属使用主机名与插件路径的摘要，不保存主机名原文；这是恢复提示，不是跨设备锁。移动插件目录或更改主机名会使旧记录被视为其他设备，跨设备接管留待后续设计。

每次读取限制为 256 KiB，最多加载 2000 个任务、扫描 20000 个目录项，面板展示最近 50 条。达到上限会报告错误或截断展示。M1 保留所有修订和演示记录，不提供自动清理；并发多进程/同步冲突按修订冲突拒绝恢复，不宣称支持分布式写入。

## 验收与后续开发

- `pnpm test:fulltext`：输入规范化、模式隔离、重复点击、候选绑定、字节进度、取消后的迟到事件、失败重试、初始/阶段/回执/完成写入失败、回执核对、设备归属、卸载、TaskRun 路由；文件存储使用内存文件系统验证半写入、修订冲突、标记、读取上限、路径与符号链接拒绝、句柄关闭。
- `pnpm test:ingest`、`pnpm test:dashboard`：既有入库任务与控制台入口回归。
- `tests/obsidian-fulltext-acquisition.cjs`：原生面板交互、无模型入口、进度、关闭重开、候选、停止重试、保存失败、窄宽面板及旧设置/历史保持；测试使用内存任务，不调用真实模型或来源。
- 文件系统持久化另在测试库显式演示，并通过插件重载检查；演示记录保留，不删除。

旧全量测试入口含不符合当前约束的清理路径，本阶段采用专项验证，不宣称通过全量测试。下一步 M2 应增加真实身份与来源快照契约、请求地址与字节策略、PMC PDF 校验和无模型本地查看；M1 演示通过不代表这些能力已经可用。

### 本阶段实际验证记录（2026-09-09）

类型检查、生产构建、全文获取两组专项、五组入库回归、两组控制台回归、22 组阅读回归及 28 项发布审计通过。原生全文面板通过 14 项检查，包括 360/680 像素宽度；既有入库续办界面通过 28 项检查。测试库已实际保存一条虚构演示回执，插件重载后绑定核验通过，正式任务历史未混入该记录。

部署前备份三个插件文件并核对哈希；首次部署保护 80 个既有文件。实际重载后再次核对包括三个构建文件在内的 83 个非全文存储文件，内容一致。演示记录与截图留在本地测试位置，不提交到仓库；真实来源和模型调用次数均为零。
