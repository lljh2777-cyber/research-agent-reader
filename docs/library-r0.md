`projectLibrary()` 只接收现有对象的已规范化数据，返回文献视图；没有存储对象、写入回调、网络服务、模型配置或时钟参数。它不调用 `SourceCatalog.associate()`，不分配 `paperId`，也不自动补写 DOI 或中文标题。

对象种类包括文献记录、来源、阅读会话、论文笔记、批注与获取任务。底层 ID 继续由原服务拥有；来源版本、投影标识和现有阅读证据类型不改。返回的 `row-…` 仅为确定性视图键，基于成员引用生成；改标题不会改变它，增减成员可能改变它，不能用作持久文献身份。

纯投影报告传入快照的状态；新适配器负责读取磁盘及调用已有来源校验器。一次扫描不是整个 Vault 的事务快照；点击打开原文、生成讲解或应用修订时，仍由既有服务重新核对真实来源。

## 关联规则

1. 使用规范化 DOI、PMID、PMCID 或已有 `paperId` 建立候选组；标题和 citekey 不作为合并依据。
2. 检查整组，而不只逐对检查。例如 A 与 B 共享 DOI，B 与 C 共享 PMID，而 C 与 D 引出另一个 DOI 时，整组进入冲突状态，各对象保留为独立行。
3. 共同字段冲突、多个 `paperId`、同组多个 citekey 均阻止合并。相同 citekey 被其他未关联组使用时也显示冲突；不会按文件名把两组并到一起。
4. 缺少标识且没有 `paperId` 的旧资料保持独立、待关联。仅元数据的既有文献记录可以正常投影，不要求原文或 Wiki 存在。
5. 冲突行只保留自己的标识，不展示一组混合后的身份。原有 `paperId` 只原样返回；`primaryNoteId` 只能指向已关联组内的笔记。
6. 只有来源类型和已核验指纹均与会话固定来源相符，才能通过显式绑定关联来源与会话。绑定仍参加整组身份冲突检查；即使没有 DOI，也不为此分配新 `paperId`。路径相同但文件已替换时保留历史会话，不重新绑定。

关联索引按精确字段构建，避免逐条比较整个输入集合。诊断按问题共享，行只保存诊断 ID；2,000 条共享 DOI 但具有不同 `paperId` 的样本产生 2,000 行和一份共享冲突清单，不复制 2,000 份完整清单。输入暂限 10,000 个对象，超限明确失败；这不是实际库容量或已测性能承诺。

## 状态与能力边界

| 信息 | 当前投影规则 |
|---|---|
| 来源已保存 | 只使用来源记录中的正式保存事实；获取任务 `acquired` 不自动生成该事实 |
| 原文可用 | 适配器传入的已核验指纹才允许显示可打开；未核验、缺失、损坏均返回具体阻塞原因 |
| 来源支持的阅读能力 | PDF/MinerU 支持页面入口，JATS 支持正文块入口；普通 Markdown 可以普通阅读，不能因此获得交互深读能力 |
| 讲解进度 | 复用 `mainIds`、节点生成状态、`outline` 和 `completed`；没有路线时总数为未知 |
| 人工阅读状态 | 仅来自显式文献记录；缺失为未标记，不从讲解完成推断 |
| 节点理解 | 复用 `learningState`，只统计生成完成的节点；保留未标记计数 |
| 未解决问题 | 只计算标记为仍有疑问的已生成节点；所有节点均未标记时为未知，已标记范围不代表全文无疑问 |
| 笔记审阅 | 需要显式审阅时间与内容哈希；当前正文不同则待复查，旧决定保留 |
| 内容角色 | 原文、AI、人工、外部资料、综合判断分别表达；旧批注没有角色时保持未知 |

这些能力表示来源格式和已提供核验快照允许哪些入口，不代表模型已配置、已读取图像或科学内容已被人工核验。归档阅读保留为可查看历史；演示、测试与代码会话排除出正式论文视图，并返回排除引用以便调用方解释范围。

读取输出与输入数据相互独立；调用方修改投影不会改动原有来源、会话或笔记对象。输入顺序不影响分组、临时键或诊断。重复对象引用、非规范化标识、无效 `paperId`、审阅凭据与不一致会话 ID 会明确报错；适配器应将真实损坏来源转换为带诊断的不可用对象，而不是传入伪造的已验证数据。

## 实际读取接口

`readPaperLibrary(vault, plugin, options)` 只要求两个存储对象提供 `read/list`，内部写接口直接抛错。插件通过显式调用 `inspectPaperLibrary(signal?, verifyMineruPath?)` 暴露查询；不在启动时自动扫描，也不创建新页面或命令。

| 读取范围 | 行为及限制 |
|---|---|
| `papers/<packageKey>/_source/manifest.json` | 先检查清单及目录绑定，再复用 PDF/JATS 完整包校验器；清单缺失、无效或文件被改写时保留不可用条目，不能降级成普通 Markdown |
| `papers/<citekey>/article.md` 旧包 | 读取原文与提取清单；默认保持未核验。`0.52.1` 可显式指定一个包，调用真实完整加载器，核验后前后比较 `article.md + manifest.json` 指纹；其他包不执行这类重读取 |
| `Clippings/**/*.md` | 读取普通 Markdown 与显式标识，允许普通阅读，不自动获得交互深读能力 |
| `wiki/sources/*.md` | 读取正文哈希、显式 title/citekey/DOI/PMID/PMCID；不从文件名推断身份，坏元数据保留独立条目和诊断；不将已有笔记视为已审阅 |
| `wiki/annotations/**/*.md` | 读取本插件的 `agent-dashboard:annotation-*` 块及外部 `annotation_schema: 2`，区分原文引句、人工与 AI 区段；重复块或不可靠分区排除并报告，不从任一条选定内容 |
| 插件 `reading-sessions/`、`reading-test-sessions/`、`code-reading-sessions/` | 仅解析正式 JSON 文件的独立内存副本，复用会话校验器；测试目录用途缺失也按测试排除，代码目录的错误论文记录报告异常 |

读取会话时不调用 `ReadingRepository.load()` 或 `ReadingWorkspaceService.ready()`，避免触发启动恢复和保存“生成已中断”。查询只反映磁盘已保存状态，不包含正在编辑但尚未保存的内存进度。目录外的 PDF 会话保持可识别的历史记录，不因打开列表而自动读取外部文件。

旧 Dashboard 批注没有不可变来源指纹，仅保存来源路径提示；即使锚点恰好匹配，也不借用当前来源的文献身份。锚点偏移则标记 `changed`。外部 `annotation_schema: 2` 原样保留来源路径、仓库标识与版本字符串，因版本算法及仓库语义尚未确认而保持独立；不能根据本地同名路径推断其内容已变化。原文件保留。

第二批结果包括 `papers`、共享 `diagnostics`、被排除会话 `excluded`、带范围和路径的 `readIssues`，以及 `stats`；第三批增加人工记录与 `recordStates`。`complete` 只代表没有读取问题，不代表所有关联已解决、科学内容已核对或全文已读完。获取任务、待提交会话旁文件和外部 PDF 内容尚未由该适配器读取。

默认总读取预算 256 MiB、最多 10,000 次文件读取和 4,096 次目录读取；单目录上限沿用底层存储的 4,096 项。`stats.filesRead` 是读取调用次数，并非去重后的文件数。文件还受各格式单文件上限约束。超出总预算或取消时整次查询明确失败，不把资源不足报告成原文损坏。核心接口允许显式调整 `maxBytes`；`0.52.1` 的受信任 MinerU 回调使用传入的只读存储，全部文件字节纳入本次预算及统计，元数据访问不计作文件内容读取。投影最多接收 10,000 个对象。

## 验证范围

`pnpm test:library` 的 16 个投影场景和 11 个读取场景全部通过。读取测试以模拟传输建立真实 JATS 包，复用真实清单、资源和会话校验器；覆盖损坏包、固定指纹变化、旧 MinerU 校验回调、批注角色及重复 ID、坏元数据、测试隔离、外部路径、正在生成的会话不被改写、取消与预算不足。MinerU 完整验证回调为模拟，不声称本批已验证旧包的图像和产物完整性。

测试加载器读取并编译源码，业务数据保留在内存；没有真实外部服务或模型调用。另通过全文获取 6 组、来源入库 3 组、JATS 8 组、批注来源完整性、阅读 progress/catalog/entry 回归，以及类型检查、生产构建和发布审计。存在递归清理的旧全量测试入口未运行；本次文件系统回归保留独立临时夹具，不执行删除。

### 本机只读基线

在桌面 Obsidian 测试库部署 `0.51.3` 后，使用实际插件接口连续扫描两次：

| 项目 | 结果 |
|---|---|
| 每次文件／目录读取 | 135 次／13 次，读取 3,621,986 字节 |
| 两次耗时 | 682 ms／636 ms，作为单机两次观察，不代表大库性能承诺 |
| 适配对象 | 151 个，包含 40 个被排除的演示／测试／代码会话 |
| 正式视图中的对象 | 71 个 Wiki、28 条本插件批注、8 个来源、4 个论文会话，共 111 个待归组条目，不能视为 111 篇已识别论文 |
| 来源核验 | 3 个普通 Markdown 已核验；5 个旧 MinerU 未运行完整验证，保留未核验状态 |
| 读取缺口 | 5 条 MinerU 核验缺口，3 个其他格式的批注文件；32 个旧批注或历史会话的来源绑定待核对 |
| 确定性及保护 | 两次对象、诊断和排除结果一致；部署及扫描前后 879 个受保护文件哈希一致；阅读服务实例和现有布局未变化；取消可中止查询 |

部署只替换三个插件构建文件并保留旧版备份。原生错误检查无插件错误。本机没有正式 PDF/JATS 管理包，本批这些格式的验证依据是上述内存及隔离文件系统夹具，不能用本机计数替代实际 PDF/JATS 性能或科学质量验收。
