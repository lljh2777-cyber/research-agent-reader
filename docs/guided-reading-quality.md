# 主线导读质量

教学规则保持简短：一个中心问题、解释方法理由、区分事实与解释、保留指标与图表含义、连贯推进。正文结构、篇幅和例子由模型按内容决定，不要求固定章节或填满检查清单。

`skills/paper-guided-reading/SKILL.md` 随构建嵌入两个阅读后端。程序另行提供当前任务、输出协议及来源边界；编号、状态、存储和学习标记由插件管理。

## 0.37.0 的模块计划

尚无提纲和已完成主线的新会话，先根据全文证据目录及节选规划路线，再按当前单元选取并读取原文。规划覆盖全文位置，不代表已经逐项核验全文；纯扫描且不超过三张图像时，规划实际读取全部图像，超过容量或后端不支持图片时明确提示补足可读来源，不根据空白页码猜测路线。

每项只保存标题、中心问题、候选证据 ID。计划与现有 `outline` 一并原子保存到阅读会话，候选 ID 不计为实际引用。第一项作为全文总览，最后一项作为论证与缺口综合；单元标题、位置和结束判断由程序维护。规划失败不推进，讲解失败后重试和重载复用已保存路线。已有提纲或已有完成主线的旧会话不重新规划。

首次开始通常比原流程增加一次规划调用，之后仍是证据选择和讲解；长支线按原有规则摘要。规划用量单独显示，不增加每轮自评调用。经过验证的 Direct API 配置使用当前可用 ID 的原生 Schema，其他配置与 Codex CLI 保留本地校验。背景摘要维持原有机制，不新增复杂概念状态。

两种视图共享相同会话。阅读路线中展示中心问题，阅读助手可以取得下一单元的准确编号、标题和问题；支线取证与回答不接收最新主线模块，继续使用自身背景快照。讲解规则改善不等于已经证明模型答案质量提升，仍需按下面的场景对照原文评估。

## 质量对照

下面是人工评估场景，不是已经通过的模型实验。比较讲解内容，不按小标题数量评分；自动化检查负责引用、顺序及保存等可判定约束。

| 场景 | 观察重点 |
| --- | --- |
| 同时报告 Top-1、Top-k 与实验验证率 | 保留各自任务与分母，避免直接当作同一种准确率比较 |
| 工作流示意图与结果图相邻 | 区分设计说明与实验证据；读图说明有用的坐标轴、对照和不确定性 |
| 正文引用未提供的补充表 | 指出具体缺口，继续解释有证据的部分，不补造表格内容 |
| 下一模块沿用上一讲概念 | 简短衔接后回答新问题，避免换标题重复前文 |
| 从旧回答划选公式追问 | 聚焦选区与必要例子，保持支线背景及主线位置 |
| 最后一个综合单元 | 综合已讲的论点与证据，保留未解决缺口，不把讲完等同于掌握或 X-Ray |

后续仅针对反复出现且可复现的问题增加约束，避免将某篇论文的特殊情况写成所有论文的要求。
