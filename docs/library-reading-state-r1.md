交付日期：2026-09-11。开发版本 `0.57.0`。本批接入 R0 已有的人工记录服务，完成“文献详情 → 修改阅读状态 → 明确保存 → 刷新展示”的流程。主要笔记选择与 R1 整体收尾尚未完成。

后续进展：`0.58.0` 已接入[主要笔记选择](library-primary-note-r1.md)，两类编辑复用同一保存过程，写入字段仍分别限定。以下保留本批原始交付范围。

## 使用

从研究工作台打开 **文献库**，选择一条文献，在 **我的阅读状态** 点击 **修改阅读状态**。页面重新核对身份与人工记录后，提供五个选项：

| 选项 | 含义 |
|---|---|
| 阅读状态未标记 | 尚未作出声明，也可撤回已有标记 |
| 未开始阅读 | 用户声明尚未开始 |
| 正在阅读 | 用户声明阅读中 |
| 用户标记已读 | 用户声明已完成本次阅读 |
| 待回看 | 用户计划重新阅读 |

选择不同状态后点击 **保存阅读状态**；未改动时不保存。取消只放弃本次未保存的选择。编辑期间保留当前文献，保存或取消后可切换文献、刷新或打开原文。搜索和筛选不改变当前编辑对象。关闭标签页或重载不会保存未提交的草稿。

人工阅读状态独立于模型讲解生成量、节点理解标记、笔记审阅及来源证据等级。选择“用户标记已读”不会赋予 `x-ray` 深度，也不会修改论文笔记正文。

## 写入与失败恢复

- 浏览、筛选、选择详情和准备编辑均只读取记录，不创建文献 ID，也不调用模型或外部服务。文献必须已有唯一可靠的 `paperId`；旧资料缺少身份时显示原因。
- 开始编辑时保存文献、成员、笔记内容及人工决定的摘要凭据。明确保存使用同一凭据，服务再次读取核对；外部修改后，旧编辑不能覆盖最新内容。
- 状态保存只提交 `paperId`、编辑凭据和阅读状态，保留主要笔记与身份决定。旧主要笔记缺失或关联变化时，现有服务仍会阻止保存；本批不自动清除选择。
- 人工记录损坏或出现并发版本时显示原因，不按时间挑选版本，不提供隐式合并。本页尚无冲突处理入口。
- 保存失败保留所选状态和原凭据，可以明确重试。若提示文献或笔记变化，取消编辑、刷新并核对后再选择。保存成功后的刷新错误单独显示，不把已提交记录报告为写入失败。
- 重复保存点击只提交一次。准备阶段取消、关闭后的迟到结果不能更新视图；已经进入保存的操作不提供取消或回滚承诺，关闭后仍可能完成写入，重新打开时按磁盘记录展示。
- 继续使用插件目录 `paper-records/<paperId>/` 下的追加日志，不改变存储结构，不覆盖旧修订；可见数据迁移留到 R4。

`src/library/reading-state-editor.ts` 管理编辑凭据、草稿、准备／保存过程及迟到结果；`src/views/paper-library.ts` 提供五态编辑和保存后的目录刷新。插件现有 `preparePaperRecord`／`savePaperRecord` 接口与记录服务无需改动。`styles.css` 增加表单布局，`tests/test_library_reading_state.js` 覆盖控制器及真实记录服务的内存集成。

新增七组定向场景覆盖无改动不写入、五态保存、取消、重复点击、保存期间草稿冻结、关闭后的迟到成功／失败、身份与多版本拦截、失败后明确重试、旧凭据拒绝、主要笔记和历史保留。视图异步回归还验证保存后的刷新不抢回用户新选择的文献、提交成功与刷新失败分开反馈。记录存储回归另覆盖真实文件及独立进程恢复。执行前核对清理行为，未运行含批量删除的旧全量测试；真实文件夹具保留。

原生 Obsidian 验收在 `paper-test` 加载 114 条真实记录，再使用库外隔离文件存储驱动实际文献库视图及插件人工记录接口。隔离样本验证五态切换、准备失败与取消、保存失败和重试、外部更新拦截、身份缺失、并发记录提示、提交后刷新失败，以及 430 px 布局。插件重载后从隔离磁盘恢复已保存的“用户标记已读”，未提交的“待回看”草稿未恢复；主要笔记仍指向原笔记。
