## 修复内容

### 桌面辅助进程未创建文件

旧写入器通过 `process.execPath` 加 `ELECTRON_RUN_AS_NODE=1` 执行 Node.js 脚本。在本机 Obsidian `1.13.7` 中，实际启动的是 Obsidian CLI：`-e` 被当作未知命令，但子进程仍以 0 退出。写入器随后检查目标文件时才收到 `ENOENT`。

现在写入器使用独立 Node.js：普通 Node 环境可使用自身可执行文件；Electron 环境只从绝对 PATH 目录查找 `node.exe` / `node`，忽略空项及相对目录，使用解析后的实际路径。不再依赖 Electron 的启动行为，也不自动安装运行时。缺少 Node.js 时给出可执行提示，PDF 初始笔记流程会在模型生成前检查；已有原文保持可用。

可信父目录检查、独占临时文件、硬链接发布、禁止覆盖及写后回读继续保留。辅助进程隐藏运行，最长等待 15 秒，移除继承的 Node 注入选项。错误输出保留实际错误码；只有 `EEXIST` 才显示同名笔记冲突，磁盘或运行时故障显示创建失败。

### 初始笔记缺少正文深度提示

真实回答没有返回可选的 `evidenceGaps`，旧模板因此完全省略“证据缺口”。模板现在固定注明摘要级概述及尚未逐图核验，再追加模型返回的具体缺口。测试中已生成的这一份新笔记补上同样的固定提示，保留模型正文和身份字段，并在测试库日志记录这次检查；没有批量改写旧笔记。

## 仍需完成

1. **新转换包的文献关联。** 当前库读取器只从旧 MinerU 正文属性读取文献标识，新发布的忠实转换正文不带这类属性，因此转换包仍是独立未核验条目；PDF 和 Wiki 已归到同一论文。下一步应沿用固定来源凭据接入关联，不能按文件名前缀或标题合并，也不能改写 `article.md` 来补身份。任务结果中的转换路径和重复处理复用目前可用。
2. **科学与教学质量。** 本轮笔记只达到 `abstract-level`。已检查标题页、绑定的原文读取记录、笔记结构及深度提示，没有逐图分析或完成独立科学审阅，不能提升到 `x-ray`。R0 科学审阅和 T1 教学审阅门槛继续保留。
3. **范围外验收。** 本轮真实服务链仅覆盖 PDF → MinerU → 初始 Wiki；JATS 使用既有原生证据和本轮内存回归，没有再次付费生成。跨平台实际启动、同步盘长期运行与外部 CSV/BibTeX 的真实写入仍未覆盖。
